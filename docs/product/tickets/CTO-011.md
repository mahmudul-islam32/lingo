# CTO-011: Typed answers with `ss` / umlaut leniency (B1-T2)
**Owner:** cto (contract, checker) · **Priority:** P1 · **Depends on:** CTO-008 ·
**Milestone:** v1.1.0 · **Decisions:** PD-010, PD-012, PD-033 · **ADR:** ADR-010 (proposed) ·
**Consumer:** LES-017 (planned, dev-lessons: input UI)

**Status:** cto technical ticket (CTO-010 plan).

## User story
As a German learner, I want to type a short German answer and have it accepted when I write
`ss` for `ß` or `ae / oe / ue` for `ä / ö / ü`, with a note showing the correct spelling, so
that I can practise writing without a German keyboard.

## Acceptance criteria
1. A strict `typed_translate` exercise type in `ExerciseSchema`: `prompt` (known language),
   `answers` (1–6 accepted learning-language answers, authored case; `answers[0]` is
   canonical), optional `hint` (known language, ≤ 80 characters) and optional `audio`.
2. An answer contract `{ type: "typed_translate", text }` (`text` ≤ 120 characters).
3. A pure `checkTypedAnswer(exercise, answer)` in `src/contracts` returns `correct` when the
   normalised text matches any accepted answer exactly (PD-010 normalisation: case and
   punctuation ignored, umlauts and `ß` significant).
4. If there is no exact match, but there is one after folding both sides (`ß → ss`,
   `ä → ae`, `ö → oe`, `ü → ue`, and the umlaut letters typed as `ae / oe / ue`), the result
   is `correct` with `spellingNotes` naming the canonical spelling, for example
   `{ kind: "sharp_s" | "umlaut", expected: "Straße" }` (PD-033 §3).
5. A noun typed in lower case (the canonical token starts with a capital letter that isn't
   sentence-initial) is `correct` with a `{ kind: "capitalisation", expected: "Brot" }` note.
6. Any other difference is `incorrect` (no typo tolerance in v1.1.0), with `correctAnswer =
   answers[0]`. Scoring follows PD-012: a correct answer with notes is **not** a mistake and
   costs no heart.
7. The tile and listen checkers don't change: `normalizeAnswerText` stays strict (PD-033 §1).
8. Unit tests: `Straße` / `Strasse`, `schön` / `schoen`, `Müller` / `Mueller`, a minimal pair
   (`Maße` / `Masse`: accepted with a note, because the learner can't type `ß`), an exact
   match that wins over a lenient one (`Masse` is accepted as `Masse` when it is itself an
   accepted answer), lower-case nouns, sentence-initial words with no note.

## Technical notes
_(cto)_
- **Files:** `src/contracts/course.ts` (schema), `src/contracts/answer.ts`
  (`TypedTranslateAnswerSchema`, `checkTypedAnswer`, optional `spellingNotes` on
  `AnswerCheckResult`), `src/contracts/text.ts` (new `foldGermanSpelling(normalized)`, kept
  separate from `foldDiacritics`, which stays speech-only), `src/contracts/config.ts` (limits),
  ADR-010. `src/features/lessons/checking/checkAnswer.ts` gets a one-line delegation (lane
  exception, as for cloze).
- **Capitalisation** needs the un-lowercased tokens: compare the typed and canonical tokens
  position by position after the exact/lenient match succeeds; only tokens after position 0
  whose canonical form starts upper-case are checked.
- **Edge cases:** NFC/NFD input (`u` + combining diaeresis is the same as `ü`), `ẞ`, the Swiss
  `ss` (correct with a note, never a mistake), apostrophes, double spaces, trailing
  punctuation, an empty or whitespace-only answer (`incorrect`, never a crash).
- **Language-specific:** the fold table lives in a per-language map (`de` only for now);
  other courses get exact matching only.
- **Content rules (pm, CDS):** accepted answers must be short (≤ 80 characters) and at most
  6 per exercise; the schema rejects two accepted answers that fold to the same text.
- **Compatibility:** bundled content (ADR-009 §5); content uses `typed_translate` only from
  the release that contains LES-017.
- **LES-017 (planned, dev-lessons):** text input with `lang={learningLanguage}`,
  `autocomplete="off"`, `autocorrect="off"`, `spellcheck={false}`,
  `autocapitalize="sentences"`; an `ä ö ü ß` key row that inserts at the caret (buttons with
  accessible names); Enter checks (FIX-001 behaviour); the feedback panel shows the spelling
  notes as text; 375 × 667 with the on-screen keyboard open (the Check bar stays visible).
