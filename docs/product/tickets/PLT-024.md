# PLT-024: German course in onboarding and Learn
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** CTO-008, CON-DE-A1-01, PLT-009
(soft: if PLT-009 isn't merged, apply criteria 7–9 to the temporary Learn) · **Milestone:**
v0.3.1 · **Decisions:** PD-030, PD-031

## User story
As a new visitor who wants to learn German, I want onboarding to set me up with the German
course and take me straight into my first German lesson, so that I start learning within two
minutes (PRD G1).

## Acceptance criteria
### Onboarding
1. The Course step lists only **available** courses from the registry (CTO-008): one card,
   "German", subtitle "for English speakers". Spanish isn't shown or named. The line "More
   languages coming soon" stays, outside the radiogroup.
2. When exactly one course is available, it is **preselected** and "Continue" is enabled
   right away. With two or more, nothing is preselected (PLT-004 criterion 3 behaviour).
3. The Welcome heading reads "Learn German in five minutes a day". The language name comes
   from the default course's data, not a hard-coded string (a test with the `en-es` fixture
   as default renders "Learn Spanish …").
4. "Start learning" saves `courseId: "en-de"` and opens the first lesson of `en-de`
   (`/lesson/de-a1-u01-l1-…`, from the course data, not hard-coded).

### Lesson route
5. `/lesson/[lessonId]` resolves the course of the lesson with the CTO-008 helper, so both
   `en-de` and `en-es` lessons play. Results are saved with the right `courseId`. Unknown ids
   show the 404 page.
6. Static params and the PWA precache list include every bundled lesson of every
   registered course (the manifest test is updated and stays green).

### Learn
7. Learn shows the course in the learner's settings (`courseId`), falling back to
   `DEFAULT_COURSE_ID` (`en-de`).
8. **Existing Spanish guests:** a guest whose settings say `en-es` still sees the Spanish
   path with all their completed lessons, XP and streak unchanged (RTL or e2e with a seeded
   profile).
9. Learn shows the course name and the learner's current CEFR level as text above the path
   (e.g. "German · A1"), where the current level is the level of the available lesson.

### Quality
10. German lesson text in the route is announced in German: the lesson container or the
    learning-language elements have `lang="de"` (taken from the course, never hard-coded).
11. The existing e2e tests that relied on Spanish content (`onboarding`, `lesson-route`,
    `lessons-results`, PLT-009 loop) pass: they either use German content or seed an `en-es`
    profile. No test is deleted without a replacement.
12. A new Playwright test (mobile): a new visitor finishes onboarding with the keyboard only,
    lands in the first German lesson, completes it, and sees the first German lesson as
    completed on Learn.
13. At 375 × 667: no horizontal scrolling on onboarding or Learn; the course card fits in
    full. No serious or critical axe violations on the Course step and on Learn.
14. Loading, error and empty states from PLT-004 and PLT-007 are unchanged ("No courses are
    available right now." if the registry has no available course).

## Out of scope
- A course switcher in settings or on Learn (later; Spanish guests keep Spanish)
- A placement test / "I already know some German" (Phase 2)
- Level headers on the path (GAM-010)
- Localised UI (Phase 2 known languages, PD-031)

## UX notes
- **Course step:** one card "German", subtitle "for English speakers", check icon shown
  because it's preselected; "Continue" enabled. No flags (PLT-004 UX).
- **Welcome:** "Learn German in five minutes a day", body unchanged.
- **Learn:** a small caption "German · A1" above the path (text, not colour only).
- **Loading:** skeleton cards as before. **Error:** as PLT-004 criterion 11 and PLT-007.
  **Empty:** criterion 14.
- **Success:** "Start learning" opens the first German lesson full-screen.

## Implementation (dev-platform, 2026-11-13)

1. `OnboardingFlow` loads `listAvailableCourses()` (registry `available` only): one card "German", "for English speakers". Spanish isn't shown or named; "More languages coming soon" stays outside the radiogroup. RTL + e2e (`onboarding.spec.ts`, `german-course.spec.ts`).
2. `effectiveCourseId(chosen, courses)` preselects the only course, so the check icon shows and "Continue" is enabled right away; with two or more courses nothing is preselected (RTL with `listBundledCourses()`).
3. `Welcome` reads the default course with `useCourse(DEFAULT_COURSE_ID)` and renders `welcomeHeading(languageName(course.learningLanguage))` ("Learn German in five minutes a day"). While loading, or if the course can't be read, it shows the static `WELCOME_FALLBACK_HEADING` "Learn a language in five minutes a day". RTL: `defaultCourseId="en-es"` gives "Learn Spanish …", the fixture repository too, and there's a fallback test.
4. "Start learning" saves `courseId: "en-de"` and `router.replace(firstLessonPath(course))`. RTL compares with the course data; e2e reads the id from `content/courses/en-de/course.json`.
5. Route resolution came from CTO-008. RTL: a German fixture lesson plays and the result is saved with `courseId: "en-de"`. e2e: a seeded Spanish guest plays `en-es` Lesson 1 on the same route. Unknown ids still 404 (e2e).
6. Came from CTO-008 (static params and precache for all courses; manifest test green). The build prerenders 65 lesson pages.
7. `learnCourseId(settings.courseId)` (`src/app/(tabs)/_learn/course-caption.ts`) keeps any registered course (hidden included). It falls back to `DEFAULT_COURSE_ID` with no settings or an unknown/removed id (unit + RTL).
8. e2e `german-course.spec.ts`: a guest seeded with `courseId: "en-es"` (`seedSettingsCourse` in `tests/e2e/helpers/seed.ts`) sees the Spanish path. They play Lesson 1, and Learn keeps it completed with Total XP 15 and Streak 1 day, also after a reload. RTL: `en-es` settings reach every Learn block.
9. `CourseCaption` (text `<p>` between the streak/goal row and the path) shows `courseCaption(course, currentLevel(course, completed))`. The level is that of the available lesson (first not completed, the path rule), or the last lesson's when everything is done. It reads "German · A1", or the name only for courses without levels ("Spanish"). It keeps its line height while loading. A read error counts as nothing completed. Unit + RTL + e2e.
10. The lessons feature already sets `lang={course.learningLanguage}` on learning-language elements. The route container stays English (the UI is English). RTL: German options sit in `lang="de"`, the es fixture in `lang="es"`, and the English prompt isn't marked German. e2e asserts `[lang="de"]` in the exercise area.
11. Every spec that picked "Spanish" now plays German, with ids, titles and answers read from the course files by `tests/e2e/helpers/course.ts` (`playLesson`, `answerCorrectly`, `answerWrong`, and `nodeNamePattern`, which matches nodes by title so the specs pass with both the GAM-008 names and GAM-010's "Unit N, Lesson M: …" names). Those specs are onboarding, lesson-route, lessons-results, gamification-loop, shell, lesson-offline.pwa and pwa. The Spanish guest test uses `completeOnboardingAsSpanishGuest`. No test was deleted. The duplicate "CTO-008 choosing German" test was merged into the first lesson-route test. `helpers/lesson-1.ts` (en-es answer keys) is kept.
12. `german-course.spec.ts` (375 × 667): keyboard-only onboarding, then the first German lesson played with the keyboard to results, then Learn shows it completed, Lesson 2 up next and "German · A1".
13. e2e at 375 × 667: no horizontal scroll on the Course step and Learn, the German card fits in full (`ratio: 1`), and axe is clean on the Course step and Learn.
14. Loading skeleton, error and "No courses are available right now." empty states are unchanged (RTL kept).
