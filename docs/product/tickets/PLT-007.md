# PLT-007: Course loading, lesson route and temporary lesson list
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-001, PLT-004, LES-002 · **Milestone:** v0.2.0

## User story
As a learner, I want to start a lesson from the Learn tab with one tap, and as a new
visitor go straight from onboarding into my first lesson, so that I can begin practising
right away (US-LES-01, PRD goal G1).

## Acceptance criteria
1. Course data is loaded from `/content` and validated with the contracts zod schemas. Any
   invalid content file makes `npm run test` fail with a message naming the file and the
   failing field path.
2. A route `/lesson/[lessonId]` renders the lesson player (LES-002) for that lesson. An
   unknown lesson id shows the 404 page from PLT-001.
3. The bottom navigation is hidden on `/lesson/*` (full-screen lesson).
4. The Learn tab shows the unit title and its lessons as an ordered list (`<ol>`) of cards:
   lesson number, title and a "Start" action. In v0.2.0 every lesson can be started
   (PD-009); locking arrives with the skill path (GAM-008).
5. Each lesson card has the accessible name "Lesson N: <title>" and opens the lesson with
   one tap, or with Enter.
6. Onboarding's "Start learning" (PLT-004) now goes straight to `/lesson/<first lesson id>`.
7. After one online visit to Learn, Unit 1's lesson data is available offline: with the
   network offline, opening Lesson 1 from Learn shows its first exercise.
8. **Loading state:** skeleton cards with `role="status"` "Loading lessons".
9. **Error state:** "We couldn't load the course." with a "Try again" button.
10. **Empty state:** a unit with no lessons shows "New lessons are on the way." with Lumi
    (idle).
11. At 375 px: cards are full width, at least 56 px tall, and the list scrolls above the
    bottom navigation.
12. No serious or critical axe violations on Learn.
13. A Playwright test (mobile): a new visitor completes onboarding and sees the first
    exercise of Lesson 1; a second test goes offline after visiting Learn and opens
    Lesson 1.
14. Until CON-001 is merged, a small test fixture lesson (valid against the schema) is used
    in tests; it is not shown in production.

## Out of scope
- Skill path visuals, locked states and unlock order (GAM-008)
- Completed checkmarks (PLT-008)
- Caching audio files for offline (PLT-015)
- More than one course or unit (PD-002)

## UX notes
- **Learn (normal):** unit header card (indigo background, unit title, "5 lessons"), then
  the lesson list.
- **Loading:** three skeleton cards.
- **Error:** message and retry, Lumi ember (sm).
- **Empty:** as in criterion 10.
- **Success:** tapping a card opens the lesson full-screen.

## Parallel work
Needs LES-002 to render the player (a stub player is fine while LES-002 is in review).
Can be built at the same time as LES-003 and LES-007.

## Implementation (dev-platform, 2026-11-08)

1. `src/lib/content` (`createContentRepository`, `contentRepository`) parses `course.json` with `CourseSchema` and each lesson with `LessonSchema` when loaded; it throws `ContentValidationError` (file + `"<path>: <message>"` issues) or `ContentNotFoundError`. CI failure on invalid `/content` files stays with `src/contracts/__tests__/content.test.ts` (per the technical notes). `bundled-content.test.ts` fails if the lesson loader map drifts from the manifest or the files.
2. `src/app/lesson/[lessonId]/page.tsx`: `generateStaticParams` from the manifest and `dynamicParams = false`, so an unknown id returns the PLT-001 404 (e2e: status 404 + heading). It renders `LessonScreen` → `LessonPlayer` with the real registry from `@/features/lessons`.
3. The route is outside `(tabs)`, so there is no bottom nav (e2e asserts it).
4. `src/app/_shell/LessonList.tsx`: an accent unit header card ("First Steps", "5 lessons") and an `<ol>` of cards (number, "Lesson N", title, "Start"). All lessons are playable (PD-009).
5. Each card is one stretched link named "Lesson N: <title>". Tap anywhere on the card, or focus it and press Enter (RTL + e2e).
6. Onboarding's "Start learning" does `router.replace(firstLessonPath(course))` → `/lesson/u1-l1-hello`. Onboarding now loads courses through `listBundledCourses()` (`src/app/onboarding/courses.ts` removed). `OnboardingGate` no longer redirects to `/` when onboarding completes in place, so the two navigations don't race.
7. Visiting Learn prefetches every Unit 1 lesson (chunk + `["lesson", …]` query) on idle. The PLT-002 service worker also precaches every `/lesson/<id>` page (`LESSON_ROUTES` in `src/app/_pwa/pwa-config.ts`, checked against the validated manifest), and the lesson JSON chunks come in through `__SW_MANIFEST`. e2e: `lesson-route.spec.ts` goes offline after a Learn visit and opens Lesson 1 → first exercise; `lesson-offline.pwa.spec.ts` (production build) loads all five lesson pages offline on a full page load.
8. Loading state: four skeleton cards in `role="status"` "Loading lessons".
9. Error state: "We couldn't load the course." with Lumi ember (sm) and "Try again" (refetch).
10. Empty state: "New lessons are on the way." with Lumi idle (RTL). Valid content can't produce it, because `UnitSchema` requires one or more lessons.
11. e2e at 375 px: every card is as wide as the list and at least 56 px tall, and the last card sits above the bottom nav when scrolled to the end.
12. e2e: axe on Learn (lesson-route spec and the shell spec) reports no serious or critical violations.
13. `tests/e2e/lesson-route.spec.ts` (Pixel 7 + desktop): new visitor → onboarding → Lesson 1's first exercise, and Lesson 1 opened offline after a Learn visit.
14. `src/lib/content/__fixtures__/fixture-course.ts` (schema-parsed) is used only by tests.

Data: `useCourse` / `useLesson` are TanStack queries on `queryKeys.content` / `queryKeys.lesson` with the CTO-006 offline defaults.
