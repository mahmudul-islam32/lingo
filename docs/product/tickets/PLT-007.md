# PLT-007: Course loading, lesson route and temporary lesson list
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-001, PLT-004, LES-002 · **Milestone:** v0.2.0

## User story
As a learner, I want to start a lesson from the Learn tab with one tap, and as a new
visitor go straight from onboarding into my first lesson, so that I can begin practising
right away (US-LES-01, PRD goal G1).

## Acceptance criteria
1. Course data is loaded from `/content` and validated with the contracts zod schemas. Any
   invalid content file makes `npm run test` fail with a message naming the file and the
   failing field path.
2. A route `/lesson/[lessonId]` renders the lesson player (LES-002) for that lesson. An
   unknown lesson id shows the 404 page from PLT-001.
3. The bottom navigation is hidden on `/lesson/*` (full-screen lesson).
4. The Learn tab shows the unit title and its lessons as an ordered list (`<ol>`) of cards:
   lesson number, title and a "Start" action. In v0.2.0 every lesson can be started
   (PD-009); locking arrives with the skill path (GAM-008).
5. Each lesson card has the accessible name "Lesson N: <title>" and opens the lesson with
   one tap, or with Enter.
6. Onboarding's "Start learning" (PLT-004) now goes straight to `/lesson/<first lesson id>`.
7. After one online visit to Learn, Unit 1's lesson data is available offline: with the
   network offline, opening Lesson 1 from Learn shows its first exercise.
8. **Loading state:** skeleton cards with `role="status"` "Loading lessons".
9. **Error state:** "We couldn't load the course." with a "Try again" button.
10. **Empty state:** a unit with no lessons shows "New lessons are on the way." with Lumi
    (idle).
11. At 375 px: cards are full width, at least 56 px tall, and the list scrolls above the
    bottom navigation.
12. No serious or critical axe violations on Learn.
13. A Playwright test (mobile): a new visitor completes onboarding and sees the first
    exercise of Lesson 1; a second test goes offline after visiting Learn and opens
    Lesson 1.
14. Until CON-001 is merged, a small test fixture lesson (valid against the schema) is used
    in tests; it is not shown in production.

## Out of scope
- Skill path visuals, locked states and unlock order (GAM-008)
- Completed checkmarks (PLT-008)
- Caching audio files for offline (PLT-015)
- More than one course or unit (PD-002)

## UX notes
- **Learn (normal):** unit header card (indigo background, unit title, "5 lessons"), then
  the lesson list.
- **Loading:** three skeleton cards.
- **Error:** message and retry, Lumi ember (sm).
- **Empty:** as in criterion 10.
- **Success:** tapping a card opens the lesson full-screen.

## Parallel work

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-platform · **Branch:** `feature/plt-007-lesson-route`

- **Contracts:** `ContentRepository` (`getCourse(courseId)`, `getLesson(courseId, lessonId)`), `Course`/`CourseSchema`, `Lesson`/`LessonSchema`, `Unit`, `LessonSummary`, `Slug`. Content layout `content/courses/<courseId>/course.json` + `lessons/<lessonId>.json`; `DEFAULT_COURSE_ID = "en-es"`.
- **Criterion 1 is already covered** by `src/contracts/__tests__/content.test.ts` (CI fails with the zod issue path). Extend nothing there; if you want a friendlier message, a contract-test change is a cto change: file a request.
- **Files (dev-platform):** `src/lib/content/content-repository.ts` (implements `ContentRepository`: the manifest via static `import` of `course.json`; lessons via a generated map of dynamic imports `() => import("../../../content/courses/en-es/lessons/<id>.json")` so each lesson is its own chunk; parse with `CourseSchema`/`LessonSchema` at load, throw `ContentNotFoundError` for unknown ids), `src/lib/content/index.ts`, `src/lib/content/constants.ts`, `src/app/lesson/[lessonId]/page.tsx` (client; outside the `(tabs)` group so the nav is hidden; `notFound()` for unknown ids), `src/app/(tabs)/page.tsx` (Learn list), `src/app/_shell/LessonList.tsx`. Since `output` is not static export, use `generateStaticParams` from the manifest so lesson pages are prerendered and precached.
- **Queries:** `["content", courseId]` and `["lesson", courseId, lessonId]` with `staleTime: Infinity`, `networkMode: "always"`.
- **Offline (criterion 7):** add the lesson JSON chunks and `/lesson/*` pages to the Serwist precache (`additionalPrecacheEntries` from the manifest, or rely on `__SW_MANIFEST` if the chunks are emitted as JS). Verify in the Playwright offline test.
- **Lesson player:** render `<LessonPlayer lesson learningLanguage knownLanguage onFinish onQuit />` and the `LessonPlayerSkeleton` / `LessonPlayerError` from `@/features/lessons` (LES-002). A local stub is fine while LES-002 is in review. `onQuit` → `router.push("/")`.
- **Onboarding:** "Start learning" → `/lesson/${course.units[0].lessons[0].id}`.
- **Fixture (criterion 14):** `src/lib/content/__fixtures__/fixture-course.ts` (parsed with the schemas), used only in tests; never imported by app code.
- **UI (CTO-004):** `Card` (`as="li"`), `Skeleton` + `role="status"` "Loading lessons", `Button`; Lumi idle/ember.
- **Tests:** repository unit tests (valid, unknown id, invalid JSON rejected via a fixture loader injected in tests), RTL Learn list (names "Lesson N: <title>", `<ol>`), Playwright `tests/e2e/lesson-route.spec.ts` (onboarding → first exercise; offline open) + axe on Learn.
