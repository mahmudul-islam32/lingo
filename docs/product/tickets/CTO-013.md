# CTO-013: Grammar note card with tables (B1-T4)
**Owner:** cto (contract) · **Priority:** P2 · **Depends on:** LES-013 · **Milestone:** v1.2.0
· **Decisions:** PD-050, PD-060, CDS-21 · **ADR:** ADR-012 (proposed) · **Consumer:** LES-019
(planned, dev-lessons: note card component)

**Status:** cto technical ticket (CTO-010 plan). Not needed for B1 writing: B1 tips carry
one-line tables (CDS-21), and the note cards are added to the same lessons later without
exercise changes.

## User story
As a learner, I want a short grammar explanation with a small table (for example the
accusative articles) before a lesson, so that I can see the pattern at a glance.

## Acceptance criteria
1. A lesson gains an optional `note`: `title` (known language, ≤ 60 characters), `body`
   (known language, ≤ 400 characters, plain paragraphs) and an optional `table`.
2. `table`: an optional `caption`, `columns` (1–4 data column labels in the known language,
   each ≤ 16 characters, e.g. Masculine / Feminine / Neuter / Plural) and `rows` (1–6 rows,
   each a known-language `header` ≤ 16 characters, e.g. "Accusative", and `cells`: one
   learning-language cell per column, each ≤ 14 characters).
3. The schema rejects a row with the wrong number of cells, empty cells (an explicit `"–"`
   is allowed) and a table without a `body`.
4. A lesson with both `tip` and `note` is valid: the card shows the note, with the tip
   under it (LES-013 keeps working for lessons with a tip only).
5. Unit tests with an accusative-articles table (Masculine / Feminine / Neuter / Plural)
   and invalid fixtures for each rule.

## Technical notes
_(cto)_
- **Files:** `src/contracts/course.ts` (`GrammarNoteSchema`, `LessonSchema.note`),
  `src/contracts/config.ts` (limits), ADR-012.
- **Why the limits:** a row header plus 4 columns of up to 14 characters fit at 375 px (`text-sm`) without horizontal scrolling
  in a real `<table>`; wider tables would need a scrolling region, which is harder to read on
  a phone and with a screen reader.
- **LES-019 (planned, dev-lessons):** render inside the LES-013 tip card (same "Start"
  button and focus rules). Use a semantic `<table>` with `<caption>`, `<th scope="col">` and
  `<th scope="row">`; header cells `lang={knownLanguage}`, data cells
  `lang={learningLanguage}`. Tokens only, AA contrast, no colour-only meaning.
- **Compatibility:** `LessonSchema` is strict, so a build without CTO-013 rejects a lesson
  with `note`. Because content is bundled with the build (ADR-009 §5), no cached client ever
  sees it; content may use `note` only from the release that contains LES-019.
