# LES-007: Listen exercise (word bank, normal and slow audio)
**Owner:** dev-lessons · **Priority:** P0 · **Depends on:** CTO-002, LES-005 · **Milestone:** v0.2.0

## User story
As a learner, I want to hear a Spanish phrase, replay it slowly, and build what I heard so
that I can train my listening (US-LES-06, US-LES-07).

## Acceptance criteria
1. Shows the instruction "Tap what you hear", a large "Play" button
   (`aria-label="Play audio"`), a smaller "Slow" button (`aria-label="Play slowly"`), and
   the word bank from LES-005 with Spanish tiles.
2. The Spanish sentence is not shown before "Check".
3. When the exercise appears, the audio plays once automatically if the browser allows it.
   If autoplay is blocked, nothing breaks and no error is shown.
4. "Play" plays the audio at normal speed. "Slow" plays it at `CONTENT_RULES.slowPlaybackRate`
   = 0.7× (or uses the slow file if the content provides one). Pressing either while audio
   is playing restarts it. _(pm: changed from 0.75× to 0.7× by PD-014; the contract value
   stays 0.7, no contract change needed.)_
5. While the audio file is loading, the Play button shows a loading indicator and has
   `aria-busy="true"`.
6. **Fallback (PD-007):** if the audio file is missing or fails to load, the exercise
   reads the sentence with the browser's speech synthesis using a Spanish (`es-*`) voice
   (rate 1.0 for Play, 0.7 for Slow).
7. If neither the file nor a Spanish speech-synthesis voice is available, the exercise
   shows "Audio isn't available right now." and a "Skip" button. "Skip" reports
   "skipped": the exercise is not counted as wrong, not re-queued, and left out of
   accuracy.
8. The answer is the ordered tile list, checked by `checkAnswer` like a translate exercise.
   After "Check", the feedback panel shows the Spanish sentence (LES-003 criterion 4).
9. Keyboard: Play and Slow are reachable with Tab and work with Enter/Space; the word bank
   behaves as in LES-005.
10. At 375 px: Play and Slow buttons are at least 48 px, side by side, above the word bank.
11. Unit tests (with mocked `HTMLAudioElement` and `speechSynthesis`) cover: autoplay
    allowed, autoplay blocked, slow playback rate, file error → speech fallback, no file
    and no voice → Skip reports "skipped".

## Out of scope
- Generating the audio files (cto pipeline, waits on owner for TTS licence, PRD Q7)
- Listen-and-type with a keyboard (Phase 2)
- Turning listening exercises off in settings (not in MVP)

## UX notes
- **Normal:** speaker icon button with amber fill; the smaller button shows the text
  "Slow" with a "0.7×" badge (PD-014) (no animal icon, to keep our visual language distinct; only
  icons whose licence allows commercial use).
- **Loading:** spinner inside the Play button.
- **Error:** inline message with Lumi "ember" (sm) and "Skip" as the primary action; the
  "Check" button stays disabled.
- **Success:** standard feedback panel.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-lessons · **Branch:** `feature/les-007-listen`

- **Contracts:** `ExerciseComponentProps<"listen">`, `ListenExercise` (`audio: { src, slowSrc? }`, `tiles`, `answers` with `answers[0]` = the transcript), answer `{ type: "listen", tiles }`, `CONTENT_RULES.slowPlaybackRate`, `ExerciseSkipReason` `"audio_unavailable"`.
- **Slow rate:** use `CONTENT_RULES.slowPlaybackRate` (0.7, PD-014; never a literal). Speech-synthesis rates: 1.0 for Play and the same constant for Slow, so both modes stay consistent.
- **Files:** `src/features/lessons/exercises/listen/ListenExercise.tsx` (reuses `WordBank` from LES-005), `src/features/lessons/audio/audio-player.ts` (one shared `HTMLAudioElement` per lesson; `play({ src, rate })` returns a promise; restarts when already playing; `preservesPitch = true`), `src/features/lessons/audio/speech-fallback.ts` (`findVoice(lang)` picks a `speechSynthesis.getVoices()` voice whose `lang` starts with `learningLanguage`, waits for `voiceschanged` up to 1 s; `speak(text, rate)`), `src/features/lessons/audio/use-audio-playback.ts` (state machine `idle | loading | playing | fallback | unavailable`). Register in `exercises/registry.ts`.
- **Flow:** on mount try autoplay with `play()`; a rejected promise with `NotAllowedError` = autoplay blocked → stay idle silently. `error` event or 404 on the element → speech fallback with `answers[0]`; no voice → state `unavailable` → message + `Button` "Skip" → `onSkip("audio_unavailable")`. Play shows `Spinner` and `aria-busy="true"` while `loading`. The sentence is not rendered before "Check"; LES-003 shows it from `exercise.answers[0]`.
- **Offline:** audio is cached at runtime by the SW (ARCHITECTURE §10); offline with an uncached file = file error → fallback path, which is the expected behaviour.
- **Tests:** RTL + mocks: stub `HTMLMediaElement.prototype.play` (resolve / reject `NotAllowedError`), `playbackRate` set to the constant for Slow, `slowSrc` used when present, dispatch `error` → `speechSynthesis.speak` called with `lang` `es-*` voice, no voices → "Audio isn't available right now." + Skip → `onSkip("audio_unavailable")`. Provide a `vi.stubGlobal("speechSynthesis", …)` helper in `src/features/lessons/test-utils/`.
