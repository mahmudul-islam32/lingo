# FIX-006: Stable path e2e test and one hearts warning per failed read
**Owner:** dev-gamification · **Priority:** P2 · **Depends on:** FIX-002, FIX-003 ·
**Milestone:** v0.5.2 (released) · **Merged:** #76 · **Found in:** e2e flake in CI and duplicate
console warnings (recorded after the fact, PM-ACC4)

## User story
As a developer, I want the path e2e test to measure the layout only after the auto-scroll
has finished, and one warning per failed hearts read, so that CI is reliable and the logs
are readable.

## What was fixed
- `SkillPathView` sets `data-auto-scroll="pending"` / `"settled"` on its root
  (`whenScrollSettles` in `scroll-to-center.ts`). e2e waits for `"settled"` before it measures
  (`gamification-loop.spec.ts`).
- `useHearts` and `useUserProgress` share one guard (`hearts-read-warning.ts`), so one
  failed hearts read logs one warning, not two.

## Acceptance criteria
1. The path root exposes `data-auto-scroll` with `pending` then `settled` (or `settled` at
   once when there is no scroll). Unit test in `SkillPathView.test.tsx`.
2. The path e2e waits for `settled` and no longer depends on timing.
3. One failed hearts read logs exactly one warning with both hooks mounted, and one with
   `useHearts` alone (`use-user-progress.test.tsx`).

## Out of scope
Any change to scroll behaviour seen by learners.
