# GAM-012: Redesign v2 for the Learn path, Practice tab, Leagues tab and hearts dialog
**Owner:** dev-gamification · **Priority:** P1 · **Depends on:** CTO-016, PLT-026 (routes and
nav) · **Milestone:** v0.5.3 Redesign · **Decisions:** PD-064, PD-065, PD-066

## User story
As a learner, I want a clear path where I instantly see what's done, what's next and what's
locked, a Practice tab with my finished lessons, and an honest Leagues tab, so that I always
know where to go next and how to earn hearts back.

## Acceptance criteria
References: `docs/design/v2/screen-2.png` (path), `screen-7.png` (Leagues tab, honest state
only), brief tokens. **No behaviour change; existing tests keep passing** (path rules, locking,
start level, hearts and practice logic are untouched).

### Learn path (screen 2)
1. Top bar: course Chip ("DE", coral tint), streak (flame, coral, number), XP (bolt, gold, "<n>
   XP"), hearts (heart, rose, number), each with an accessible label (e.g. "12-day streak").
2. Each unit has an indigo banner card: eyebrow "LEVEL A1 · UNIT 2" style (real level and
   unit numbers) and the unit title in white Bricolage.
3. Nodes are big round 3D buttons in a zig-zag column: **done** = indigo with a white check
   and `0 6px 0 #312E81` edge; **current** = coral with a white star, a soft coral halo, and a
   white pill above it "Start · Lesson N" (N = lesson number in the unit); **locked** = light
   grey with a lock and grey edge.
4. Node behaviour (open, locked, start-gate, out-of-hearts dialog) is unchanged; each node has
   an accessible name with lesson title and state ("Lesson 3, Café order, up next").
5. Level headers and the "Start here" action (PD-064) use the new style (eyebrow + Bricolage
   heading + secondary Button) with unchanged behaviour.

### Practice tab
6. Lists every lesson the learner has completed, grouped by level/unit, as Cards with title,
   unit and a "Practise" button; most recent unit first.
7. A short header explains: "Practise a finished lesson. It's free, and correct answers earn
   hearts." with the current hearts count.
8. Opening a lesson starts the existing practice replay (practice flag, works at 0 hearts,
   PD-065); a not-completed lesson never appears here.
9. Empty state (no completed lesson): Lumi, "Finish your first lesson to practise it here."
   and a primary Button "Go to Learn".

### Leagues tab (screen 7 style, honest)
10. Shows Lumi, heading "Leagues arrive with accounts", one line explaining that weekly
    leagues come when sign-in and sync launch, and no names, ranks, tiers or numbers.
11. No interactive element except navigation; no fake leaderboard data anywhere in the code
    path rendered by this screen.

### Hearts dialog
12. The out-of-hearts / hearts dialog is restyled (Card, hearts colour, Bricolage heading,
    primary Button) with unchanged copy (incl. PD-065 "Practise a finished lesson to earn
    hearts.") and behaviour; a "Go to Practice" action may link to the Practice tab only if
    it replaces the existing link target without changing the flow.

### Quality
13. No serious or critical axe violations on Learn, Practice (with and without lessons),
    Leagues and the hearts dialog; AA contrast for all text (the "Start · Lesson N" pill text
    on white and white icons on coral are checked; coral node uses an icon, not body text).
14. At 375 × 667 no horizontal scroll; nodes are at least 64 px; tap targets at least 48 px.
15. Keyboard: Tab reaches each node in path order, Enter opens it; Practice items and Leagues
    screen are fully keyboard operable; dialog traps focus and returns it on close.
16. Unit / RTL tests: node visual state per path state, Practice list (only completed
    lessons, empty state, opens with practice flag), Leagues has no list items.
17. e2e (375 px, keyboard): finish a lesson, open Practice, start it at 0 hearts, and see the
    practice badge.
18. `npm run typecheck`, `lint`, `test`, `build` and existing e2e pass.

## Out of scope
- Real leagues (v0.6.0 and later)
- Chest / trophy nodes shown in the design (no rewards feature yet)
- Unit "guidebook" button in the design banner, unless a unit tip already exists
- Lesson player (LES-021), Profile and nav (PLT-026)

## UX notes
- **Loading:** path and Practice show skeleton nodes / cards.
- **Error:** if progress can't be read, the existing error state is restyled (Card + retry).
- **Empty:** Practice empty state (criterion 9).
- **Success:** after a lesson, the next node becomes current with the pill.
