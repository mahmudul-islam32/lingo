# GAM-008: Skill path screen with in-order unlocking and 0-hearts gate
**Owner:** dev-gamification · **Priority:** P0 · **Depends on:** GAM-003, GAM-005, PLT-007, CTO-004, CON-001 (e2e only) · **Milestone:** v0.3.0

## User story
As a learner, I want to see Unit 1 as a path where lessons unlock in order and I can tell
locked, available and completed lessons apart, so that I know where I am and what comes
next (US-GAM-01, US-GAM-02, US-GAM-03, US-GAM-14).

## Acceptance criteria
### Rule
1. A pure function `computePathNodes` implements the contracts type `ComputePathNodes`
   in `src/features/path/rules/` and is exported from `@/features/path`. Every node
   passes `PathNodeSchema.parse`.
2. Order follows the course manifest across units. A lesson with at least one result is
   `completed`. The first not-completed lesson is `available` (or `in_progress` if it is
   the `activeLessonId`). Every later lesson is `locked`. Completed lessons stay
   completed and playable.
3. Rule tests cover: new learner (L1 available, L2–L5 locked); L1 done (L2 available);
   all 5 done (all completed, none available); results for a lesson out of order (e.g.
   L3 done but not L2: L2 available, L3 completed, L4–L5 locked); `activeLessonId` set;
   unknown lesson ids in the results are ignored. 100 % branch coverage.

### Screen
4. A component `SkillPath` (props: `courseId`) is exported from `@/features/path`. It
   shows the unit header (unit title and "N of 5 lessons completed") and the 5 lessons as
   an ordered list (`<ol>`) of round nodes in a vertical path, each with the lesson
   number and title visible.
5. Each node shows its state with an icon **and** text, not colour alone: completed =
   check icon + "Completed"; available = Lumi-glow ring + "Start"; locked = lock icon +
   "Locked"; in progress = half-filled ring + "Continue".
6. Accessible names: "Lesson N: <title>, completed", "Lesson N: <title>, up next",
   "Lesson N: <title>, locked" (and ", in progress").
7. Activating an available or completed node (tap, Enter or Space) opens
   `/lesson/<lessonId>` with one action (PRD G1). Completed nodes say "Start again".
8. A locked node has `aria-disabled="true"`, stays focusable, and activating it shows a
   toast "Finish Lesson N to unlock this one." (N = the available lesson) and does not
   navigate.
9. **0-hearts gate:** when `useHearts().view.canStartLesson` is false, activating an
   available or completed node does not navigate. It opens a dialog (CTO-004 `Dialog`)
   titled "You're out of hearts" with the `formatHeartRefill` text (GAM-005, e.g. "Next
   heart in 3 h 12 min") and one "OK" button. It mentions no feature that doesn't exist
   yet (no practice mode, no purchase). Focus returns to the node on close.
10. While hearts are 0, available and completed nodes show a small outlined heart and the
    text "No hearts left" under the title, so the gate is visible before tapping.
11. On open, the path scrolls so the available node is visible (no animation under
    `prefers-reduced-motion`).
12. After finishing a lesson and returning to Learn, the finished node is completed and
    the next one is available without a reload.
13. **Loading state:** a skeleton header and 5 skeleton nodes, with `role="status"`
    "Loading your path".
14. **Error state:** if the course can't be loaded, "We couldn't load the course." with a
    "Try again" button. If only the results can't be read, the path shows with Lesson 1
    available and the rest locked (no error banner; the learner can still learn).
15. **Empty state:** a unit with no lessons shows "New lessons are on the way." with
    Lumi (idle), as in PLT-007.
16. At 375 × 667: nodes are at least 64 px, tap targets at least 48 px, no horizontal
    scrolling, and the last node is not covered by the bottom navigation.
17. No colour literals; state colours from tokens with 3:1 contrast for node outlines in
    both themes.
18. RTL tests cover: each node state and its accessible name; navigation on
    available/completed; locked toast; 0-hearts dialog and focus return; loading; course
    error; results-error fallback.

## Out of scope
- Replacing the temporary list in the Learn route and redirecting locked deep links
  (PLT-009, dev-platform owns `src/app`)
- Unit checkpoints, "jump ahead" tests, more units (Phase 2)
- Crowns, levels or per-lesson stars (not planned)
- Showing `in_progress` on Learn: in MVP no node is in progress there, because lessons
  are full-screen and unfinished lessons are not saved (PD-018). The state is still built
  and tested.
- Animations between states (Phase 2 mascot/path animations)

## UX notes
- **Layout:** unit header card (indigo, unit title, completed count), then the nodes in a
  gentle left-right zigzag on a vertical line. At 375 px the zigzag offset is at most
  48 px.
- **Normal:** completed nodes amber with check; the available node is the largest and
  has a soft glow ring; locked nodes muted with a lock.
- **Loading:** skeleton (criterion 13).
- **Error:** message + "Try again", Lumi ember (sm).
- **Empty:** criterion 15.
- **0 hearts:** criterion 9–10; copy stays kind, no "you failed" wording.
- **Success:** tap opens the lesson full-screen.
