# GAM-003: XP totals and today's XP from saved results
**Owner:** dev-gamification · **Priority:** P0 · **Depends on:** GAM-002, PLT-008 · **Milestone:** v0.3.0

## User story
As a learner, I want my total XP and today's XP to add up every lesson I finish so that I
can see my effort grow (US-GAM-04, US-GAM-07).

## Context
GAM-002 already shipped the pure rules in `src/features/gamification/rules/`
(`calculateXp`, `computeStreak`, `loseHearts` / `refillHearts` / `viewHearts`,
`computeDailyGoalProgress`, `toLocalDate`). This ticket adds the missing aggregate rule
(`ComputeUserProgress` in `src/contracts/api.ts`) and the read hooks that every v0.3.0
screen uses. It adds no UI.

## Acceptance criteria
1. A pure function `computeUserProgress` implements the contracts type
   `ComputeUserProgress` and is exported from `@/features/gamification`. Its output passes
   `UserProgressSchema.parse`.
2. `totalXp` = the sum of `xpEarned` over all results of the course, including replays
   (PD-008). With no results it is 0.
3. `completedLessonIds` lists each lesson id with at least one result exactly once, and
   `lessonsCompletedCount` equals its length. Replaying a lesson does not raise the count.
4. `dailyGoal` comes from the existing `computeDailyGoalProgress` with the learner's goal
   and today's local date. `dailyGoal.earnedXp` is "today's XP".
5. `streak` comes from the existing `computeStreak` over the distinct `localDate`s of the
   results. `hearts` is the stored state after `refillHearts(state, now)`.
6. Results whose `courseId` differs from the input course are ignored.
7. The function contains no XP, heart or goal number literals (values come from the inputs
   and `GAME_CONFIG`).
8. A hook `useLocalToday()` returns the device-local date (`YYYY-MM-DD`) and updates
   without a reload: at local midnight while the app is open, and when the page becomes
   visible again (`visibilitychange`) on a different day.
9. A hook `useUserProgress(courseId)` returns `{ status: "loading" | "error" | "success",
   progress }`, reading results, hearts and settings through the `@/lib/offline` data
   layer (never Dexie directly). It re-derives when `["progress", courseId]` or
   `["hearts"]` is invalidated, so finishing a lesson updates totals without a reload.
10. Before onboarding has saved a daily goal, `useUserProgress` uses
    `GAME_CONFIG.defaultDailyGoalXp` as the goal instead of failing.
11. If the results can't be read, the hook returns `status: "error"` and does not throw;
    callers decide the fallback.
12. Unit tests (table-driven) cover: no results; one perfect lesson (15 XP total, 15
    today); a replay of the same lesson (30 total, still 1 lesson completed); results
    from yesterday and today (only today's XP in `dailyGoal`); results of another course
    ignored; hearts refilled lazily at `now`; 1,000 results computed in under 50 ms.
13. Hook tests cover: loading → success; error state; `useLocalToday` changes at a
    simulated local midnight and on `visibilitychange`.
14. Branch coverage of `progress.ts` is 100 %.

## Out of scope

- XP history or charts (Phase 2)

## UX notes
No UI. States exposed to consumers:
- **Loading:** `status: "loading"` (consumers show their own skeleton).
- **Error:** `status: "error"` (consumers show a fallback, never a crash).
- **Empty:** a new learner gets `totalXp: 0`, `lessonsCompletedCount: 0`, streak 0, full
  hearts, `earnedXp: 0`.
- **Success:** full `UserProgress`.
