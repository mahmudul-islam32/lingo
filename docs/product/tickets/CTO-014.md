# CTO-014: Offline budget and cache rules for 210 German lessons (B1-T6)
**Owner:** cto (budget, architecture) · **Priority:** P1 · **Depends on:** CON-DE-B1-PLAN ·
**Milestone:** v1.1.0 (before the first B1 content merges, PD-063) · **Decisions:** PD-063 ·
**Implemented in:** PLT-015 (dev-platform: offline caching and sync)

**Status:** cto technical ticket (CTO-010 plan). No contract change; it updates
`ARCHITECTURE.md` §10 and §13 and gives PLT-015 its numbers.

## Problem
`ARCHITECTURE.md` §10 sizes the audio runtime cache at 300 entries and §13 budgets the
precache for "shell + Unit 1 content". Measured on `main` (9cc0664, production build):
- 130 German lesson chunks are **160 KB gzip in total (about 1.2 KB each)**. 210 lessons will
  be about 260 KB: lesson JSON is not a problem.
- A1 + A2 have **388 listen exercises** (about 3 per lesson). At 210 lessons that is about
  630 clips, plus slow variants and the optional cloze, MC prompt and passage audio. A 300-entry
  cache would evict audio of lessons the learner hasn't finished, so offline lessons would
  fall back to speech or "Audio isn't available right now" without warning.

## Acceptance criteria
1. `ARCHITECTURE.md` §13 budgets: total precache (shell + every lesson chunk of every
   available course) ≤ 3 MB gzip; audio is never precached.
2. §10 audio rules: CacheFirst cache per course and content version
   (`audio-<courseId>-v<version>`), **no entry cap by count**, a byte budget instead (about
   40 MB per course, well within mobile storage quota) with LRU eviction only past it, and the
   old version's cache deleted on activate.
3. Warm-up: when a lesson opens, the audio of that lesson and of the next available lesson is
   fetched in an idle callback (not the whole unit), so offline play is always one lesson
   ahead with no burst of hundreds of requests.
4. `navigator.storage.persist()` is requested after onboarding (guest data and cached audio
   survive storage pressure); a refusal changes nothing else.
5. PLT-015 implements 2–4, with a unit test for the cache-name rule and an e2e test that
   plays the warmed next lesson's listen exercise offline.

## Technical notes
_(cto)_
- **Files (PLT-015):** `src/app/sw.ts` (audio route above `defaultCache`, expiration by size),
  `src/lib/offline/**` (warm-up and the `persist()` call). cto: `ARCHITECTURE.md` §10 / §13 in
  this ticket's PR.
- Serwist's `ExpirationPlugin` caps by `maxEntries` / `maxAgeSeconds`; the byte budget is a
  small custom plugin (sum `content-length` on `cacheDidUpdate`, evict the oldest past the
  budget), or `maxEntries: 2000` as a simpler stand-in if the custom plugin is too costly. The
  ADR isn't needed unless that choice changes the budget.
- Placeholder audio isn't in `public/audio` yet (TTS licence, PRD Q7). Until then the warm-up
  only fetches what exists and the speech fallback (PD-034) covers the rest.
- **Edge cases:** the course version bump on every content release would throw the whole audio
  cache away. Key the cache name on a separate `audioVersion` only if re-downloads become a
  problem (measure first).
