# CTO-008: German course support (levels, registry, normalisation, speech locale, default course)
**Owner:** cto · **Priority:** P0 · **Depends on:** CTO-002 · **Milestone:** v0.3.1 ·
**Decisions:** PD-030, PD-033, PD-034, PD-037

## User story
As a learner of German, I want the course organised by CEFR level, with my umlauts and ß
checked correctly and German audio when recordings are missing, so that I always know my
level and never lose a heart to a technical quirk.

## Context
The owner moved the product to German (PD-030). Today's contract has Course → Unit → Lesson,
one course (`DEFAULT_COURSE_ID = "en-es"`), a lesson route without a course id
(`/lesson/<lessonId>`) and a listen fallback that assumes a Spanish voice. This ticket makes
the contracts and content tooling ready for a long, level-based German course. It doesn't
build screens (PLT-024, GAM-010 and LES-014 do that).

## Acceptance criteria
### CEFR level layer
1. The course contract has a **level layer** above units: every unit belongs to exactly one
   CEFR level from the set A1, A2, B1, B2, C1, C2. The cto picks the shape (e.g. a `levels`
   array with `units`, or a `level` field on each unit) and records it in an ADR.
2. A course can declare a level **with no units yet** (shown as "Coming soon" by GAM-010),
   and the schema accepts it.
3. The schema **rejects** levels out of CEFR order, a level declared twice, and a unit placed
   in two levels. Each case has a unit test.
4. Each level has an English display title (e.g. "A1 · Beginner") and an optional short
   description (max 280 characters).
5. The existing `content/courses/en-es/course.json` still validates. If the new shape needs a
   change to that file, the cto makes the mechanical change in the same PR (pre-approved by
   the pm here; no wording changes) and bumps its `version`.
6. The flattened lesson order used by `computePathNodes` (A1 unit 1 lesson 1 … C1 last
   lesson) is available from one exported pure helper, with a unit test across two levels.

### Course registry and default course
7. There is one **course registry** listing every bundled course with its id and a
   visibility of `available` or `hidden`. Initial values: `en-de` available, `en-es` hidden.
8. A helper returns the **available** courses in registry order (used by onboarding,
   PLT-024). Hidden courses still load by id (`getCourse("en-es")` works).
9. `DEFAULT_COURSE_ID` is **`"en-de"`**.
10. A content test fails when a **lesson id is used in two courses** (the lesson route has
    no course id) and when an exercise id is used twice across all courses.
11. A helper resolves `lessonId → courseId` across all registered courses (used by the
    lesson route, PLT-024), with unit tests for an `en-de` lesson, an `en-es` lesson and an
    unknown id.
12. A schema-valid **fixture** course `en-de` with A1 (2 units × 2 lessons) and A2 (no
    units) exists for feature tests (GAM-010, PLT-024).

### German text normalisation (PD-033)
13. `normalizeAnswerText` keeps `ä ö ü ß` distinct and doesn't fold `ss` or `ae / oe / ue`.
    Unit tests: `schön ≠ schon`, `Straße ≠ Strasse`, `Brüder ≠ Bruder`, `Grüße ≠ Grusse`.
14. Case is ignored as before (PD-010): `Brot = brot`, `ÄPFEL = äpfel` (uppercase umlauts
    lower-case correctly). Unit tests.
15. NFD input equals NFC input (`"schön" = "schön"`). Unit test.
16. German quotes and apostrophes: `„Hallo“` = `hallo`; `Wie geht’s?` = `wie geht's`. Unit
    tests.
17. The behaviour for hyphenated compounds (`U-Bahn`, `S-Bahn`, `E-Mail`) is documented and
    tested: a tile `U-Bahn` and the answer `Ich nehme die U-Bahn.` stay buildable and match.
18. `foldDiacritics` (speech only) folds `ö → o`; `ß` behaviour is documented and tested.

### Speech locale and audio (PD-034)
19. The contracts expose the **speech locale** for a course's learning language, `de` →
    `de-DE`. Spanish keeps its current behaviour. LES-014 and LES-011 read it from here, not
    from hard-coded values. Unit test.
20. `AudioPathSchema` accepts `/audio/de/a1/u01/de-a1-u01-l1-ex05.mp3`. Unit test.
21. The cto checks whether `multiple_choice.audio` is rendered by LES-004. The finding is
    written in the Technical notes; if it isn't rendered, a LES ticket is proposed to the pm.

### Docs
22. `ARCHITECTURE.md` and a new ADR describe the level layer, the registry, the cross-course
    id rule and the speech locale. `CONTRACTS_VERSION` is bumped only if a persisted or
    synced shape changes (settings `courseId` stays a slug).
23. `npm run typecheck`, `lint`, `test` and `build` pass.

## Out of scope

- Typed answers with `ss` / `ae` leniency (Phase 2, PD-033 point 3)
- New exercise types (gender choice, cloze: curriculum §6)
- Course switching in settings (later)
- Any German lesson content (CON-DE-A1-NN)
