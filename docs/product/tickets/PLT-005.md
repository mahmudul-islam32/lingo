# PLT-005: Install prompt and app-update notification
**Owner:** dev-platform · **Priority:** P1 · **Depends on:** PLT-002, CTO-004 · **Milestone:** v0.1.0

## User story
As a learner, I want a friendly invitation to install the app and a notice when a new
version is ready so that I can open Polyglow from my home screen and always have the
latest version (US-PLT-13).

## Acceptance criteria
1. The app listens for `beforeinstallprompt`, calls `preventDefault()` and keeps the event
   for later, so the browser's own mini-infobar doesn't appear.
2. When the event is available, onboarding is complete and the learner is on the Learn tab,
   a card "Install Polyglow" appears with body "Open it from your home screen, even
   offline." and two buttons: "Install" and "Not now".
3. "Install" opens the browser's native install prompt. If the learner accepts, the card
   disappears and doesn't return.
4. "Not now" hides the card and it doesn't reappear for 7 days (dismissal time stored on
   the device).
5. The card never shows when the app already runs installed
   (`display-mode: standalone`, or `navigator.standalone` on iOS).
6. On iOS Safari (no `beforeinstallprompt`), the same card instead shows the steps "Tap
   Share, then Add to Home Screen", with a "Got it" button. Same 7-day rule.
7. When a new service worker is waiting, a toast "A new version of Polyglow is ready"
   appears with a "Refresh" button. "Refresh" activates the new worker and reloads the
   page once.
8. The update toast is never shown on `/lesson/*` routes. If an update arrives during a
   lesson, the toast appears after the learner leaves the lesson.
9. The card and the toast are keyboard-operable and announced politely (`role="status"`).
10. Unit tests cover the 7-day dismissal rule (shown, dismissed, hidden on day 6, shown on
    day 8) and the "already installed" check.

## Out of scope
- Showing the prompt after the first completed lesson instead of after onboarding
  (revisit in v1.0.0 with analytics data)
- Auto-update without asking

## UX notes
- **Install card:** sits at the top of the Learn page content (not over the bottom
  navigation), with a small Lumi icon. Fits at 375 px without truncating the buttons.
- **Update toast:** CTO-004 Toast, bottom of the screen above the navigation, stays until
  dismissed or refreshed.
- **Error:** if the native prompt fails or is dismissed, the card simply hides for 7 days;
  no error message.
- **Loading/empty:** not applicable.

## Parallel work
Needs PLT-002. Can run in parallel with PLT-004 and PLT-006.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-platform · **Branch:** `feature/plt-005-install-update`

- **Contracts:** none (install dismissal is a device UI preference, not synced user data). Store it in `localStorage` key `polyglow.installPromptDismissedAt` (ISO string); wrap access in try/catch for private mode.
- **Files (dev-platform):** `src/lib/offline/install-prompt.ts` (pure: `shouldShowInstallCard({ now, dismissedAt, isStandalone, onboarded, onLearnTab, hasPromptEvent, isIos }): "prompt" | "ios-steps" | "hidden"` and `isStandaloneDisplay(matchMedia, navigator)`), `src/app/_shell/InstallCard.tsx` (captures `beforeinstallprompt`, typed with a local `BeforeInstallPromptEvent` interface), `src/app/_shell/UpdateToast.tsx` (listens via `@serwist/window` `Serwist` instance `waiting` event; "Refresh" → `messageSkipWaiting()` then reload once on `controlling`).
- **UI (CTO-004):** `Card`, `Button`; the update notice uses `useToast().show({ title: "A new version of Polyglow is ready", action: { label: "Refresh", onClick }, duration: null, tone: "info" })` from the shared `ToastProvider` (sticky, `role="status"`).
- **Edge cases:** suppress the toast while `usePathname()` starts with `/lesson/`; keep the "update waiting" flag and show it when the route changes away from a lesson. Seven days = `7 * 24 * 60 * 60 * 1000` ms compared on instants (`now` injected).
- **Tests:** Vitest table tests for `shouldShowInstallCard` (shown, dismissed, hidden on day 6, shown on day 8, standalone, iOS) and `isStandaloneDisplay`. RTL for the card buttons with a fake `beforeinstallprompt` event. The update toast route rule gets one RTL test with `usePathname` mocked.

## Implementation notes
_(dev-platform, 2026-11-12, branch `feature/plt-005-install-update-prompt`, merged with main after GAM-003/GAM-008, GAM-005, FIX-001, CON-002, README-001)_

1. `src/app/_pwa/install-prompt-store.ts` (Zustand vanilla store, local `BeforeInstallPromptEvent` interface): `init()` listens for `beforeinstallprompt`, calls `preventDefault()` and keeps the event. `InstallPromptCapture` (root layout) calls `init()` on hydration, so an event that fires during onboarding or on another tab is still kept.
2. `src/app/_shell/InstallCard.tsx` at the top of the Learn page: `Card` with a small decorative Lumi, h2 "Install Polyglow", "Open it from your home screen, even offline.", `Button`s "Install" / "Not now". It shows only when `shouldShowInstallCard(...)` (`src/lib/offline/install-prompt.ts`) returns `"prompt"`: profile `onboardingComplete`, pathname `/`, and an event is available. Buttons wrap (`flex-wrap`), so nothing truncates at 375 px.
3. "Install" calls `event.prompt()` and awaits `userChoice`. On `accepted` the card hides for the session, and the browser fires no new event once the app is installed. `appinstalled` also clears the event.
4. "Not now" stores `new Date(now).toISOString()` in `localStorage["polyglow.installPromptDismissedAt"]` (try/catch for private mode; the in-memory value still applies). The card is hidden while `now - dismissedAt < 7 * 24 * 60 * 60 * 1000`. A dismissed or failing native prompt takes the same path, with no error message.
5. `isStandaloneDisplay(matchMedia, navigator)`: `(display-mode: standalone)` or `navigator.standalone === true`. In that case the card is always hidden.
6. iOS (`isIosDevice`: iPhone/iPod/iPad UA, or iPadOS "MacIntel" with touch), no event: the same card with "Tap Share, then Add to Home Screen." and "Got it". It follows the same 7-day rule and storage key.
7. `src/app/_shell/UpdateToast.tsx` + `src/app/_pwa/sw-update.ts`, built on the plain Service Worker API (no new dependency; `@serwist/window` is only transitive). `watchForWaitingWorker` reports a worker that is already waiting (with an active one) or one that reaches `installed` after `updatefound`; a first install is never reported. It shows `useToast().show({ title: "A new version of Polyglow is ready", action: { label: "Refresh" }, duration: null, tone: "info" })`. "Refresh" posts `{ type: "SKIP_WAITING" }` (Serwist's worker handles it when `skipWaiting: false`) and reloads once on `controllerchange` (module-level guard). If another tab already activated the worker, it reloads right away. Mounted in the root layout and active only in production builds.
8. `isLessonRoute` (`src/app/_shell/lesson-route.ts`, now shared with the offline banner) suppresses the toast on `/lesson` and `/lesson/*`. The waiting worker is kept in state and the toast shows once the pathname leaves the lesson. It is also withdrawn if the learner enters a lesson while it is showing. The install card never shows there either, because it is Learn-only.
9. The card is `role="status"` `aria-live="polite"`, labelled by its h2 and described by its body, with native buttons. The toast sits in the shared `ToastProvider`'s `role="status"` region. Both are covered by keyboard (Tab/Enter) tests in RTL and Playwright, and the card passes axe.
10. Unit tests: `src/lib/offline/__tests__/install-prompt.test.ts` (table: shown, dismissed, day 6 hidden, 7 days minus 1 ms hidden, exactly 7 days shown, day 8 shown, standalone, iOS steps and their 7-day rule, unreadable value; `isStandaloneDisplay`; `isIosDevice`; storage that throws). Also `src/app/_shell/__tests__/InstallCard.test.tsx` (fake `beforeinstallprompt`) and `src/app/_shell/__tests__/UpdateToast.test.tsx` (fake registration/workers, lesson route with mocked `usePathname`).

E2E: `tests/e2e/install-prompt.spec.ts` (dev projects; a stand-in `beforeinstallprompt`, because headless Chromium never fires a real one; covers Install, Not now + reload + day 8, Profile tab, iOS UA). `tests/e2e/update-toast.pwa.spec.ts` (`pwa-prod`): a second worker version is registered under `/sw.js?v=2` (Playwright can't intercept the worker script fetch); it checks Refresh → exactly one reload with the new worker in control, and no toast under `/lesson/*` until "Back to Learn". The full suite passes locally on Chromium 1243.

Known limit: if Chromium fires `beforeinstallprompt` before React hydrates, the event is missed for that page load (the next load catches it). An inline early-capture script could close this gap later if analytics show it matters.
