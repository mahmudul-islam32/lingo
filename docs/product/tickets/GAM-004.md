# GAM-004: Streak status and `useStreak` hook
**Owner:** dev-gamification · **Priority:** P0 · **Depends on:** GAM-003 · **Milestone:** v0.3.0

## User story
As a learner, I want my streak to go up on each day I complete a lesson, and the app to
know whether today still needs a lesson, so that I'm reminded not to break it (US-GAM-08,
US-GAM-09).

## Context
The streak engine itself (`computeStreak`, local-date based, with DST, midnight and
timezone tests) was shipped by GAM-002 in `src/features/gamification/rules/streak.ts`.
Do **not** rewrite it. This ticket adds the one status value every streak UI needs (top
bar, Lumi, results screen) and the hook that serves it, so the UI tickets share one
definition (PD-017).

## Acceptance criteria
1. A pure function `getStreakStatus(streak: StreakState)` is exported from
   `@/features/gamification` and returns exactly one of:
   - `"none"`: `current === 0` and `longest === 0` (never completed a lesson);
   - `"extended"`: `extendedToday === true` (a lesson was finished today);
   - `"at_risk"`: `current > 0` and `extendedToday === false` (finished yesterday, not
     yet today);
   - `"broken"`: `current === 0` and `longest > 0` (a full day was missed).
2. A pure function `didExtendStreak(before: StreakState, after: StreakState)` returns
   `true` only when `before.extendedToday` is false and `after.extendedToday` is true
   (the first lesson of the day). It is used by LES-010.
3. A pure function `formatStreakDays(n)` returns "1 day" for 1 and "N days" otherwise
   (including "0 days").
4. A hook `useStreak(courseId)` returns `{ status, streak, streakStatus }` from
   `useUserProgress` (GAM-003). No second read of the results.
5. When the local date changes while the app is open (`useLocalToday` from GAM-003), the
   hook's `streakStatus` changes without a reload, e.g. `"extended"` → `"at_risk"` at
   midnight, and `"at_risk"` → `"broken"` one day later.
6. The existing `streak.test.ts` cases (DST, midnight, travel, future dates) stay
   unchanged and pass.
7. Unit tests cover every status in criterion 1, `didExtendStreak` for: first lesson
   today, second lesson today, first lesson ever, lesson after a broken streak; and
   `formatStreakDays` for 0, 1, 2.
8. A hook test advances a fake clock across local midnight in two timezones
   (`Europe/Berlin`, `America/Los_Angeles`) and checks criterion 5.
9. Branch coverage of the new module is 100 %.

## Out of scope
- Changing `computeStreak` rules (only via a new decision)
- Streak freeze and repair (Phase 2)
- Streak reminders and notifications (Phase 2)
- Any visual component (GAM-007, GAM-009, LES-010)

## UX notes
No UI. Product meaning of the statuses, used for copy elsewhere:
- **none:** "Finish a lesson to light your first streak."
- **extended:** streak shown lit; no nagging.
- **at_risk:** streak shown but unlit; "Do a lesson today to keep your N-day streak."
- **broken:** "Your streak went out. Start a new one today."
- **Loading / error:** passed through from `useUserProgress`.

## Parallel work
Needs GAM-003. Can be built at the same time as GAM-006 and GAM-008. GAM-007, GAM-009
and LES-010 use it.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-gamification · **Branch:** `feature/gam-004-streak-status`

- **Contracts:** `StreakState` (`current`, `longest`, `lastActiveDate`, `extendedToday`), `StreakStateSchema`. `StreakStatus` (`"none" | "extended" | "at_risk" | "broken"`) is a feature type exported from `@/features/gamification`, not a contract: only gamification computes it, and other features import it from the public API. No contract change needed.
- **Reuse:** `computeStreak` (GAM-002) unchanged. `useUserProgress` and `useLocalToday` (GAM-003). The hook does no reads of its own (AC 4).
- **Files:** `src/features/gamification/rules/streak-status.ts` (`getStreakStatus`, `didExtendStreak`, `formatStreakDays`, `type StreakStatus`) + `rules/__tests__/streak-status.test.ts`; `src/features/gamification/hooks/use-streak.ts` + test; barrel lines.
- **Rule order:** check `extendedToday` first, then `current > 0` → `at_risk`, then `longest > 0` → `broken`, else `none`. The schema already rules out `extendedToday && current === 0`. `didExtendStreak` compares only `extendedToday` (AC 2), so "lesson after a broken streak" returns true.
- **Criterion 5:** happens for free because `useUserProgress` re-derives from `useLocalToday`; test it, don't add another timer.
- **Tests:** pure table tests for every status and `didExtendStreak` case; `formatStreakDays(0|1|2)`. Hook test: `vi.stubEnv("TZ", …)` is not reliable in-process, so inject the timezone: `useLocalToday` should take an optional `timeZone` (default device), and the test renders with `"Europe/Berlin"` and `"America/Los_Angeles"` while advancing fake timers across midnight. `streak.test.ts` must stay byte-identical (`git diff` empty).
