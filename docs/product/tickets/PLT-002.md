# PLT-002: Installable PWA: manifest, icons, service worker, offline shell
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-001 · **Milestone:** v0.1.0

## User story
As a learner, I want to install Polyglow on my phone's home screen and have it open even
without a connection so that it feels like a native app (US-PLT-13, US-PLT-14).

## Acceptance criteria
1. A web app manifest is served and linked from every page, with: `name` "Polyglow",
   `short_name` "Polyglow", `start_url` "/", `scope` "/", `display` "standalone", `lang`
   "en", and `theme_color` / `background_color` taken from the brand tokens (midnight
   indigo / warm off-white).
2. The manifest lists PNG icons at 192 × 192 and 512 × 512, plus a 512 × 512 icon with
   `purpose: "maskable"`. A 180 × 180 `apple-touch-icon` is linked.
3. All icons are original Polyglow/Lumi artwork (a simple original glyph is fine for now).
   No third-party or stock assets.
4. iOS meta tags are present: `apple-mobile-web-app-capable`,
   `apple-mobile-web-app-status-bar-style`, `apple-mobile-web-app-title` "Polyglow".
5. A Serwist service worker is generated by `npm run build` and registered in production
   builds. It is not registered under `npm run dev`.
6. The app shell (`/`, `/profile`, `/onboarding`, JS/CSS, icons, fonts) is precached.
   After one online visit, reloading `/` with the network offline renders the app shell,
   not the browser's offline error page.
7. Opening a route that isn't cached while offline shows an offline fallback page with the
   heading "You're offline" and a "Try again" button that reloads the page.
8. Chrome DevTools > Application > Manifest shows no installability errors on a production
   build served over `localhost`.
9. No console errors appear on first load or on a reload with the service worker active.
10. A Playwright test (production build) visits `/` online, sets the browser context
    offline, reloads, and asserts the Learn page heading is visible.
11. The offline fallback page meets the PLT-001 accessibility rules (one `<h1>`, `<main>`,
    focusable button, no serious/critical axe violations).

## Out of scope
- Custom install prompt and update toast (PLT-005)
- Caching lesson content and audio (PLT-007 precaches Unit 1 JSON; full offline audio is
  PLT-015)
- Push notifications (Phase 2)
- Splash screens per iOS device size (we rely on manifest colours and icons)

## UX notes
- **Success:** installed app opens full-screen with the indigo theme colour in the status
  bar and the Learn tab.
- **Offline fallback (error state):** Lumi slot (GAM-001 "ember" pose if merged), heading
  "You're offline", body "Check your connection and try again.", primary "Try again".
- **Loading:** none beyond PLT-001's loading UI.
- **Empty:** not applicable.

## Implementation notes
_(dev-platform, 2026-11-07, branch `feature/plt-002-pwa-offline`, rebased on main after PLT-001 #20, GAM-001 #19, CTO-005 #22; ships together with PLT-006)_

1. `src/app/manifest.ts` (`/manifest.webmanifest`, linked by Next on every page): name/short_name "Polyglow", `start_url`/`scope` "/", `display: "standalone"`, `lang: "en"`, `theme_color = BRAND_HEX.night950` (midnight indigo), `background_color = BRAND_HEX.canvasLight` (warm off-white). Unit test `src/app/_pwa/__tests__/manifest.test.ts`.
2. Icons `public/icons/icon-192.png`, `icon-512.png` (`purpose: "any"`), `icon-maskable-512.png` (`purpose: "maskable"`, full bleed, glyph inside the 40 % safe zone); `public/apple-touch-icon.png` (180 × 180) linked via `metadata.icons.apple`. The unit test reads the PNG headers to check the declared sizes.
3. Original Lumi lantern glyph, hand-written SVG in `src/app/_pwa/generate-icons.mjs` (brand palette only), rasterised with `sharp` (already installed by Next). Also generates the favicon `src/app/icon.svg`; the template's `favicon.ico` (third-party art) is removed.
4. `metadata.appleWebApp` (`apple-mobile-web-app-title` "Polyglow", `apple-mobile-web-app-status-bar-style` `black-translucent`, body pads `env(safe-area-inset-top)`) plus `other["apple-mobile-web-app-capable"] = "yes"`, because Next 16 only emits `mobile-web-app-capable`.
5. Serwist `@serwist/next` + `serwist` 9.5.13 (exact). `next.config.ts` wraps the config with `withSerwistInit({ swSrc: "src/app/sw.ts", swDest: "public/sw.js", disable: NODE_ENV !== "production", register: false, reloadOnOnline: false })`. `@serwist/next` is webpack-only, so **`npm run build` is now `next build --webpack`** (dev stays on Turbopack, worker disabled). Tailwind under webpack: the same `@tailwindcss/turbopack` loader runs as an `enforce: "pre"` rule with a `resource` condition (a `test` rule would make Next disable its built-in CSS). `_shell/ServiceWorkerRegistration.tsx` registers only when `NODE_ENV === "production"` (unit-tested), after `load`.
6. Precache = Serwist's chunk/CSS/`public/` manifest + `PRECACHED_ROUTES` (`/`, `/profile`, `/onboarding`, `/offline`, `/manifest.webmanifest`, `/icon.svg`) appended in `manifestTransforms` with a per-build revision. No web fonts exist yet (system font stack). `clientsClaim: true` so the first worker controls the tab after one visit. Verified in `tests/e2e/pwa.spec.ts`.
7. `src/app/offline/page.tsx` (static): decorative `Lumi pose="ember"` (GAM-001), h1 "You're offline", "Check your connection and try again.", `Button` "Try again" → `location.reload()`. Serwist `fallbacks` serve it for any `document` request that fails; e2e checks an uncached URL offline.
8. Manifest has name, icons 192/512, `start_url`, `display`, and the worker has a fetch handler. Manual DevTools check not possible in this unattended run (no headed browser); the e2e spec covers the manifest fields and icon responses. **To do in review:** DevTools > Application > Manifest on `npm run build && npm run start`.
9. `pwa.spec.ts` "registers a service worker without console errors" collects `console.error`/`pageerror` on first load and on a reload with the worker active.
10. `pwa.spec.ts` "reloading / while offline renders the Learn page" (project `pwa-prod`, `next start` on port 3100).
11. Offline page: one `<main>` (`_shell/Main`), one `<h1>`, native focusable button; e2e runs axe on it. Unit test `src/app/offline/__tests__/offline-page.test.tsx`.

Runtime caching (`src/app/sw.ts`): Supabase (`*.supabase.co` and `/(auth|rest|realtime|storage|functions|graphql)/v1/`) `NetworkOnly` first, then Serwist's `defaultCache`; PLT-007/PLT-015 insert their rules above `defaultCache`. `skipWaiting: false` (updates wait for PLT-005).

Tooling touched for this ticket (cto review): `package.json` (deps + `build` script), `next.config.ts`, `.gitignore` / `.prettierignore` / `eslint.config.mjs` ignore the generated `public/sw.js*` and `public/swe-worker*`, `playwright.config.ts` adds the `pwa-prod` project and a second `webServer` (`next start --port 3100`; builds first when not in CI).

E2E: run locally against the pre-installed Chromium 1243 (Playwright's own download is blocked here): `pwa.spec.ts`, `offline-banner.spec.ts` and `shell.spec.ts` all pass on production servers. `pwa-prod` runs in the CI e2e job (CTO-005) after `npm run build`, against `next start --port 3100`.

Open question: AC1 asks for an off-white `background_color` while the app is dark-first (ADR-004), so the splash screen is off-white before the dark shell paints. Followed the AC; switching to `BRAND_HEX.night950` is a one-line change.
