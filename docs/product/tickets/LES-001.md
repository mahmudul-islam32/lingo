# LES-001: Answer checking (`checkAnswer`)
**Owner:** dev-lessons · **Priority:** P0 · **Depends on:** CTO-002 · **Milestone:** v0.2.0

## User story
As a learner, I want my answers to be judged fairly and consistently so that I'm not
marked wrong for a valid answer (US-LES-10, US-CON-03).

## Acceptance criteria
1. A pure function `checkAnswer(exercise, answer)` in `/src/features/lessons` returns the
   result type defined in `/src/contracts` (at least: `correct: boolean` and the canonical
   correct answer to display).
2. It handles every MVP exercise type in the contracts union: multiple choice, translate
   (word bank), listen (word bank) and match pairs. A TypeScript exhaustiveness check makes
   the build fail if a new type is added to the union without being handled.
3. **Multiple choice:** correct only when the selected option is the exercise's correct
   option.
4. **Translate and listen:** the learner's ordered tiles are joined into a sentence and
   compared with each accepted answer. Correct if it matches **any** accepted answer.
5. Text comparison ignores letter case, leading/trailing whitespace, repeated spaces, and
   these punctuation marks: `. , ! ? ¡ ¿ ; : …` and double quotes (straight `"` and
   curly `“ ”`). Single quotes / apostrophes are not removed (see criterion 6).
6. Accents and `ñ` are significant (PD-010): "si" does not match "sí", "ano" does not match
   "año". Apostrophes inside English words are kept ("I'm" ≠ "Im").
7. The canonical answer returned for display is the first accepted answer as written in the
   content (original casing, accents and punctuation).
8. **Match pairs:** correct when every pair is matched; the result reports whether any
   mismatch happened during the exercise (used for accuracy, PD-012).
9. The function has no side effects and imports nothing from React, the DOM or storage.
10. Unit tests cover at least: each type correct/incorrect; case ("Hola" vs "hola");
    punctuation ("¡Hola!" vs "hola"); extra spaces; second accepted answer; accent
    mismatch; `ñ` mismatch; empty answer is incorrect; tile order matters ("buenos días"
    vs "días buenos"). Line coverage of the module is at least 95 %.

## Out of scope
- Typo tolerance and typed (keyboard) answers (Phase 2)
- Diacritic tolerance (Phase 2, with typed answers)
- Speech recognition matching (LES-011)

## UX notes
No UI. The canonical answer string is what LES-003 shows after "Correct answer:".

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-lessons · **Branch:** `feature/les-001-check-answer`

- **Contracts (`@/contracts`):** implement `CheckAnswer = (input: AnswerCheckInput) => AnswerCheckResult`. Input `{ exercise: Exercise; answer: AnswerInput }` (answer type equals exercise type); output `{ exerciseId, outcome: "correct" | "incorrect" | "skipped", correctAnswer: string | null, heartCost }`. Text helpers `normalizeAnswerText`, `tokenizeAnswer`, `foldDiacritics`; `GAME_CONFIG.heartsLostPerMistake`.
- **Name/shape mapping (cto decision, contracts win):** criterion 1's `checkAnswer(exercise, answer)` is `checkAnswer({ exercise, answer })`; "`correct: boolean`" is `outcome === "correct"`. `heartCost = GAME_CONFIG.heartsLostPerMistake` for `incorrect` (any non-speak type), else 0. The player decides whether hearts are actually deducted (v0.3.0).
- **Rules (ARCHITECTURE §8):**
  - `multiple_choice`: `answer.optionId === exercise.correctOptionId`; `correctAnswer` = text of the correct option.
  - `word_bank_translate` / `listen`: `normalizeAnswerText(answer.tiles.join(" "))` equals `normalizeAnswerText(a)` for any `a` of `exercise.answers`; `correctAnswer = exercise.answers[0]` verbatim (criterion 7). Empty tiles → incorrect.
  - `normalizeAnswerText` already implements criteria 5 and 6 (case, whitespace, `. , ! ? ¡ ¿ ; : …` and straight/curly double quotes removed; apostrophes kept and unified; accents and ñ significant). It also strips brackets and dashes, which content never uses inside answers. Do **not** add a second normaliser in the feature.
  - `match_pairs`: correct iff `matches` covers every pair id exactly once and each `learningPairId === knownPairId`; `correctAnswer: null`; never costs a heart. **Criterion 8 (updated by CR-001):** the answer carries `mismatchCount`; the result's `mistake` is true when `mismatchCount > 0` (outcome stays `correct`, `heartCost` 1, applied from v0.3.0). An incomplete board is `incorrect`.
  - `speak` (LES-011, v1.0.0, implement now because the union is exhaustive): `skipped` → `outcome: "skipped"`; else any transcript `foldDiacritics`-equal to `phrase` or an `acceptedTranscripts` entry → correct; `correctAnswer = phrase`; `heartCost` always 0.
- **Exhaustiveness:** `switch (input.exercise.type)` with a `default: { const never: never = input.exercise; throw … }`. Narrow the answer with a small guard (`answer.type === exercise.type`) rather than casts.
- **Files:** `src/features/lessons/checking/checkAnswer.ts`, `src/features/lessons/checking/index.ts`, `src/features/lessons/index.ts` (public barrel exports `checkAnswer`). No React/DOM/storage imports (criterion 9; an ESLint `no-restricted-imports` override is not required, review will check).
- **Tests:** `src/features/lessons/checking/checkAnswer.test.ts`, table-driven, using exercises parsed through the contract schemas (`MultipleChoiceExerciseSchema.parse(...)`), so fixtures are always valid. Cover every case in criterion 10 plus: second accepted answer, apostrophe ("I'm" vs "Im"), curly quotes, match pairs with a wrong/missing/duplicated pair, speak skipped/correct/folded. Every returned value must pass `AnswerCheckResultSchema.parse`. Coverage ≥ 95 % lines (add `@vitest/coverage-v8` as a devDependency if you want the number in CI; otherwise paste the local report in the PR).
