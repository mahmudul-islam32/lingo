# PLT-003: Guest mode: on-device learner profile
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** CTO-002 · **Milestone:** v0.1.0

## User story
As a new visitor, I want to start learning without creating an account so that I can try
the app first (US-PLT-01).

## Acceptance criteria
1. On the first visit, a guest profile is created on the device in IndexedDB (Dexie) with a
   random UUID, a `createdAt` timestamp and default settings as defined in the contracts
   (no course chosen, no daily goal, onboarding not complete).
2. The guest profile keeps the same id after a page reload and after closing and reopening
   the browser.
3. Creating and reading the guest profile makes no network requests and works with the
   network offline.
4. The guest-profile functions defined in `/src/contracts` (`api.ts`) are implemented for
   guest storage: at least read the profile, update settings (course, daily goal), and set
   onboarding complete. If a needed function is missing from the contracts, a request is
   filed in `docs/architecture/contract-requests.md` instead of redefining types.
5. Daily goal values are validated against the allowed options from contracts/config
   (10 / 20 / 30 / 50 by default, PD-003). An invalid value is rejected with a typed error
   and not stored.
6. If IndexedDB can't be opened (for example some private browsing modes), the app falls
   back to in-memory storage, keeps working for the session, and exposes a flag so the UI
   can show the "can't save" notice (see UX notes).
7. The Dexie database has an explicit schema version number, so later tickets can add
   tables with a migration.
8. Only data needed for learning is stored (no email, no name until the learner provides
   one). Nothing is sent to analytics or any server by this ticket.
9. Unit tests (with `fake-indexeddb` or equivalent) cover: first-visit creation, reload
   keeps the id, settings update, invalid daily goal rejected, in-memory fallback.

## Out of scope
- Onboarding UI and redirects (PLT-004)
- Saving lesson results (PLT-008)
- Moving guest data to an account (PLT-013, v0.4.0)
- Clearing / resetting guest data from settings (PLT-017)

## UX notes
- No screen of its own. Guest mode is invisible: the learner just starts.
- **Loading:** while the profile is being read, the shell shows PLT-001's loading UI; a
  returning learner must not see a flash of onboarding.
- **Error (storage unavailable):** non-blocking banner, `role="status"`: "Progress can't
  be saved in this browser mode. You can still learn, but it will be lost when you close
  the tab." Dismissible with a close button labelled "Dismiss".
- **Success/empty:** not applicable.

## Parallel work
Can be built at the same time as PLT-001 and GAM-001. No UI file overlap with PLT-001
except the storage banner slot, which the cto should place in Technical notes.
