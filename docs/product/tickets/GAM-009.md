# GAM-009: Lumi reflects the streak (glowing / ember)
**Owner:** dev-gamification · **Priority:** P1 · **Depends on:** GAM-001, GAM-004 · **Milestone:** v0.3.0

## User story
As a learner, I want Lumi to glow when I've practised today and dim when my streak is at
risk or gone, so that I can feel my streak at a glance and want to keep it lit (US-GAM-09;
brand story in PD-001).

## Acceptance criteria
1. A pure function `lumiPoseForStreak(streakStatus)` is exported from
   `@/features/gamification` and maps the GAM-004 statuses to the existing GAM-001 poses:
   - `"extended"` → `"happy"` (glowing);
   - `"at_risk"` → `"idle"` (normal glow, waiting);
   - `"broken"` → `"ember"`;
   - `"none"` → `"idle"`.
2. A component `StreakLumi` (props: `courseId`) renders `<Lumi />` from
   `@/components/ui` (PD-016) with the mapped pose at size `md`, plus one message line:
   - extended: "You're glowing! Your streak is safe today."
   - at_risk: "Do a lesson today to keep your N-day streak." (N = `streak.current`,
     e.g. "1-day streak", "3-day streak")
   - broken: "Your streak went out. Start a new one today."
   - none: "Finish a lesson to light your first streak."
3. Lumi stays decorative (`aria-hidden`); the message line carries the meaning and is
   plain text (not a live region on page load).
4. When the status changes while Learn is open (a lesson finished, or local midnight),
   pose and message change without a reload.
5. No new SVG artwork: only the four GAM-001 poses are used. Pose mapping lives in the
   gamification feature, not in `src/components/ui`.
6. **Loading state:** Lumi `idle` with a one-line text skeleton (no layout shift when the
   message arrives).
7. **Error state:** Lumi `idle` and no message line (never an error text here).
8. At 375 px Lumi and the message fit in one row beside or above the daily goal ring
   (GAM-006) with no horizontal scrolling; the message wraps to at most 2 lines.
9. The message text meets 4.5:1 contrast in both themes.
10. Unit tests cover all four mappings, every message (including "1-day streak"), the
    loading and error states, and a status change re-render.

## Out of scope
- Animated Lumi or reactions (Phase 2 "mascot animations")
- New poses (would need a GAM-001 follow-up)
- Lumi inside lessons (results screen already uses "celebrating", LES-008)
- Streak reminders (Phase 2)
- Mounting on Learn (PLT-009)

## UX notes
- **Normal:** Lumi on the left, message on the right, inside the Learn header area.
- **Loading:** idle Lumi + text skeleton.
- **Error:** idle Lumi only.
- **Empty (new learner):** status `none`, idle Lumi, "Finish a lesson to light your
  first streak."
- Tone: warm and encouraging; never guilt-tripping ("went out", not "you failed").

## Parallel work
Needs GAM-004 (statuses) and GAM-001 (merged). Can be built at the same time as GAM-007
and LES-010. PLT-009 mounts it.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-gamification · **Branch:** `feature/gam-009-streak-lumi`

- **Contracts:** `StreakState.current`. `LumiPose` comes from `@/components/ui` (not a contract). No contract change needed.
- **Placement (PD-016):** GAM-001 was merged with Lumi already in `src/components/ui/` (`Lumi.tsx`, `lumi-poses.tsx`, `LUMI_POSES`, `LUMI_SIZE_PX`), so nothing has to move. Import `{ Lumi, type LumiPose }` from `@/components/ui`; never add pose-selection logic to `src/components/ui`.
- **Reuse:** `useStreak` + `type StreakStatus` (GAM-004), `Skeleton` (text line).
- **Files:** `src/features/gamification/rules/lumi-pose.ts` (`lumiPoseForStreak(status): LumiPose`, exhaustive `switch` with a `never` check) and `rules/streak-message.ts` (`streakMessage(status, current)`), `components/StreakLumi.tsx`, tests, barrel lines.
- **Messages:** "N-day" is a compound adjective, so it is not `formatStreakDays` ("1-day streak", "3-day streak"). At-risk always has `current >= 1` by the GAM-004 rule.
- **Rendering:** `<Lumi pose size="md" />` with no `label` so it stays `aria-hidden` (GAM-001: without `label` Lumi renders `aria-hidden`); message in a `<p className="text-fg line-clamp-2">`; no `aria-live`. Loading: idle Lumi + `Skeleton` line of the same height; error: idle Lumi only.
- **Tests:** `lumiPoseForStreak` for all four statuses, every message incl. "1-day streak", loading, error, and a re-render with a changed mocked `useStreak` result.
