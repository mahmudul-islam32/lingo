# GAM-007: Top bar: streak, total XP, hearts
**Owner:** dev-gamification · **Priority:** P0 · **Depends on:** GAM-003, GAM-004, GAM-005, CTO-004 · **Milestone:** v0.3.0

## User story
As a learner, I want to see my streak, total XP and hearts at the top of the home screen
so that I'm reminded not to break my streak and know if I can start a lesson
(US-GAM-09, US-GAM-10, US-GAM-12).

## Acceptance criteria
1. A component `GamificationTopBar` (props: `courseId`) is exported from
   `@/features/gamification` and shows three items in this order: **streak**, **total
   XP**, **hearts**.
2. **Streak** shows a flame-style glow icon (original SVG, not an animal or bird) and the
   current streak number. The icon is lit (amber, filled) when `streakStatus` is
   `"extended"`, and unlit (outlined, muted) otherwise, with the state also in the
   accessible name (not colour alone).
3. The streak item's accessible name is "Streak: N days" plus ", done for today" when
   `"extended"` or ", do a lesson today to keep it" when `"at_risk"` (uses
   `formatStreakDays` from GAM-004).
4. **Total XP** shows the `XpBadge` (CTO-004) with `progress.totalXp`. Accessible name
   "Total XP: N".
5. **Hearts** shows the `HeartsMeter` (GAM-005) with `useHearts().view.current`.
6. The hearts item is a button. Activating it (tap, Enter or Space) opens a dialog
   (CTO-004 `Dialog`) titled "Hearts" that shows the meter, the text from
   `formatHeartRefill` and `formatHeartsFull`, or "Your hearts are full." when full, plus
   one line explaining the rule: "You lose a heart for each wrong answer. One heart comes
   back every 4 hours." (hours from `GAME_CONFIG`). A "Got it" button closes it and focus
   returns to the hearts button.
7. While the dialog is open, the refill text updates at least once per minute.
8. Values update without a reload after a lesson (GAM-003/GAM-005 invalidation) and
   when a heart refills while Learn is open.
9. The bar has no heading of its own (the page keeps one `<h1>`) and has
   `aria-label="Your progress"`; the three items are in a list so a screen reader
   announces "list, 3 items".
10. **Loading state:** three skeleton pills of the final size (no layout shift).
11. **Error state:** an item that can't be read shows "–" with the accessible name
    "Streak unavailable" / "XP unavailable"; hearts fall back to full (GAM-005 UX notes).
    The bar never shows an error banner.
12. At 375 × 667 all three items fit on one row with no horizontal scrolling; the hearts
    button tap target is at least 44 × 44 px; focus ring visible on the button.
13. No colour literals (grep of new files for hex/rgb is empty); only tokens, so
    contrast holds in both themes. Axe on the mounted bar is checked in PLT-009
    criterion 8.
14. RTL tests cover: new learner (0 days, 0 XP, 5 hearts); extended and at-risk
    accessible names; 0 hearts with countdown in the dialog; dialog keyboard open/close
    and focus return; loading; error per item.

## Out of scope
- Tapping streak or XP (no detail screens in MVP; Phase 2 streak calendar)
- Leagues or gems (Phase 2 / not planned)
- Showing the bar inside a lesson (the lesson header has its own hearts, LES-009)
- Mounting it on Learn (PLT-009)

## UX notes
- **Layout:** sticky top row on Learn, `surface` background, items spaced evenly;
  streak left, XP centre, hearts right.
- **Normal:** the streak icon is our own small lantern-flame drawing (no emoji, no
  third-party icon), number in bold.
- **Loading:** skeleton pills.
- **Error:** "–" per item (criterion 11).
- **Empty (new learner):** 0 streak unlit, 0 XP, 5 hearts.
- **0 hearts:** outlined heart and "0"; the dialog tells the learner when the next heart
  arrives.
