# PLT-027: Goal date in Profile (row and dialog), Learn card mount, results wiring
**Owner:** dev-platform · **Priority:** P1 · **Depends on:** CTO-017, GAM-013, LES-022 (for
criterion 13 only), PLT-025, PLT-026 · **Milestone:** v0.5.4 Goal date · **Decisions:** PD-035,
PD-069, PD-071 §1

## User story
As a learner with a date in mind, I want to set, change or remove a target level and date in
my profile, see a preview of what it takes, and reach that setting from the Learn tab, so
that Polyglow can plan my daily goal with me (US-GD-01, US-GD-04).

## Acceptance criteria
Field names follow CTO-017; status and copy on Learn come from GAM-013.

### Profile row
1. Profile's settings list has a row "Goal date" directly below "Daily goal" (PD-069). It shows
   "Finish <level code> by <date>" (e.g. "Finish A2 by 12 Mar 2027", same date format as
   GAM-013 criterion 9) or "Not set", and a button "Set" (no plan) or "Change" (plan set),
   with the accessible name "Set goal date" / "Change goal date".

### Dialog
2. The button opens a modal dialog titled "Your goal date" with:
   - **Level** radio group "Which level do you want to finish?": every level of the course
     **with content** at or after the learner's start level (today A1 and A2; with start
     level A2 only A2). Preselected: the saved target, else the last level with content.
   - **Date** field "By when?" (`<input type="date">`, labelled), `min` = tomorrow,
     `max` = today + `GAME_CONFIG.goalPlanMaxDays`; prefilled with the saved date, else empty.
3. **Preview:** once a valid date is entered, the dialog shows "<lessonsLeft> lessons left ·
   about <lessonsPerDay> lessons a day. Suggested daily goal: <suggested> XP." from
   `computeGoalPlan` with the dialog's values (not yet saved). For `reached` it shows "You've
   already finished <level code>." For `tight` it adds "This date is tight. You could pick a
   later date."
4. **Validation** on Save: an empty date shows "Pick a date."; a date ≤ today shows "Pick a
   date after today."; a date after the max shows "Pick a date within 2 years." Errors are
   linked to the field (`aria-describedby`, `aria-invalid`) and focus moves to the field.
5. **Save** stores `goalPlan` through the existing settings update, closes the dialog, shows
   the toast "Goal date saved." and returns focus to the row's button. It does **not** change
   `dailyGoalXp` (PD-071: suggest only).
6. When a plan is saved, the dialog also shows a text button "Remove goal date". It clears the
   plan (CTO-017 clear semantics), closes the dialog, shows "Goal date removed." and the row
   shows "Not set".
7. **Cancel**, Escape and the close button discard the dialog's values; focus returns to the
   row's button.
8. If saving or removing fails, the dialog stays open with the values kept and shows the inline
   error "We couldn't save your goal date. Try again."
9. Opening `/profile?edit=goal-date` scrolls to the row and opens the dialog once; closing it
   removes the query parameter (history `replace`, no extra back step).

### Learn and results wiring
10. Learn mounts `GoalPlanCard` (GAM-013) under the daily-goal ring and above the path, with
    `useGoalPlan()`'s status. `onEditGoalDate` navigates to `/profile?edit=goal-date`.
11. `onUseSuggestedGoal(xp)` saves `dailyGoalXp = xp` through the same settings update as the
    Daily goal row (PD-069), shows the toast "Daily goal set to <xp> XP." and the ring, the
    weekly chart line and the card update without a reload. On failure: toast "We couldn't
    change your daily goal. Try again." and nothing changes.
12. Learners without a plan see no change on Learn other than GAM-013's text link; existing
    Learn and Profile tests pass unchanged.
13. The lesson route passes the goal-plan status computed **after** the lesson's result is
    saved to `ResultsScreen` (LES-022's prop), and passes nothing when there is no plan.
14. Onboarding is unchanged (no goal-date step, PD-071: protects time to first lesson).

### Quality
15. Works offline and for guests (settings are local); no network call is added.
16. RTL tests cover criteria 1–9 and 11 (including validation messages, focus return, remove,
    save failure, the query parameter); no serious or critical axe violations on Profile with
    the dialog open.
17. At 375 × 667 the row, the dialog (incl. the native date picker trigger and the preview)
    and the Learn card fit without horizontal scrolling; the dialog scrolls inside itself if
    needed; buttons and radios have at least 48 px targets.
18. e2e (Playwright, 375 px, keyboard only, fixed clock 2026-11-21): set target A2 by
    2027-03-12 in Profile → Learn shows "Goal: finish A2 by 12 Mar 2027" and "130 lessons
    left · 111 days to go"; with daily goal 10, "Use 20 XP a day" sets the goal to 20 and the
    card says "On track."; remove the plan in Profile → Learn shows the "Set a goal date" link.

## Out of scope
- A goal-date step in onboarding (revisit with analytics, PD-071)
- The rule and the card component (GAM-013); the results line (LES-022)
- Reminders, a weekly plan, sync of the plan to an account (v0.6.0 carries it with settings)

## UX notes
- **Row states:** "Not set" + "Set"; "Finish A2 by 12 Mar 2027" + "Change".
- **Dialog states:** empty date (no preview, Save enabled; validation on Save), valid date
  (preview), `tight` (extra line), `reached` (preview says already finished; Save still
  allowed), saving (Save disabled with "Saving…"), error (inline message), success (toast).
- **Copy rules:** "goal date", "your date"; never "exam", "test" or "pass" (PD-035, GAM-013
  criterion 14 applies to the dialog too).
- Mobile-first: the native date input is used so the phone's own date picker opens.
