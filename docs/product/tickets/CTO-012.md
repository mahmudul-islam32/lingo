# CTO-012: Reading passages and reverse-direction multiple choice (B1-T3)
**Owner:** cto (contract) · **Priority:** P1 · **Depends on:** CTO-008 · **Milestone:** v1.1.0
(falls back to v1.1.1 if late) · **Decisions:** PD-012, PD-019, PD-060 · **ADR:** ADR-011
(proposed) · **Consumer:** LES-018 (planned, dev-lessons: passage component)

**Status:** cto technical ticket (CTO-010 plan).

## User story
As a B1 learner, I want to read a short German text (a flat ad, a notice, a letter, a news
item) and answer a few questions about it in English, so that I practise reading real
everyday texts.

## Acceptance criteria
1. **Reverse MC:** `multiple_choice` gains an optional `direction`: `"to_learning"` (default,
   today's behaviour: prompt in the known language, options in the learning language) or
   `"to_known"` (prompt in the learning language, options in the known language). Existing
   content stays valid without changes (PD-019's reversibility note).
2. **Passages:** a lesson gains an optional `passages` array. Each passage has an `id`, a
   `kind` (`letter`, `email`, `notice`, `ad`, `news`), an optional `title` and a `text` of up
   to 600 characters in the learning language (paragraphs separated by a blank line).
3. A `multiple_choice` exercise may reference a passage with `passageId`. The schema rejects
   an unknown `passageId`, a passage with fewer than 2 or more than 4 questions referencing
   it, and a passage question whose `direction` isn't `to_known`.
4. Each question is an ordinary MC exercise: the answer check, scoring (PD-012) and
   re-queueing don't change.
5. `lang` rules are documented for the component: passage text and title in
   `learningLanguage`; for `to_known` MC the prompt in `learningLanguage` and the options in
   `knownLanguage` (the reverse of today).
6. Unit tests for every schema rule, including a two-question flat-ad passage (U6 L1).

## Technical notes
_(cto)_
- **Why questions are separate MC exercises and not one `reading` exercise:** the player,
  scoring, hearts, re-queue and the results stats all work per exercise. A single exercise
  with sub-questions would need partial scoring and a new result shape. With `passageId`,
  the player only needs to show the passage above the question (ADR-011).
- **Files:** `src/contracts/course.ts` (MC `direction`, `PassageSchema`,
  `LessonSchema.passages`, cross-field rules in the lesson `superRefine`),
  `src/contracts/config.ts` (`passageMaxLength: 600`, 2–4 questions per passage,
  ≤ 3 passages per lesson), ADR-011.
- **Lesson order:** the questions of a passage should follow each other. The schema checks
  that they are contiguous in `exercises`. If a question is re-queued, the player shows the
  passage again with it.
- **LES-018 (planned, dev-lessons):** the passage appears above the first question of its
  group as a `<section aria-labelledby>` card with `lang={learningLanguage}`; on later
  questions it is collapsed behind a "Show the text" disclosure button (`aria-expanded`);
  `LES-004` reads `direction` to swap the `lang` of the prompt and options. At 375 × 667 a
  600-character passage scrolls inside the exercise area and the Check bar stays visible.
- **Audio:** optional passage audio is out of scope for v1.1.0 (B1-T7 and PD-055 cover
  prompt audio).
- **Compatibility:** bundled content (ADR-009 §5). `direction: "to_known"` must not appear in
  content before the release that contains the LES-004 change, because an older build would
  tag the options with the wrong language.
