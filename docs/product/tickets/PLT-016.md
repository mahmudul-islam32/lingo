# PLT-016: Profile screen and profile/settings reads through TanStack Query
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-009, GAM-003, GAM-004, CTO-004, CTO-006 · **Milestone:** v0.4.0

## User story
As a learner, I want a profile showing my total XP, current streak, longest streak,
lessons completed and join date so that I can see my overall progress (US-PLT-10).

## Context
`/profile` is an empty state today. Identity, profile and settings are still mirrored
into the profile feature's Zustand store (`guestProfileStore`), which is a deviation
ARCHITECTURE §5 plans to retire "with the next profile/settings ticket". This is that
ticket: it moves the reads to TanStack Query first, then builds the screen on top. It
works for guests and accounts alike and needs no backend.

## Acceptance criteria
**Reads through TanStack Query (ARCHITECTURE §5, ADR-005)**
1. Identity, profile and settings are read with `useQuery` over the shared `queryKeys`
   (`profile()`, `settings()` and an identity key). The cached values are the raw
   repository facts (`Profile | null`, `Settings | null`, `Identity`).
2. Writes (`updateSettings`, `completeOnboarding`, and later `updateProfile`) are
   mutations that invalidate the matching keys. No component reads profile, settings or
   identity from Zustand any more.
3. `guestProfileStore` keeps only UI state (the storage notice: `storage` info and
   `storageNoticeDismissed`), or is replaced by a smaller store with only that. No
   persisted data is mirrored in Zustand (tested: the store's state has no `identity`,
   `profile` or `settings` fields).
4. Onboarding (PLT-004), the onboarding gate, the Learn screen (PLT-009) and the lesson
   route behave exactly as before. Their existing unit and e2e tests pass without changing
   their assertions (only their setup and mocks may change).

**Profile screen (`/profile`)**
5. The header shows the avatar (a circle with the initials of the display name, e.g.
   "L" for "Learner"), the display name as the page's only `<h1>`, and under it "Guest"
   for a guest identity or nothing extra for an account. No email is shown on Profile.
6. A stats grid shows four labelled tiles:
   - **Total XP**: sum of `xpEarned` over all lesson results of the active course.
   - **Day streak**: current streak.
   - **Longest streak**.
   - **Lessons completed**: distinct lessons with at least one result. Replays don't
     count twice.

   Values come from the same pure rules as Learn (`computeUserProgress` /
   `computeStreak`), so Learn and Profile never disagree (tested with shared fixtures).
7. A line "Joined November 2026" (month and year of `profile.joinedAt`, English,
   device timezone) sits under the stats.
8. **New learner (no results):** the tiles show 0, plus the text "Finish your first lesson
   to start your streak." with a "Start learning" link (→ `/`).
9. **Loading:** skeleton tiles at their final size, with no layout shift when the values
   arrive (CLS ≤ 0.1).
10. **Error:** if the results or the profile can't be read, the screen shows "We couldn't
    load your profile." with a "Try again" button that refetches. The bottom navigation
    still works.
11. A settings button (gear icon, `aria-label="Settings"`, ≥ 44 × 44 px) sits in the
    header's top-right corner. It links to `/settings` once PLT-017 is merged, and is
    hidden until then.
12. A slot under the header is reserved for the guest "Save your progress" card (PLT-013
    criterion 17). It renders nothing in this ticket.
13. The page works offline after one online visit (all reads are local), and updates
    without a reload after a lesson or a sync pull (query invalidation).
14. Each stat tile has an accessible name that reads as one phrase (e.g. "Total XP: 45").
    The numbers use tabular figures. No serious or critical axe violations in the
    loading, empty, data and error states, in both themes. No horizontal scrolling at
    375 × 667: the grid is 2 × 2 at 375 px.
15. Playwright (mobile): a new guest finishes onboarding and Lesson 1 with all answers
    correct, opens Profile, and sees Total XP 15, Day streak 1, Longest streak 1, Lessons
    completed 1 and "Joined <current month year>".

## Out of scope
- Editing the name or avatar (US-PLT-11, P2: PLT-024, v1.0.0, PD-026)
- Preset avatar artwork
- The settings screen (PLT-017) and the guest card's content (PLT-013)
- Achievements, XP history charts, friends (Phase 2)

## UX notes
- **Layout (top to bottom):** header (avatar 64 px, name, "Guest" label, gear top-right),
  guest card slot, 2 × 2 stats grid (`Card` tiles: icon, big number, label), join date,
  bottom navigation. Streak tile uses the streak flame icon from GAM-007, and XP uses
  `XpBadge`'s icon, so the visuals match Learn.
- **Loading:** skeletons for the avatar, the name and the four tiles.
- **Empty:** zeros plus the encouraging line and link (criterion 8).
- **Error:** inline error card with a retry. Never a blank page.
- **Success:** values shown. No animation needed (respect reduced motion if any is
  added).

## Parallel work
Needs no auth, so it can be built in wave 1 alongside PLT-010 (different folders:
`src/features/profile`, `src/app/(tabs)/profile`, onboarding and gate call sites).
Start after PLT-009 merges, because PLT-009 also touches the settings read on Learn.
PLT-017 depends on the query hooks from this ticket.
