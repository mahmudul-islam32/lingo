# LES-002: Lesson player: flow, progress bar, quit dialog, re-queue
**Owner:** dev-lessons · **Priority:** P0 · **Depends on:** CTO-002, CTO-004, LES-001 · **Milestone:** v0.2.0

## User story
As a learner, I want to move through a lesson one exercise at a time with a progress bar,
retry my mistakes before finishing, and confirm before quitting so that I always know
where I am and don't lose progress by accident (US-LES-02, US-LES-10, US-LES-12,
US-LES-14).

## Acceptance criteria
1. Given a `Lesson` (contracts type), the player shows its exercises one at a time in
   content order, using the exercise component for each `type` (LES-004..LES-007).
2. **Header:** a close button (`aria-label="Quit lesson"`) and a progress bar (CTO-004
   ProgressBar) with `aria-valuemin=0`, `aria-valuemax` = number of counted exercises and
   `aria-valuenow` = exercises answered correctly so far. A hearts slot is reserved but
   empty (filled by LES-009, v0.3.0).
3. **Action bar:** a full-width "Check" button, disabled until the current exercise reports
   that an answer is ready. Pressing Enter triggers "Check" when it is enabled.
4. "Check" calls `checkAnswer` (LES-001), shows the feedback panel (LES-003; until it is
   merged, a minimal inline "Correct" / "Incorrect" text is acceptable), and the button
   becomes "Continue".
5. **Re-queue (PD-012):** an exercise answered wrong is added again at the end of the
   queue. The progress bar advances only on a correct answer. A re-queued exercise comes
   back until it is answered correctly.
6. The lesson ends when every counted exercise has been answered correctly once.
7. **Match pairs** finish by themselves when all pairs are matched (no "Check"), then show
   "Continue". They are never re-queued.
8. **Skipped exercises:** an exercise that reports "skipped" (for example LES-007 when audio
   is unavailable) moves on without being re-queued and is not counted in the total or in
   accuracy.
9. **Unsupported types:** an exercise type the player doesn't support yet (for example
   `speak` before LES-011) is left out silently and not counted.
10. **Quit:** the close button and the Escape key open a confirm dialog (CTO-004 Modal):
    title "Quit this lesson?", body "Your progress in this lesson won't be saved.", buttons
    "Keep learning" (focused by default) and "Quit". "Quit" goes to Learn (`/`); "Keep
    learning" closes the dialog and returns focus to the close button.
11. At the end, the player produces a session summary with: lesson id, start and end
    timestamps, counted exercise total, first-try correct count, mistake count, skipped
    count, and per-exercise attempts. It is passed to the results screen (LES-008) and can
    be mapped to the contracts `LessonResult`.
12. Time is measured from the moment the first exercise is shown until the last
    "Continue".
13. On each new exercise, focus moves to the exercise's prompt heading, and screen readers
    hear "Exercise N of M" (where N counts correct answers + 1).
14. **Loading state:** a skeleton (progress bar + card) with `role="status"` "Loading
    lesson".
15. **Error state:** if the lesson can't be loaded, or has 0 counted exercises, show "We
    couldn't load this lesson." with "Try again" and "Back to Learn".
16. At 375 × 667: the action button is pinned to the bottom, at least 48 px tall, and the
    exercise area scrolls above it without being covered.
17. With `prefers-reduced-motion: reduce`, exercises change without slide animations;
    otherwise transitions are at most 300 ms.
18. The queue logic is a pure reducer with unit tests: all correct; one wrong then correct;
    same exercise wrong twice; match pairs with mismatches; skipped exercise; unsupported
    type; quit.
19. The exercise-component props interface (exercise data, disabled flag, "answer ready" /
    "answer" / "skipped" / "complete" callbacks) is exported from the lessons feature so
    LES-004..LES-007 can be built in parallel.

## Out of scope
- Hearts display and "out of hearts" ending (LES-009, v0.3.0)
- Saving progress in an unfinished lesson (non-goal, PRD §6.1)
- Lesson tip card (LES-013)
- Sound effects (LES-012)
- The lesson route itself (PLT-007)

## UX notes
- **Layout (top to bottom):** header (close, progress bar, hearts slot) → exercise area →
  fixed action bar.
- **Loading:** skeleton, no spinner flash under 200 ms.
- **Error:** Lumi "ember" pose, message and two buttons.
- **Normal:** "Check" uses the primary amber button; disabled state is visually distinct
  and has `aria-disabled`.
- **Success:** after the last correct "Continue", go straight to the results screen.
- **Empty:** a lesson with no counted exercises is treated as the error state.

### Exercise component props (the interface LES-004..007 build against)

Put this in `src/features/lessons/exercises/types.ts` and export it from
`src/features/lessons/index.ts`. LES-004..007 may copy this file verbatim into their
branch if LES-002 isn't merged yet (identical content merges cleanly).

```ts
import type {
  AnswerCheckResult,
  AnswerInputOfType,
  ExerciseOfType,
  ExerciseType,
  LanguageCode,
} from "@/contracts";

/** Why an exercise could not be played. The player moves on; it is not counted. */
export type ExerciseSkipReason = "audio_unavailable" | "invalid_content";

export interface ExerciseComponentProps<T extends ExerciseType = ExerciseType> {
  /** The exercise to show (already narrowed by `type`). */
  exercise: ExerciseOfType<T>;
  /**
   * Changes every time the exercise is presented (first time and each re-queue).
   * The player also uses it as the React `key`, so each presentation mounts fresh:
   * reshuffle options/tiles and reset local state on mount.
   */
  presentationKey: string;
  /** Course languages, for `lang` attributes and speech synthesis (`es`, `en`). */
  learningLanguage: LanguageCode;
  knownLanguage: LanguageCode;
  /**
   * id for the exercise's prompt heading. Render it on an `<h2 id={headingId} tabIndex={-1}>`;
   * the player moves focus there on each new exercise (criterion 13).
   */
  headingId: string;
  /** True once the answer was checked (or the exercise completed): inputs are locked. */
  disabled: boolean;
  /**
   * Result of "Check", or null before. Lets the component mark correct/incorrect
   * choices (LES-004 criterion 8). Always null for match pairs.
   */
  review: AnswerCheckResult | null;
  /**
   * "Answer ready" + "answer": call with the current answer whenever it changes, or
   * with null when no answer is ready. "Check" is enabled iff the last value is non-null.
   * Not used by self-completing exercises (match pairs).
   */
  onAnswerChange: (answer: AnswerInputOfType<T> | null) => void;
  /** "Skipped": the exercise can't be played; the player moves on without re-queueing. */
  onSkip: (reason: ExerciseSkipReason) => void;
  /**
   * "Complete": only for self-completing exercises (match pairs). Called once, when
   * every pair is matched, with the final answer incl. `mismatchCount` (CR-001). The
   * player runs `checkAnswer` on it; the result's `mistake` drives PD-012 scoring.
   */
  onComplete: (answer: AnswerInputOfType<T>) => void;
}

/** Registry: one component per supported type; a missing entry = unsupported (criterion 9). */
export type ExerciseComponentMap = {
  [T in ExerciseType]?: React.ComponentType<ExerciseComponentProps<T>>;
};
```

Component files: `src/features/lessons/exercises/{multiple-choice,word-bank-translate,match-pairs,listen}/…Exercise.tsx`,
each exporting e.g. `MultipleChoiceExercise: React.ComponentType<ExerciseComponentProps<"multiple_choice">>`.
The registry `src/features/lessons/exercises/registry.ts` is owned by LES-002; each exercise
ticket adds its own line (one-line merge conflicts only). Components keep their own UI state;
they never call `checkAnswer` and never read stores.

Keyboard contract: components call `event.preventDefault()` on any key they handle
(Enter/Space on a tile, arrows, digits, Backspace). The player's global Enter handler
(criterion 3) ignores events with `defaultPrevented` and events whose target is a
`button`, `input` or `[role=radio]` inside the exercise area.

### Player

- **Contracts:** `Lesson`, `Exercise`, `ExerciseType`, `LessonSession` / `LessonSessionSchema`, `LessonSessionStatus`, `ExerciseAttempt`, `AnswerInput`, `AnswerCheckResult`, `CheckAnswer` (LES-001's `checkAnswer`), `LanguageCode`, `Slug`, `IsoDateTime`, `UuidSchema`.
- **Files:** `src/features/lessons/player/session-reducer.ts` (pure reducer + `createSession`), `src/features/lessons/player/session-store.ts` (Zustand store wrapping the reducer; add `zustand` with an exact version), `src/features/lessons/player/LessonPlayer.tsx`, `PlayerHeader.tsx`, `ActionBar.tsx`, `QuitDialog.tsx`, `PlayerSkeleton.tsx`, `PlayerError.tsx`, `src/features/lessons/player/summary.ts`.
- **Public API (`src/features/lessons/index.ts`):**
  ```ts
  export interface LessonPlayerProps {
    lesson: Lesson;
    learningLanguage: LanguageCode;
    knownLanguage: LanguageCode;
    /** Called once after the last "Continue". */
    onFinish: (summary: LessonSessionSummary) => void;
    /** Called after a confirmed quit; the route navigates to "/". */
    onQuit: () => void;
  }
  export interface LessonSessionSummary {
    session: LessonSession;            // status "completed", full attempts list
    startedAt: IsoDateTime;            // first exercise shown (criterion 12)
    completedAt: IsoDateTime;          // last "Continue"
    exerciseCount: number;             // counted = presented − skipped − hidden
    firstTryCorrectCount: number;
    mistakeCount: number;
    skippedCount: number;
  }
  /** Pure mapping used by LES-008: summary + XP → contracts LessonResult. */
  export function buildLessonResult(summary: LessonSessionSummary, input: { id: Uuid; xp: XpBreakdown; timeZone: string; localDate: LocalDate }): LessonResult;
  ```
  `LessonPlayer` is a client component; PLT-007 renders it in `/lesson/[lessonId]` with loading/error handled by the route **or** by passing `lesson` only when loaded. To satisfy criteria 14–15 inside this ticket, also export `LessonPlayerSkeleton` and `LessonPlayerError({ onRetry, onBack })`.
- **Session rules (reducer, time injected):**
  - `createSession({ lesson, supportedTypes, hiddenIds, now, sessionId })`: `queue` = exercise ids in content order minus hidden/unsupported ones (put them in `hiddenExerciseIds`). `heartsAtStart = heartsRemaining = GAME_CONFIG.maxHearts` until LES-009.
  - `check(answer, result, now)`: append an `ExerciseAttempt` copying `outcome`, `mistake` and `heartCost` from the `AnswerCheckResult` (`isRetry` = this id already has an attempt). Incorrect → move `queue[0]` to the end. Correct → pop on "Continue".
  - Match pairs (CR-001): `onComplete(answer)` → the player calls `checkAnswer` with that answer (it carries `mismatchCount`) and dispatches the same `check` action. The result is `correct`, with `mistake: true` and `heartCost: 1` when `mismatchCount > 0`; it is never re-queued (outcome stays `correct`). Hearts are only deducted from v0.3.0 (LES-009).
  - `skip(reason, now)`: append an attempt with `outcome: "skipped"`, `mistake: false`, `heartCost: 0` and an empty answer of the exercise type (`{ type: "listen", tiles: [] }`), pop without re-queue; it counts in `skippedCount` and not in the progress max.
  - `quit` → `status: "quit"`; empty queue → `status: "completed"`.
  - Derived: `exerciseCount` = distinct non-hidden ids; `mistakeCount` = attempts with `mistake === true`; `firstTryCorrectCount` = ids whose first attempt is `correct` with `mistake === false`; `perfect = mistakeCount === 0 && exerciseCount − skippedCount ≥ 1`. Progress: `aria-valuenow` = correct ids, `aria-valuemax` = `exerciseCount − skippedCount`.
- **UI (CTO-004):** `ProgressBar` (`value`, `max`, `label="Lesson progress"`, `valueText="Exercise N of M"`), `IconButton` (`label="Quit lesson"`, `ref` kept for focus return), `Dialog` (`initialFocusRef` = "Keep learning", `onClose`, Esc built in; returns focus to the opener), `Button` (`variant="primary" size="lg" fullWidth`), `Skeleton`, `VisuallyHidden` + a polite live region for "Exercise N of M". Lumi "ember" from GAM-001 in the error state (placeholder if not merged).
- **Layout:** `h-dvh flex flex-col`; exercise area `flex-1 overflow-y-auto`; action bar `sticky bottom-0 pb-[env(safe-area-inset-bottom)]`. Transitions: CSS `motion-safe:` classes (≤ 300 ms), or Framer Motion `LazyMotion` + `useReducedMotion()` if you need exit animations.
- **Edge cases:** global Escape opens the quit dialog only when no dialog is open; `presentationKey = ${exerciseId}:${attemptIndex}`; lesson with 0 counted exercises → error state (criterion 15); never call `Date.now()` in the reducer.
- **Tests:** `session-reducer.test.ts` for every case in criterion 18 plus summary numbers (mistakes, first-try, skipped, perfect). `LessonPlayer.test.tsx` with a schema-valid fixture lesson and stub exercise components injected through a `components` prop (default = the registry): Check disabled until `onAnswerChange(answer)`, Enter triggers Check, re-queue order, quit dialog focus and Escape, `onFinish` called once with the summary.

Notes / decisions:
- **Out of hearts:** prepared for LES-009 but off by default. With the optional `hearts`
  prop (`{ initial, onLose, onOutOfHearts }`), the reducer counts down `heartsRemaining`,
  calls `onLose(cost)` right after Check (the caller persists it via gamification/data
  layer), and ends as `out_of_hearts` on the next Continue (it wins over `completed`). No
  result is produced.
- `summary.exerciseCount` includes skipped exercises, like `LessonResult.exerciseCount`;
  the counted total is `exerciseCount − skippedCount`.
- CR-003 is open: there's no empty multiple-choice answer for skipped attempts, and
  `perfect` vs PD-012 conflict when everything is skipped. Workarounds are documented
  there.
  - _(cto, 2026-11-07)_ CR-003 approved and done: skipped attempts record `answer: null`
    and `LessonResult.perfect` follows PD-012; both workarounds were removed in
    `chore/cr-003-skipped-attempts-perfect`.
