# CTO-016: Design system v2 (tokens, fonts, shared components, design references)
**Owner:** cto · **Priority:** P1 · **Depends on:** — · **Milestone:** v0.5.3 Redesign ·
**Decisions:** PD-001, PD-066

## User story
As a learner, I want every Polyglow screen to share one clear, consistent look so that the
app feels polished and easy to read; as a developer, I want shared tokens and components so
that PLT-026, GAM-012 and LES-021 can restyle their screens without redefining styles.

## Acceptance criteria
Reference: `/home/user/design-ref/BRIEF.md` (token list) and screens 1–8. **No behaviour
change; existing tests keep passing.**

### References
1. `docs/design/v2/` contains the brief (`BRIEF.md`), `screen-1.png` … `screen-8.png` and
   `screen-1.html` … `screen-8.html`, with a short README mapping each screen to the ticket
   that implements it (1, 8 → PLT-026; 2, 7 + Practice → GAM-012; 3–6 → LES-021). The brief's
   "parla" name and logo are marked "not used" (PD-066 §8).

### Tokens and theme
2. Tailwind theme tokens exist for every colour in the brief (indigo, coral, ink / muted /
   subtle / slate, canvas / surface / border / strong border, XP gold, success, error,
   hearts), with names documented in an ADR or `docs/design/v2/README.md`.
3. Radii tokens: 16 px for cards and buttons, 8–12 px for chips, full for nodes and avatars.
4. Shadow tokens are solid with no blur: card `0 3px 0 #E3E5EE`, primary button
   `0 4px 0 #312E81`, node `0 6px 0 #312E81`, locked node `0 6px 0 #CDD0DD`.
5. The app uses the light theme only: app background is canvas `#F6F7FB`; the dark theme and
   any theme toggle are removed (PD-066 §1); no screen renders dark styles when the OS is in
   dark mode.
6. Fonts: Bricolage Grotesque (700, 800) and DM Sans (400, 500, 700) are loaded via
   `next/font/google` (self-hosted at build, no request to Google Fonts at runtime, checked in
   the built output / network panel); headings and numbers use Bricolage, body and UI use DM
   Sans.

### Shared components (`/src/components/ui/**`)
7. **Button** with variants primary (indigo, 3D edge), secondary (white, border), danger
   (red), success (green) and ghost/link; pressed state moves down 2 px with a smaller shadow;
   disabled state is grey with no 3D edge (screen 3 Check bar). Existing Button props and
   call sites keep working.
8. **Card** (white, 16 px radius, card border + shadow; optional selected state with indigo
   2 px ring and check icon, screen 1).
9. **ProgressBar** (indigo fill on light track, rounded; exposes `role="progressbar"` with
   value attributes, screen 3).
10. **StatTile** in two layouts: icon + value + label (screen 8), and coloured header + value
    (gold / indigo / green, screen 6).
11. **Chip** (small rounded label, e.g. course "DE" chip on screen 2, eyebrows).
12. **OptionCard** (selectable card with optional number badge or code badge, used by
    onboarding options and MC 2 × 2 cards, screens 1 and 3); supports `radio` semantics.
13. Each new or changed component has a unit test and a short usage note (story file or
    README); changed existing components are listed in the PR description (CLAUDE.md).

### Quality
14. All token text / background pairs used by the components meet WCAG AA (4.5:1 body,
    3:1 large text and UI parts); pairs that fail (e.g. white on coral `#F2613F` at body size)
    are documented with the allowed use (large/bold text or icon only) and a passing
    alternative.
15. Components render without horizontal scroll at 375 px, have tap targets of at least
    48 px, a visible focus ring (indigo, not colour-only), and are operable with keyboard
    (Tab, Enter / Space).
16. `npm run typecheck`, `lint`, `test`, `build` and the existing e2e suite pass.

## Out of scope
- Restyling feature screens (PLT-026, GAM-012, LES-021)
- A dark v2 palette (later, PD-066)
- New illustrations beyond existing Lumi assets

## UX notes
- Eyebrows: 12–13 px, uppercase, letter-spaced, DM Sans 700.
- Headings 22–36 px Bricolage 800; body 14–16 px DM Sans.
- **States:** components expose disabled, loading (Button shows spinner and keeps width),
  selected and error (red border + icon + text) states; none rely on colour alone.
