# FIX-015: The review error state says "Back", not "Back to Learn"
**Owner:** dev-lessons (criteria 1–3, 5) · dev-platform (criterion 4, one line in
`src/app/review/ReviewScreen.tsx`) · **Priority:** P2 · **Depends on:** LES-023, PLT-029 ·
**Milestone:** next after v0.5.5 (not blocking v0.5.5, PD-083) · **Source:** PM-ACC6,
PLT-029 AC 10 FAIL

## User story
As a learner whose review couldn't load, I want the button to say where it takes me so that
I'm not surprised to land on Practice when it promised Learn.

## Background
`LessonPlayerError` (`src/features/lessons/player/PlayerError.tsx`) always shows "Back to
Learn". On `/review` its `onBack` goes to `/practice` (PLT-029 AC 10 asks for "Back"). The
same happens in `ReviewPlayer`'s own error state (no playable item), whose `onQuit` also goes
to Practice. The RTL test matches `/^Back/`, so it didn't catch the label.

## Acceptance criteria
1. `LessonPlayerError` accepts an optional back-button label. Without it, the button still
   reads "Back to Learn" (the lesson route is unchanged; existing tests pass unchanged).
2. `ReviewPlayer`'s error state (no playable item) shows "Back"; activating it calls
   `onQuit` once.
3. The button's accessible name equals its visible text in both cases (WCAG 2.5.3).
4. `/review`'s error state (failed queue read, or every candidate lesson failing to load)
   shows "Back", which goes to `/practice`. The PLT-029 RTL test asserts the exact name
   `"Back"` instead of `/^Back/`.
5. RTL: the lesson route's error state still shows "Back to Learn"; no serious or critical
   axe violations in either state; `npm run typecheck`, `lint`, `test`, `build` pass.

## Out of scope
- The heading "We couldn't load this lesson." on `/review` (PLT-029 AC 10 asked for the lesson
  error state as is; wording goes to the microcopy review CON-003)
- Any other change to the error, empty or results states

## UX notes
- **Error state on `/review`:** Lumi (ember), heading, "Try again" (primary), "Back"
  (secondary, to Practice).
- **Error state on `/lesson/<id>`:** unchanged ("Back to Learn", to Learn).
- Mobile 375 px and buttons ≥ 48 px as today (`Button size="lg"`).
