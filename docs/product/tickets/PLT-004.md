# PLT-004: Onboarding: choose course and daily goal
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-001, PLT-003, GAM-001 (soft: use a placeholder image if not merged) · **Milestone:** v0.1.0

## User story
As a new visitor, I want to pick the language I want to learn and a daily goal so that I
get the right course and my habit target is set from the start (US-PLT-02, US-PLT-03).

## Acceptance criteria
1. `/onboarding` has three steps on one route: **Welcome**, **Course**, **Daily goal**. A
   text indicator shows "Step N of 3" on steps 2 and 3.
2. **Welcome:** shows Lumi (happy pose), the heading "Learn Spanish in five minutes a day"
   and one primary button "Get started". There is no "I already have an account" link yet
   (PD-011; added in PLT-018).
3. **Course:** lists the courses from the course data (one in MVP: "Spanish", subtitle
   "for English speakers") and a non-interactive line "More languages coming soon".
   "Continue" is disabled until a course is selected.
4. **Daily goal:** shows the goal options from contracts/config, by default 4 options:
   Casual 10 XP, Regular 20 XP, Serious 30 XP, Intense 50 XP, each with a hint
   ("About 1 lesson a day", "About 2 lessons a day", "About 3 lessons a day", "About 5
   lessons a day"). No option is preselected. The final button "Start learning" is disabled
   until one is chosen.
5. Course and goal options are radio groups (`role="radiogroup"` with an accessible name).
   Arrow keys move the selection; the selected option shows a check icon, not only a
   colour change.
6. Steps 2 and 3 have a "Back" button (`aria-label="Back"`) that returns to the previous
   step and keeps that step's selection.
7. On each step change, focus moves to the new step's `<h1>`.
8. "Start learning" saves the course and daily goal to the guest profile (PLT-003), sets
   onboarding complete, and navigates to `/`. (PLT-007 changes the target to Lesson 1.)
9. **Redirects:** while onboarding is not complete, opening `/` or `/profile` redirects to
   `/onboarding`. Once complete, opening `/onboarding` redirects to `/`.
10. Reloading during onboarding returns to the Welcome step with nothing saved.
11. **Error state:** if saving fails, an inline message "We couldn't save your choices.
    Please try again." appears with `role="alert"`, the learner stays on step 3 and the
    selection is kept.
12. **Empty state:** if no courses are available, the Course step shows "No courses are
    available right now." and a "Try again" button.
13. At 375 × 667, every option of the current step is visible without horizontal
    scrolling, options are at least 48 px tall, and the primary button is pinned to the
    bottom of the screen.
14. No serious or critical axe violations on any step.
15. A Playwright test (mobile project) completes onboarding as a new visitor with the
    keyboard only, lands on `/`, reloads, and stays on `/`.

## Out of scope
- Account creation or log-in during onboarding (v0.4.0)
- Placement test / "I know some Spanish" (Phase 2)
- Choosing a display name or avatar (PLT-016)
- Reminder time picker (Phase 2, with push reminders)

## UX notes
- **Welcome:** Lumi centred, large heading, short body "Short lessons, real progress.", one
  amber primary button at the bottom.
- **Course step:** one card per course with a flag-free label (we use language names, not
  flags). Selected card: indigo border plus check icon.
- **Daily goal step:** four stacked option rows; label left, XP right, hint below the label.
- **Loading:** skeleton cards while course data loads.
- **Error:** inline alert above the button; button stays enabled for retry.
- **Success:** goes straight to the next screen, no toast.
- Reduced motion: step changes without slide animation.

**Owner agent:** dev-platform · **Branch:** `feature/plt-004-onboarding`

- **Contracts (`@/contracts`):** `GAME_CONFIG.dailyGoalOptions` / `DAILY_GOAL_OPTIONS`, `DailyGoalXp`, `Settings`, `ProfileUpdate`, `Course` (title + languages for the course card). The labels/hints (Casual … Intense, "About N lessons a day") are UI copy: a `Record<DailyGoalXp, { label: string; hint: string }>` in `src/app/onboarding/goal-options.ts`, typed so that a new option in contracts fails typecheck.
- **Files (dev-platform):** `src/app/onboarding/page.tsx` (client step machine with `useState`, no persistence until the last step), `src/app/onboarding/steps/{Welcome,CourseStep,GoalStep}.tsx`, `src/app/_shell/OnboardingGate.tsx` (redirect logic), shared `src/app/_shell/RadioCardGroup.tsx` (roving tabindex radiogroup, reused by both steps).
- **Data:** course list from `ContentRepository.getCourse(DEFAULT_COURSE_ID)` (PLT-007 implements `src/lib/content`; until then a `getCourses()` stub in `src/lib/content/index.ts` returning the fixture manifest is fine). Saving = `ProfileRepository.saveSettings({ ...current, courseId, dailyGoalXp, updatedAt: now })` then `updateProfile({ ..., onboardedAt: now, updatedAt: now })`, through a TanStack Query mutation that invalidates `["settings"]` and `["profile"]`. If `@tanstack/react-query` isn't installed yet, this ticket adds it and the `QueryClientProvider` in `src/app/providers.tsx` (`networkMode: "always"`).
- **Redirects:** client-side in `OnboardingGate` (in the `(tabs)` layout and in the onboarding page), based on `profile.onboardedAt`. Render the PLT-001 loading UI until the profile query resolves, so a returning learner never sees a flash of onboarding. Use `router.replace`, not `push`.
- **UI (CTO-004):** `Button` (`variant="primary" size="lg" fullWidth`), `Card`, `IconButton` (Back), `Skeleton` for course loading; check icon from `@/components/ui` (`CheckIcon`). Lumi from GAM-001 (`<Lumi pose="happy" size="lg" />`); if GAM-001 isn't merged, a `Skeleton shape="circle"` placeholder.
- **Edge cases:** Back keeps selections (state lives in the page, not the step); focus `<h1>` with `tabIndex={-1}` + `ref.focus()` in an effect on step change; saving error keeps step 3 and the selection, `role="alert"`.
- **Tests:** RTL: radiogroup keyboard (arrows move + select), disabled buttons until selection, Back keeps selection, save error shows alert (repository mocked). Playwright `tests/e2e/onboarding.spec.ts` keyboard-only (criterion 15) + axe on each step.

## Implementation notes
_(dev-platform, 2026-11-07, branch `feature/plt-004-onboarding`, rebased on main after PLT-001 #20, GAM-001 #19, CTO-005 #22)_

1. `src/app/onboarding/OnboardingFlow.tsx` is a client step machine (`welcome` / `course` / `goal`) on the single `/onboarding` route. `steps/StepLayout.tsx` shows "Step N of 3" on steps 2 and 3 only.
2. `steps/Welcome.tsx`: `<Lumi pose="happy" size="lg" />` from `@/components/ui` (GAM-001), the heading "Learn Spanish in five minutes a day", the body "Short lessons, real progress." and one primary `Button` "Get started". There is no log-in link (PD-011). RTL asserts exactly one button and no links.
3. `steps/CourseStep.tsx`: one card per course from `courses.ts` (`loadCourses()` dynamically imports `content/courses/en-es/course.json` and validates it with `CourseSchema`; this is a stub until PLT-007's `src/lib/content`). The card shows "Spanish" with the subtitle "for English speakers", derived from `knownLanguage` via `Intl.DisplayNames`. "More languages coming soon" is plain text outside the radiogroup. "Continue" stays disabled until a course is selected.
4. `steps/GoalStep.tsx` + `goal-options.ts`: the options come from `GAME_CONFIG.dailyGoalOptions`. The copy is a `Record<DailyGoalXp, { label; hint }>`, so a new contract option fails typecheck. The accessible names are "Casual 10 XP" … "Intense 50 XP", with the hints as descriptions. Nothing is preselected, and "Start learning" is disabled until the learner picks a goal.
5. `src/app/_shell/RadioCardGroup.tsx` (shared by both steps): `role="radiogroup"` named by the step `<h1>` (`aria-labelledby`), `role="radio"` + `aria-checked`, roving tabindex. Arrow keys (with wrap-around) and Home/End move focus and selection, and Space/Enter select. The selected card has an indigo `border-night-400` and a check icon (`CheckIcon`).
6. `IconButton label="Back"` on steps 2 and 3. Selections live in the flow's state, not in the steps, so Back keeps them (RTL).
7. The `<h1>` has `tabIndex={-1}`, and an effect focuses it on every step change but not on the first render (RTL + e2e).
8. "Start learning" calls `guestProfileStore.updateSettings({ courseId, dailyGoalXp })`, then `completeOnboarding()`, then `router.replace("/")`. The RTL test uses the real in-memory `@/lib/offline` session and checks the stored settings and `onboardedAt`. This goes through the PLT-003 Zustand store, not TanStack Query, because Query isn't installed yet (ARCHITECTURE §5 temporary deviation). Moving to a Query mutation is a follow-up.
9. `src/app/_shell/OnboardingGate.tsx`: `require="onboarded"` in `(tabs)/layout.tsx` and `require="not-onboarded"` in `onboarding/page.tsx`. It shows the PLT-001 `LoadingState` until the profile is ready, then uses `router.replace`. If the profile can't load, it shows `ErrorState` with a retry. Covered by RTL and e2e (`/` and `/profile` → `/onboarding`, `/onboarding` → `/` once onboarded).
10. Nothing is written before the last step. A reload restarts at Welcome (RTL checks that storage is empty, e2e reloads).
11. If saving fails, `<p role="alert">` "We couldn't save your choices. Please try again." appears above the button. The learner stays on step 3 with the selection kept, and the button stays enabled for a retry (RTL for both `updateSettings` and `completeOnboarding` failures).
12. With no courses, or if the course load fails, the step shows "No courses are available right now." and a "Try again" button that reloads (RTL). While loading, skeletons appear in a `role="status"` region named "Loading courses".
13. The footer is `sticky bottom-0` with safe-area padding, and options are `min-h-14` (56 px). `tests/e2e/onboarding.spec.ts` checks at 375 × 667 that there is no horizontal scroll, that every option is fully in view and at least 48 px tall, and that the primary button sits at the bottom.
14. axe (serious/critical) runs on every step, after the fade-in finishes.
15. `tests/e2e/onboarding.spec.ts`: the visitor completes onboarding with the keyboard only (Tab, Space, Arrow, Enter), lands on `/`, reloads and stays on `/`.

Also: `tests/e2e/shell.spec.ts` and `smoke.spec.ts` now finish onboarding first (`onboarding-helpers.ts`), because the tabs redirect until onboarding is done. The step change uses `motion-safe:animate-fade-in`, so reduced motion gets no animation. Verified locally with `next start` plus system Chrome: all 44 e2e tests pass on both projects.
