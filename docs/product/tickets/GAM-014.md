# GAM-014: `useGoalPlan` reads the plan of its course (per-course goal plans)
**Owner:** dev-gamification · **Priority:** P1 · **Depends on:** CTO-018, GAM-013 ·
**Milestone:** v0.5.5 (per-course goal plan, before v0.6.0 sync) · **Decisions:** PD-077,
PD-078

## User story
As a learner who switches between courses, I want each course's Learn card to show that
course's own goal date so that a plan for one course never changes the numbers of the other
(US-GD-05).

## Acceptance criteria
Field names follow CTO-018 and its ADR (proposal: `Settings.goalPlans: Record<Slug,
GoalPlan>`). Fixtures: the real `en-de` (A1 60, A2 70 lessons) and `telc-b1-en-de` courses,
or fixtures of the same shape.

1. `useGoalPlan({ courseId })` passes **that course's** plan to `computeGoalPlan` (CTO-018
   criterion 5); without `courseId` it uses the active course, as today. The return values
   are unchanged: `undefined` while loading, `null` for no plan / no levels / read error,
   else the status.
2. **Isolation:** with plan "A2 by 2027-03-12" on `en-de` and none on `telc-b1-en-de`,
   `useGoalPlan({ courseId: "en-de" })` returns that plan's status and
   `useGoalPlan({ courseId: "telc-b1-en-de" })` returns `null`. With plans on both, each
   hook returns its own course's target and counts (RTL / hook tests).
3. **Migrated data:** a settings record with only the old single `goalPlan` (CTO-018
   criterion 3) gives the plan to the course that record names as active and `null` to the
   others.
4. The hook updates without a reload after one course's plan is set, changed or cleared,
   and after a lesson result of that course is saved; a change on another course doesn't
   change its value (test with query invalidation).
5. Any gamification helper that reads `settings.goalPlan` directly (rules, copy, exports)
   reads the per-course plan instead; a grep in the PR description shows no remaining reader
   of the old field outside the contract's migration.
6. `GoalPlanCard`, the rule's statuses and the copy are unchanged; GAM-013's tests pass
   unchanged apart from fixtures moved to the new settings shape.
7. Read errors behave as in GAM-013 criterion 8 (logged, `null`, no banner). The plan is read
   with CTO-018's selector (criterion 11, e.g. `goalPlanFor(settings, courseId)`), never by
   reading the settings fields directly.

## Out of scope
- Profile row and dialog, Learn mount, results wiring and the e2e (PLT-028)
- Excluding review results from the completed-lesson count (GAM-015 criterion 7)
- A date-only goal for courses without levels (PD-078 §5)
- Showing other courses' plans anywhere

## UX notes
No visible change for a learner on one course. A learner on two courses sees each course's
own card on Learn, or the "Set a goal date" link when that course has no plan; courses
without levels show nothing (FIX-014). Mobile 375 px and accessibility: unchanged from
GAM-013 (criteria 15, 16 still hold; its tests keep running).
