# GAM-011: Start level on the path, "Start here", gainHearts rule and hook, 0-hearts gate for practice
**Owner:** dev-gamification · **Priority:** P1 · **Depends on:** CTO-015 (contract, ADR-013),
GAM-002, GAM-005, GAM-008 · **Milestone:** v0.5.2 · **Decisions:** PD-012, PD-018, PD-064,
PD-065

## User story
As a learner who already knows A1, I want the path to start at my chosen level, with a
"Start here" option on locked levels and the earlier lessons still open, and as a learner
with no hearts, I want to earn hearts back by answering correctly and to replay finished
lessons at 0 hearts, so that I neither redo what I know nor wait hours for a refill
(US-SL-02, US-SL-04, US-HE-01, US-HE-02, US-HE-03).

## Acceptance criteria
Names of types, fields and functions follow ADR-013 / CTO-015 where they differ from the
wording below; the behaviour is what is tested.

### Path rule (start level)
1. `computePathNodes` takes the start level as defined by CTO-015. With no start level, or a
   start level that is not a level of the course with content, its output is identical to
   today's for the same results (existing GAM-008 rule tests pass unchanged).
2. With start level A2: every not-completed A1 lesson is **playable** (not `locked`, not
   `completed`, not "up next"); A1 lessons with a result are `completed`; the first
   not-completed A2 lesson is the one `available` ("up next") node; every later lesson is
   `locked`.
3. If every lesson of the start level is completed, the first not-completed lesson after it
   is up next (normal rule).
4. **Lowering:** with A2 L1–L2 completed and the start level changed from A2 to A1, A1 L1 is
   up next, all other not-completed A1 lessons and A2 L3 onward are `locked`, and A2 L1–L2
   stay `completed`.
5. No result, XP event or lesson count is created or changed by the start level (unit test:
   `totalXp` and `lessonsCompletedCount` equal for start level A1 and A2 with the same
   results).
6. Rule tests cover criteria 1–5, a start level equal to the first level, an unknown level,
   and results in a skipped level; 100 % branch coverage of the changed rule.

### Path screen
7. A playable earlier-level node shows an open-lock icon and the text "Open" (not
   "Completed", "Start" or "Up next") and has the accessible name "Lesson N: <title>, open".
   Activating it with tap, Enter or Space opens `/lesson/<lessonId>`.
8. Each **locked level header** (a level whose lessons are all `locked`) shows a secondary
   button "Start here" with the accessible name "Start here: <level code> <level title>"
   (e.g. "Start here: A2 Elementary"). Level headers that are not locked show no button.
9. Activating "Start here" saves the start level (the setter from ADR-013), and without a
   reload the path shows that level's first not-completed lesson as up next, scrolls to it
   (no animation under `prefers-reduced-motion`), moves focus to it, and announces
   "Starting at <level code> <level title>." in a polite live region.
10. If saving the start level fails, the path doesn't change and shows the toast "We couldn't
    change your start level. Try again."

### Earning hearts
11. A pure function `gainHearts` (in `src/features/gamification/rules/`, exported from
    `@/features/gamification`) adds 1 heart per call up to the maximum of 5. At 5 it returns
    the state unchanged. It never changes the next refill time while hearts stay below 5;
    at 5 the refill timer stops as in GAM-002.
12. A hook `useGainHearts` (mirror of `useLoseHearts`, GAM-005) persists a gain in the same
    store, works for guests and offline, updates `useHearts()` and the Learn top bar without
    a reload, and logs a failed save without throwing.
13. The 4-hour refill still works after gains: unit test with 2 hearts, one gain (3), then
    the next refill time passes → 4.
14. Rule and hook tests cover 0 → 1, 4 → 5, 5 → 5, gain then refill, gain then loss, and a
    save failure.

### 0-hearts gate
15. At 0 hearts, activating a **completed** node opens `/lesson/<lessonId>` (practice,
    PD-065). Activating an up-next or open (not completed) node opens the GAM-008 dialog.
16. At 0 hearts, only not-completed playable nodes show "No hearts left"; completed nodes
    show "Practice: earns hearts" instead.
17. The GAM-008 dialog "You're out of hearts" shows the refill text and, when at least one
    lesson is completed, the line "Practise a finished lesson to earn hearts." With no
    completed lesson the line is absent. Focus returns to the node on close.
18. A pure function (name per ADR-013) answers "can this lesson start?" from hearts and node
    state: completed → yes at any hearts; available or open → yes only with at least 1
    heart; locked → no. It is exported for PLT-025 and has 100 % branch coverage.

### Quality
19. RTL tests cover criteria 7–10, 15–17, including accessible names, focus after "Start
    here", the live-region text and the dialog with and without completed lessons; no
    serious or critical axe violations on the path with a skipped level.
20. At 375 × 667 a level header with "Start here" fits on one row or wraps without
    horizontal scrolling; the button is at least 48 px tall; the "Open" and "Practice: earns
    hearts" texts are not truncated. Contrast meets AA in both themes.
21. e2e (Playwright, 375 px): with start level A2 set by test setup, A1 L1 shows "Open", A2 L1
    is up next, and "Start here" on a locked level header moves up next there, all with the
    keyboard only (Tab, Enter).

## Out of scope
- The onboarding step, the Profile setting and the lesson-route lock (PLT-025)
- Gaining hearts inside the lesson player, practice cost and the lesson out-of-hearts screen
  (LES-020)
- A placement test (Phase 2 idea, PD-064)
- Hiding or collapsing skipped levels

## UX notes
- **Skipped level:** its header looks like a normal level header; its nodes are open (no
  glow ring), so the up-next glow stays unique.
- **Locked level header:** title, "N lessons", lock icon and the "Start here" secondary
  button on the right.
- **Loading / error / empty:** unchanged from GAM-008. While the start level is being read,
  the path skeleton stays; a read error falls back to the first level (no error banner).
- **Success:** after "Start here", the new up-next node glows and has focus.
- **0 hearts:** completed nodes say "Practice: earns hearts"; others say "No hearts left".
