# PLT-014: Sync engine, push: idempotent upload of results and settings (no double XP)
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** CTO-025, PLT-010; PLT-013 for the
e2e (it needs an account identity) · **Milestone:** v0.6.0 Accounts and sync, part A (local
Supabase) · **Decisions:** PD-085, PD-087

## User story
As a learner, I want lessons I finish offline to upload by themselves when I'm back online, and
never to count twice, so that I never lose or inflate XP or streak days (US-PLT-15).

## Acceptance criteria
1. The `SyncEngine` (`src/lib/sync`, contract in `api.ts`) runs **only** for an `account`
   identity with accounts enabled. A guest device never sends a request (unit test + the PLT-010
   network e2e).
2. **Triggers:** app start, the `online` event, 2 s after the last enqueue (debounced) and every
   60 s while the page is visible, with the values from `SYNC_CONFIG`.
3. **Push order** is `createdAt` ascending. `lesson_result` → insert that ignores an existing id
   (incl. `kind` and `exerciseOutcomes`); `settings` / `profile` / `hearts` → upsert by user with
   the client `updatedAt` (the server skips stale writes). Mapping as in ADR-020; the legacy
   `goalPlan` is never sent.
4. Success or "already exists" deletes the queue record. Network error, timeout or 5xx keeps it,
   increments `attemptCount` and sets `nextAttemptAt` with the `SYNC_CONFIG` backoff. A 4xx
   validation or RLS error marks only that record `rejected` with `lastError` (max 500
   characters), never retries it and doesn't stop the others.
5. **401 / expired session:** records stay `pending` (never rejected), the engine pauses with
   status `error` and `useSession()` reports `expired`; it resumes after the next log-in.
6. **No double XP:** the same result pushed twice (retry after a lost response, two tabs) leaves
   one row; an e2e checks total XP on the server and on the device after reload equals the sum
   of distinct results.
7. **One sync at a time per device** across tabs (lock per ADR-020); a test with two engine
   instances on one store sends each record once.
8. **Offline → online:** e2e (`accounts` project): signed in, go offline (`context.setOffline`),
   finish 3 lessons, go online → within 10 s the 3 results are in `lesson_results` and the queue
   is empty.
9. `status()` is `idle | syncing | offline | error`, `subscribe()` notifies on change, and a
   `useSyncStatus()` hook exposes status, pending count and last successful push time for
   PLT-016. `syncNow()` never throws.
10. Logs contain no email, token or lesson content; rejected records are visible in dev tools.
11. Unit tests with a fake transport cover ordering, coalescing of LWW kinds, backoff, rejected
    vs. retried errors, 401 pause and criterion 7. `npm run typecheck`, `lint`, `test`, `build`
    pass.
