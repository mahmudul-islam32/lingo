# FIX-005: Lumi ember on the lesson error and audio-unavailable states (LES-009 PM note)
**Owner:** dev-lessons · **Priority:** P2 (not blocking any release) · **Depends on:** GAM-001,
LES-002, LES-007 · **Milestone:** v1.0.0 (polish; can be done any time) ·
**Branch:** `fix/fix-005-lumi-ember-states` · **Found in:** PM-ACC3 (LES-009 PM note, 2026-11-08)

## User story
As a learner who hits an error in a lesson, I want to see Lumi's calm ember pose, so that the
error screens look like the rest of Polyglow and don't feel broken.

## Problem
The PM note in LES-009 asked for two small UX-note fixes that weren't done:
- `src/features/lessons/player/PlayerError.tsx` still renders the `EmberPlaceholder` circles,
  and its comment says GAM-001 isn't merged (it is).
- The listen exercise's "Audio isn't available right now." state has no Lumi (LES-007 UX notes).

## Acceptance criteria
1. The lesson error state ("We couldn't load this lesson.") shows `<Lumi pose="ember" />` from
   `@/components/ui`. `EmberPlaceholder` and its test id are removed.
2. The listen "Audio isn't available right now." state shows `<Lumi pose="ember" size="sm" />`
   next to the message. Copy and the Skip button are unchanged (PD-007).
3. Lumi stays decorative (`aria-hidden`). The heading or message keeps its current
   accessible text and focus behaviour.
4. At 375 × 667 the error state and the listen exercise with the message still fit without
   horizontal scrolling. The listen "Check" bar isn't pushed off screen.
5. RTL tests assert the ember pose in both states. `npm run typecheck`, `lint`, `test` and
   `build` pass.

## Out of scope
- New Lumi poses or animations (Phase 2)
- Any change to the audio fallback logic (LES-014)

## UX notes
- **Error:** Lumi ember (md), heading, "Try again" and "Back to Learn".
- **Audio unavailable:** small Lumi ember beside the one-line message, Skip below.
