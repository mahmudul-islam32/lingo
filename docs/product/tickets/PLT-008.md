# PLT-008: Save lesson results on the device
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-003, PLT-007, CTO-002 · **Milestone:** v0.2.0

## User story
As a learner, I want my finished lessons to be saved on my device, even offline, so that I
never lose a lesson I completed (US-PLT-14, PRD principle "Offline is normal").

## Acceptance criteria
1. The contracts data-layer function for saving a `LessonResult` is implemented for guest
   storage (Dexie) in `/src/lib/offline`.
2. Saving is idempotent: saving a result with the same result id twice stores one record.
3. Each saved result stores the learner's device-local date (`YYYY-MM-DD`) and timezone
   offset at completion time (input for streaks in v0.3.0, PRD Q4).
4. Each saved result is marked as not yet synced, for the sync queue in v0.4.0 (PLT-014).
5. The contracts function for reading completed lesson ids (or the equivalent read
   function) is implemented, and Learn (PLT-007) shows a "Completed" label with a check
   icon on every lesson that has at least one saved result.
6. Returning from the results screen to Learn shows the new "Completed" label without a
   page reload.
7. Saved results survive a reload and are saved and read with the network offline.
8. Storage failures return a typed error to the caller (used by LES-008's error state);
   they never crash the page.
9. The Dexie schema version is increased with a migration that keeps existing guest
   profiles (PLT-003).
10. Completed lessons still show "Start again" as their action, so they can be replayed
    (US-GAM-14).
11. Unit tests (fake IndexedDB) cover: save, duplicate save, read completed ids, local date
    and offset stored, migration from the PLT-003 schema version, storage error.

## Out of scope
- XP totals, streaks, daily goal (v0.3.0)
- Uploading results to Supabase (PLT-014)
- Deleting results

## UX notes
- **Completed card:** check icon + "Completed" text next to the title; action "Start
  again". State is not conveyed by colour alone.
- **Loading:** completion labels appear with the list (no separate spinner).
- **Error:** if completed ids can't be read, the list still shows with "Start" on every
  lesson (no error banner; the learner can still learn).
- **Empty:** no completed lessons, so no labels.

## Technical notes

**Owner agent:** dev-platform · **Branch:** `feature/plt-008-save-results`

- **Contracts:** `ProgressRepository` (`saveLessonResult(result)`, `listLessonResults(courseId)`), `LessonResult`/`LessonResultSchema`, `SyncQueueRecord`/`SyncQueueRecordSchema` (`kind: "lesson_result"`, `id = result.id`, `schemaVersion: CONTRACTS_VERSION`, `status: "pending"`, `attemptCount: 0`, `nextAttemptAt = createdAt`, `lastError: null`), `ComputeUserProgress` / `UserProgress.completedLessonIds` (or simply the distinct `lessonId`s of `listLessonResults`).
- **Mapping:** criterion 3's "timezone offset" is stored as the IANA `timeZone` plus `localDate` on `LessonResult` (contract; the offset is derivable). Criterion 4's "not yet synced" = the `syncQueue` record written in the same Dexie transaction (`db.transaction("rw", db.lessonResults, db.syncQueue, …)`). Criterion 5's read function = `listLessonResults(courseId)`; expose a hook `useCompletedLessonIds(courseId)` in `src/lib/offline/hooks.ts` (query key `["progress", courseId]`; the cached data must be the raw `LessonResult[]` from `listLessonResults` and the ids a `select`, ADR-005, because GAM-003 reads the same key).
- **Files:** `src/lib/offline/db.ts` (`version(2)`: `lessonResults: "id, localDate, lessonId, courseId"`, `syncQueue: "id, [status+nextAttemptAt]"`; upgrade keeps v1 tables), `src/lib/offline/progress-repository.ts`, `src/lib/offline/errors.ts` (`StorageError` with `cause`), Learn list update in `src/app/_shell/LessonList.tsx` ("Completed" + `CheckIcon`, "Start again").
- **Idempotency:** `saveLessonResult` uses `add` inside the transaction and treats `ConstraintError` on an existing id as success (do not overwrite: results are immutable). Validate with `LessonResultSchema.parse` first.
- **Errors:** all Dexie errors are wrapped in `StorageError`; the mutation in LES-008 surfaces it. Reading errors in Learn fall back to "no completed lessons".
- **Memory fallback (PLT-003):** the in-memory store implements the same `ProgressRepository`.
- **Tests:** `fake-indexeddb`: save, duplicate save (one result, one queue record), `listLessonResults` filters by course, `localDate`/`timeZone` stored, upgrade from a v1 database created with the PLT-003 schema keeps the guest profile, simulated failure (`vi.spyOn(db.lessonResults, "add").mockRejectedValue`) → `StorageError`.

## Implementation (dev-platform, 2026-11-08)

1. `ProgressRepository.saveLessonResult` (Dexie and the in-memory fallback, `src/lib/offline/repositories.ts`) parses with `LessonResultSchema`, then writes the result and its sync record in one transaction. The route passes it to LES-008's `ResultsScreen` as `save`.
2. Idempotent by result id: a second save with the same id is a no-op, leaving one result and one queue record (unit test). The route creates the id once per finished session.
3. `localDate` (`toLocalDate`) and the IANA `timeZone` are set by `toLessonResult` and stored as given (unit test with `Pacific/Auckland`). The offset can be derived from the timezone (technical notes).
4. The same transaction writes a `lesson_result` `SyncQueueRecord` (`status: "pending"`, `attemptCount: 0`, `lastError: null`) (unit test).
5. `listLessonResults(courseId)` is read through `useCompletedLessonIds(courseId)` (`src/lib/offline/hooks.ts`), a `select` over `["progress", courseId]` (ADR-005). Learn shows a check icon + "Completed", which is also the link's accessible description.
6. `ResultsScreen.onSaved` → `useInvalidateProgress` (`refetchType: "all"`, because the app defaults have `refetchOnMount: false`). Continue → Learn shows the label with no reload (unit + e2e).
7. Dexie persists across reloads (unit: a new session on the same device; e2e: reload keeps the label). An e2e test plays Lesson 1 entirely offline and gets the label.
8. Every `ProgressRepository` method wraps non-validation failures in `StorageError` (`code: "storage_failed"`, `operation`, `cause`), exported from `@/lib/offline`. The results screen shows its save-error state; the page never crashes (RTL). If reading fails, Learn lists every lesson with "Start".
9. No Dexie version bump: PLT-003 already shipped `lessonResults` and `syncQueue` with the needed indexes in schema v1. A unit test opens a v1 database with a guest profile, saves a result and keeps the profile. If PM wants a version bump anyway, it is a no-op `version(2)`.
10. Completed cards show "Start again" and stay playable. The results screen's "Practice again" restarts the lesson.
11. Unit tests (`fake-indexeddb`): `src/lib/offline/__tests__/lesson-results.test.ts` (save, duplicate save, completed ids, local date/timezone, v1 database, storage errors), plus `hooks.test.tsx`.
