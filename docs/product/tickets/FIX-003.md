# FIX-003: A hearts read error must not hide XP, streak, goal and path progress (GAM-003 criterion 15)
**Owner:** dev-gamification · **Priority:** P0 (blocks the v0.5.0 combined release, PD-054) ·
**Depends on:** GAM-003, GAM-005 · **Milestone:** v0.3.0 (released in v0.5.0) ·
**Decisions:** PD-021 · **Branch:** `fix/fix-003-hearts-read-fallback` ·
**Found in:** PM-ACC3 (GAM-003 criterion 15 FAIL)

## User story
As a learner whose device storage fails to read my hearts, I want to still see my XP, streak,
daily goal and completed lessons, so that a storage hiccup never looks like lost progress.

## Problem
In `src/features/gamification/hooks/use-user-progress.ts`, `useProgressInputs` returns
`status: "error"` when `hearts.isError`. PD-021 / GAM-003 criterion 15 say a hearts read error
is treated as full hearts. Today, if hearts fail but results are fine:
- the top bar shows "–" for streak and XP,
- the daily-goal ring shows "Daily goal unavailable right now.",
- the skill path falls back to "Lesson 1 available, rest locked", so finished lessons look lost,
- the results screen's Streak row shows "–".

## Acceptance criteria
1. If the hearts read fails and the results read succeeds, `useProgressInputs(courseId)`
   returns `status: "success"` with `hearts = createFullHearts(now)` and the real `results`.
2. `useUserProgress(courseId)` then returns `status: "success"` with the real `totalXp`,
   `completedLessonIds`, `streak` and `dailyGoal`, and `hearts` at full.
3. Exactly one `console.warn` is logged for the hearts read failure per failed read (not one
   per render).
4. The fallback isn't written to storage: `saveHearts` isn't called because of the fallback,
   and the `["hearts"]` cache isn't filled with the fallback (ADR-005: derived values stay out
   of the cache).
5. If the results read fails, the status is still `"error"` (criterion 11 unchanged), whether
   or not hearts fail too.
6. The existing test "returns status 'error' when hearts can't be read" is replaced by "hearts
   fail, results OK → success with full hearts". A second test covers "results fail and hearts
   fail → error".
7. An RTL test with a stub session whose `getHearts` rejects shows, on `SkillPath`, a lesson
   with a saved result as "completed" (not the Lesson 1 fallback). On `GamificationTopBar` it
   shows the real "Total XP: N" and the hearts button "Hearts: 5 of 5".
8. `progress.ts` branch coverage stays 100 %. `npm run typecheck`, `lint`, `test` and `build`
   pass.

## Out of scope
- Retrying the hearts read or showing an error banner (UX stays silent, GAM-005 UX notes)
- Changing `useHearts` (it already falls back to full hearts)
- Any change to `useLoseHearts`

## UX notes
- **Error (hearts only):** everything renders as in success, with 5 hearts. No banner.
- **Error (results):** unchanged (each block's own fallback).
- **Loading / empty / success:** unchanged.
