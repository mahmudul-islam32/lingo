# PLT-012: Password reset by email
**Owner:** dev-platform · **Priority:** P1 · **Depends on:** PLT-010 · **Milestone:** v0.4.0

## User story
As a learner, I want to reset my password by email so that I can get back into my
account (US-PLT-08).

## Context
Supabase sends a recovery email with a link back to the app. Without a hosted project
(PD-022) the demo backend keeps sent emails in a **demo outbox** that tests (and the
demo screen itself) can read, so the full flow can be tested end to end.

## Acceptance criteria
1. `/forgot-password` has an "Email" field (pre-filled when opened from `/login` with an
   email typed in), a primary "Send reset link" button and a "Back to log in" link.
   The same email validation as PLT-010 criterion 7 applies.
2. After a valid submit the screen always shows "If an account exists for
   <email>, we've sent a link to reset your password. Check your inbox." It shows this
   whether or not the account exists (no account enumeration; tested both ways).
3. The confirmation has a "Send again" button that stays disabled for 60 s, with a
   visible countdown ("Send again in 42 s"). A rate-limit response from the backend shows
   "Too many requests. Please wait a minute and try again."
4. **Demo mode:** each reset request for an existing demo account adds an entry to the
   demo outbox (to, subject "Reset your Polyglow password", link). The confirmation
   screen shows "Demo mode: open the reset link" linking straight to it. A test helper
   reads the outbox.
5. The link opens `/reset-password`. With a valid recovery session the screen asks for a
   "New password" (8–72 characters, show/hide toggle, `autocomplete="new-password"`)
   and has a primary "Save new password" button.
6. Saving a valid password updates it, keeps the learner signed in, runs `completeSignIn`
   (PLT-010 criterion 9), and shows the toast "Your password has been updated." on the
   next screen. Logging in with the old password then fails, and with the new one
   succeeds (tested on the demo backend).
7. An expired, already-used or malformed link shows "This reset link has expired or was
   already used." with a "Send a new link" button (→ `/forgot-password`). Demo links
   expire after 1 hour and work once.
8. Offline, both screens show the PLT-010 offline note and disable their primary button.
   Network or 5xx errors show "Something went wrong. Please try again."
9. Keyboard and screen-reader use: the confirmation and errors are announced
   (`role="status"` / `role="alert"`), and focus moves to the confirmation heading after
   submit. There are no serious or critical axe violations on both screens and their
   states. No horizontal scrolling at 375 × 667.
10. Playwright (demo mode): sign up, sign out through the gateway (test helper), request a
    reset, open the outbox link, set a new password, and land signed in with the toast.

## Out of scope
- Changing the password from Settings while signed in
- Changing the email address
- Custom email templates and SMTP (hosted project setup, waiting on owner)

## UX notes
- **Layout:** same auth layout as PLT-010. Heading "Reset your password" / "Choose a new
  password".
- **Loading:** button spinner ("Sending…" / "Saving…").
- **Empty:** email field empty unless pre-filled.
- **Error:** inline field errors, plus an alert for server errors and expired links.
- **Success:** confirmation text with an envelope icon (original art). After saving the
  new password, the next screen shows the toast.

## Parallel work
Independent of PLT-011 and PLT-014. Touches only its own routes plus the "Forgot
password?" link target from PLT-010.
