# GAM-013: Goal date rule (`computeGoalPlan`, `useGoalPlan`) and the Learn goal card
**Owner:** dev-gamification · **Priority:** P1 · **Depends on:** CTO-017, GAM-003, GAM-006,
GAM-011 · **Milestone:** v0.5.4 Goal date · **Decisions:** PD-035, PD-064, PD-071 §1

## User story
As a learner who wants to reach a level by a date, I want the Learn tab to show how many
lessons are left, how many days I have and whether my daily goal gets me there, with a
one-tap way to use the suggested goal, so that I can plan my learning without guilt
(US-GD-02, US-GD-03, US-DE-07).

## Acceptance criteria
Field and type names follow CTO-017 / its ADR. Example course for the tests: the real `en-de`
course (A1 = 60 lessons, A2 = 70 lessons) or a fixture of the same shape.

### Rule (`computeGoalPlan`, pure, in `src/features/gamification/rules/`)
1. Returns `null` when there is no `goalPlan`, or when `targetLevel` is not a level of the
   course with content.
2. **Lessons counted:** every not-completed lesson (checkpoints included) in the levels from
   the effective start level (GAM-011 rule: missing or unknown → first level) up to and
   including `targetLevel`. Levels before the start level are never counted. If `targetLevel`
   comes before the start level, only `targetLevel`'s not-completed lessons are counted.
3. `daysLeft` = calendar days from `today` to `targetDate` (`targetDate − today`; the target
   day itself is not counted). Local dates only, so DST and time zones don't change it.
4. When `lessonsLeft > 0` and `daysLeft ≥ 1`: `lessonsPerDay = ceil(lessonsLeft / daysLeft)`;
   required XP = `lessonsPerDay × GAME_CONFIG.xpPerLesson`; `suggestedDailyGoalXp` = the
   smallest `dailyGoalOptions` value ≥ required XP, or the largest option if none is.
5. **Status:** `reached` when `lessonsLeft = 0` (any date); else `date-passed` when
   `daysLeft ≤ 0`; else `on-track` when required XP ≤ `dailyGoalXp`; else `raise-goal` when
   required XP ≤ the largest option; else `tight`. For `reached` and `date-passed`,
   `lessonsPerDay` and `suggestedDailyGoalXp` are `null`.
6. Worked examples are unit tests (today = 2026-11-21, start A1, target A2 by 2027-03-12,
   nothing completed → `lessonsLeft` 130, `daysLeft` 111, `lessonsPerDay` 2, suggested 20):
   daily goal 20 → `on-track`; daily goal 10 → `raise-goal`; target 2026-12-01 → `daysLeft`
   10, `lessonsPerDay` 13, suggested 50, `tight`; all 130 completed → `reached`; today =
   2027-03-12 with lessons left → `date-passed`; start A2 → `lessonsLeft` 70 even with A1
   lessons not completed; start A2, target A1 → A1's not-completed lessons only.
7. The rule creates and changes no result, XP, streak, hearts or setting. 100 % branch
   coverage of the rule.

### Hook
8. `useGoalPlan()` (exported from `@/features/gamification`) returns the current
   `GoalPlanStatus | null` from settings, saved results and `useLocalToday`, works for guests
   and offline, and updates without a reload after a lesson result, a daily-goal change or a
   goal-plan change. A read error returns `null` and is logged (no error banner, PD-021
   spirit).

### Learn goal card (`GoalPlanCard`, props: status, `onUseSuggestedGoal(xp)`, `onEditGoalDate()`)
9. Title for every status: "Goal: finish <level code> by <date>", e.g. "Goal: finish A2 by
   12 Mar 2027" (date via `Intl.DateTimeFormat("en-GB", { day: "numeric", month: "short",
   year: "numeric" })`).
10. `on-track`, `raise-goal`, `tight` show "<lessonsLeft> lessons left · <daysLeft> days to go"
    (singular "1 lesson", "1 day") and:
    - `on-track`: "On track. Your daily goal of <dailyGoalXp> XP gets you there."
    - `raise-goal`: "Aim for about <lessonsPerDay> lessons a day to get there." and a primary
      button "Use <suggested> XP a day".
    - `tight`: "This date is tight: about <lessonsPerDay> lessons a day. You could pick a
      later date." and a secondary button "Use 50 XP a day" (the largest option) plus the
      link "Change date".
11. `reached`: "You've finished <level code>. Well done!" and the link "Set a new goal date".
    `date-passed`: "Your goal date has come. Pick a new date to keep a plan." and the link
    "Change date". Neither shows lesson or day counts.
12. "Use <n> XP a day" calls `onUseSuggestedGoal(n)` once; "Change date" and "Set a new goal
    date" call `onEditGoalDate()`. The card never changes settings itself.
13. With `status = null` the card renders only a text link "Have a date in mind? Set a goal
    date" that calls `onEditGoalDate()`.
14. **Copy rules (PD-035, PD-071):** no text in the card contains the whole words (case
    insensitive) "exam", "test", "pass", "behind", "late" or "failed"; an RTL test checks
    every status's rendered text against this list ("later" is allowed).
15. Accessibility: the card is a `section` with the accessible name "Goal date"; status text is
    plain text (not colour only); the status line is in a polite live region so a change after
    "Use <n> XP a day" is announced; buttons and links are reachable with Tab and work with
    Enter / Space; no serious or critical axe violations in any status.
16. At 375 × 667 every status fits without horizontal scrolling or truncated text; buttons are
    at least 48 px tall; v2 tokens only (CTO-016, AA contrast).
17. RTL tests cover criteria 9–15 for all five statuses and `null`.

## Out of scope
- The Profile row, the dialog, mounting the card on Learn, wiring the callbacks (PLT-027)
- The results-screen line (LES-022)
- Pace from history ("you did 3 lessons this week"), a weekly plan, reminders, a celebration
  animation on `reached`
- Changing the daily goal automatically (PD-071: suggest only)

## UX notes
- **Placement:** PLT-027 mounts the card under the daily-goal ring on Learn, above the path.
- **Empty (no plan):** one quiet text link, no card chrome, so learners without a date see
  almost nothing new.
- **Loading:** render nothing until the hook has a value (no skeleton; the ring and path have
  their own).
- **Error:** treated as no plan (criterion 8).
- **Success:** after "Use <n> XP a day", the status line changes to the `on-track` text and
  the daily-goal ring shows the new goal.
- Tone: kind and practical (PRD §8.3). Never a pass promise or a deadline threat.
