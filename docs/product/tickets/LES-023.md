# LES-023: Review session in the player, per-exercise outcomes in every result, review results screen
**Owner:** dev-lessons · **Priority:** P1 · **Depends on:** CTO-019, LES-020, LES-021,
LES-022 · **Milestone:** v0.5.5 Smart review · **Decisions:** PD-065, PD-079, PD-080, PD-081

## User story
As a learner, I want to play a review of exercises from different lessons in the same
player I know, free and earning hearts like practice, and see what I earned at the end, so
that reviewing feels like a short lesson (US-SR-02, US-SR-04).

## Acceptance criteria
Names follow CTO-019 and its ADR (`ExerciseOutcome`, `ReviewItem`, the review-result kind).

### Outcomes in every result
1. `toLessonResult` (or the ADR's equivalent) fills the per-exercise outcomes for **every**
   finished session from `session.attempts`, using CTO-019 criterion 1: `correct` = first
   attempt correct with no mistake; `incorrect` = any attempt with `mistake: true`;
   `skipped` = skipped without an answer; hidden exercises get none. Unit tests: a lesson
   with a wrong-then-right exercise gives `incorrect`; a match pairs with a mismatch gives
   `incorrect`; a listen skipped for missing audio gives `skipped`; a hidden speak gives no
   outcome; the counts satisfy CTO-019 criterion 5 (the result still parses).
2. Quit and out-of-hearts sessions still produce no result and no outcomes (PD-080).

### Review session in the player
3. The player can play a **review** built from `ReviewItem`s of one course (1 to
   `reviewSessionSize` items, from different lessons and units). The ADR fixes the prop
   (e.g. `review: { items }` next to `lesson`, or a review "lesson" plus a source map).
   Exercises are shown in the order given; wrong answers are re-queued at the end, as in a
   lesson.
4. Each outcome of a review result has the **source** `lessonId` of its exercise (CTO-019
   criterion 2); the result is marked as a review (criterion 7). Unit test with items from
   two lessons.
5. **Practice rules (PD-065, PD-079):** a review never costs hearts while
   `GAME_CONFIG.practiceCostsHearts` is false, may start at 0 hearts, each correct Check earns
   `heartsGainedPerCorrectAnswer` up to the max, and the Practice badge (LES-020) is shown.
   No out-of-hearts screen can appear in a review.
6. No tip card is shown (tips belong to lessons). Every exercise type in
   `REVIEW_EXERCISE_TYPES` renders as in its lesson, including `lang` tagging, audio and
   figures (ADR-017); the feedback panel shows the exercise's own `explanation`.
7. The player's header / session label reads "Review" where a lesson shows its title (if
   the header shows no title, the `main` region gets the accessible name "Review"). The
   progress bar and "Exercise <i> of <n>" count review items.
8. Quit works as in a lesson: the quit dialog, nothing saved, hearts earned so far kept.
9. Sound effects follow `soundEffectsEnabled` as in a lesson (LES-012).

### Results screen in review mode
10. `ResultsScreen` gets a review mode: heading "Review complete!", the XP, accuracy and
    hearts rows as for a lesson (XP from `calculateXp`, the same as a lesson, PD-079), the
    streak and daily-goal rows (LES-010), and **no** goal-date row (a review never changes
    lessons left).
11. Buttons: primary "Continue" (the route sends it to `/practice`) and secondary "Review
    more" (replaces "Practice again"; calls the existing retry callback). Saving and the
    save-error state work as for a lesson (LES-008).

### Quality
12. Accessibility: keyboard-only play of a 10-item review works (Tab, Enter / Space, as in
    LES-002 criterion 3); the review results heading gets focus on mount as the lesson
    heading does; no serious or critical axe violations in the player or the review
    results.
13. At 375 × 667 the review header, every reviewable exercise type and the review results
    (all rows plus Continue) fit as the lesson versions do (LES-021), with no horizontal
    scrolling.
14. RTL tests cover criteria 3–11 with a fixture review of 3 items from 2 lessons (one
    `multiple_choice`, one `word_bank_translate`, one `match_pairs`); existing player and
    results tests pass unchanged.

## Out of scope
- Choosing the items, the Practice card (GAM-015); the `/review` route, loading the
  lessons, saving, navigation (PLT-029)
- New exercise types, new content, a review-specific feedback copy set
- Showing which lesson an exercise came from (later, if learners ask)

## UX notes
- **Loading:** the route shows `LessonPlayerSkeleton` while it builds the items (PLT-029).
- **Error:** the route's error state (PLT-029); inside the player, an exercise that fails to
  render follows the lesson rules.
- **Success:** results "Review complete!", then "Continue" back to Practice, whose card shows
  the new count.
- Tone: the same kind feedback headings as lessons; no "you got this wrong last time"
  framing.
