# PLT-011: Google sign-in
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** PLT-010 · **Milestone:** v0.4.0

## User story
As a learner, I want to sign in with Google so that I don't need another password
(US-PLT-07).

## Context
Supabase Auth's Google provider uses an OAuth redirect. The hosted project and the Google
OAuth client are waiting on the owner (PD-022), so the demo backend simulates the
provider. With real credentials only the configuration changes. One Google button serves
both sign-up and log-in: a new Google user gets a new account.

## Acceptance criteria
1. `/signup` and `/login` show a "Continue with Google" button above the email form,
   separated by an "or" divider. It follows Google's published sign-in button branding
   rules (their "G" mark, the label "Continue with Google"), and is not restyled in
   Polyglow colours.
2. The button is hidden in `off` mode (the screens show the PLT-010 criterion 3 message
   instead) and is disabled offline with the same offline note as the email form
   (PLT-010 criterion 15).
3. **Supabase mode:** pressing the button starts the provider redirect with
   `redirectTo = <origin>/auth/callback`. The button shows "Opening Google…" with
   `aria-busy="true"` until the page navigates away.
4. **Demo mode:** pressing the button opens a demo dialog titled "Demo Google sign-in"
   with an email field (pre-filled `demo.learner@example.com`) and "Continue" / "Cancel".
   "Continue" signs in that demo Google user, creating it the first time. It goes through
   the same `/auth/callback` route as the real flow, so the callback logic is tested in
   e2e.
5. `/auth/callback` shows Lumi and "Signing you in…" (`role="status"`) while the session
   is exchanged. On success it calls `completeSignIn` (PLT-010 criterion 9) exactly once,
   even if React renders it twice.
6. If the provider returns an error, or the learner cancels (in the demo: "Cancel"; for
   real: an `error` query parameter), the learner lands on `/login` with the alert
   "Google sign-in didn't finish. You can try again or use your email." Nothing changes
   on the device.
7. Opening `/auth/callback` directly with no auth parameters and no session redirects to
   `/login` without an error message.
8. Guest progress on the device is untouched by the redirect: the Dexie data is still
   there when the callback runs (verified in e2e with a guest who finished Lesson 1).
   Migrating it is PLT-013's handover.
9. In the demo backend, Google sign-in for an email that already has a password account
   signs in to that same account (one account per email, tested). For Supabase mode the
   behaviour follows Supabase's identity linking. Since the email is not confirmed in MVP
   (PD-023), Supabase may not link the two. The dev records the observed behaviour on a
   local Supabase stack in the ticket, and the pm decides any follow-up. It is not a CI
   test.
10. Keyboard: the button and the demo dialog can be used with the keyboard. The dialog
    traps focus and closes on Escape (= Cancel). There are no serious or critical axe
    violations on the callback screen and the demo dialog. No horizontal scrolling at
    375 × 667.
11. Playwright (demo mode): a guest finishes onboarding, opens `/login`, uses "Continue
    with Google" → "Continue", and ends signed in (same marker as PLT-010 criterion 21).
    A second test presses "Cancel" and sees the criterion 6 alert.

## Out of scope
- Apple sign-in (Phase 2)
- One-tap / Google Identity Services prompt
- Showing the Google profile photo or name on the profile (the profile keeps the guest's
  name and initials avatar, PD-024)
- Unlinking a Google identity

## UX notes
- **Layout:** Google button full width, 48 px tall, then an "or" divider, then the email
  form.
- **Loading:** button spinner ("Opening Google…"); on the callback, a centred Lumi and
  "Signing you in…".
- **Error:** an alert on `/login` (criterion 6). Kind copy, with an obvious next step
  (email form right below).
- **Offline:** button disabled with the shared offline note.
- **Success:** straight to the handover (PLT-013) or Learn.
