# PLT-001: App shell, routing and bottom navigation
**Owner:** dev-platform · **Priority:** P0 · **Depends on:** CTO-002, CTO-004 · **Milestone:** v0.1.0

## User story
As a learner, I want a clear, mobile-friendly app frame with simple navigation so that I
can always find my way to learning and to my profile (US-PLT-17).

## Acceptance criteria
1. These routes exist and render: `/` (Learn), `/profile` (Profile), `/onboarding`
   (placeholder until PLT-004), and a custom 404 page for any unknown path.
2. A bottom navigation bar has exactly two tabs, **Learn** (`/`) and **Profile**
   (`/profile`). Each tab has an icon and a visible text label (PD-005: no Leaderboard tab
   in MVP).
3. The bottom navigation shows on `/` and `/profile`. It is hidden on `/onboarding` and on
   the 404 page.
4. The active tab has `aria-current="page"`, and it is marked by more than colour alone
   (for example a filled icon plus an indicator bar).
5. The bottom navigation is a `<nav>` landmark with `aria-label="Main"`. Both tabs can be
   reached with Tab and opened with Enter.
6. Every page has exactly one `<main>` landmark and one `<h1>`. The first focusable
   element is a "Skip to content" link that moves focus to `<main>`.
7. `<html lang="en">` is set. The document `<title>` is "<Page> · Polyglow", built from a
   single app-name constant (PD-001: the name lives in one place).
8. **Loading state:** a route-level loading UI shows a spinner or skeleton with
   `role="status"` and the accessible name "Loading".
9. **Error state:** a route error boundary shows "Something went wrong" and a "Try again"
   button that re-renders the route. No stack trace is shown in a production build.
10. **404 state:** shows "We couldn't find that page" and a link "Back to Learn" to `/`.
11. **Empty states:** Learn shows "Your learning path will appear here." and Profile shows
    "Your profile will appear here." (replaced by later tickets).
12. Feature code uses only CTO-004 primitives and design tokens. No hex/rgb colour literals
    appear in files added by this ticket (checked by review/grep).
13. At a 375 × 667 viewport: no horizontal scrolling on any route, the last content element
    is not covered by the bottom navigation, and each tab's tap target is at least
    44 × 44 px.
14. The bottom navigation sits above the device safe area (uses
    `env(safe-area-inset-bottom)`).
15. Focus is visible on every interactive element (focus ring meets 3:1 contrast against
    its background).
16. An automated axe check (tooling chosen by the cto) reports no serious or critical
    violations on `/`, `/profile` and the 404 page.
17. A Playwright test on the mobile project opens `/`, switches to Profile and back to Learn
    using the bottom navigation, and checks `aria-current` each time.

## Out of scope
- Real Learn content (PLT-007, GAM-008) and real Profile content (PLT-016)
- Onboarding steps and redirects (PLT-004)
- Top bar with streak/XP/hearts (GAM-007, v0.3.0)
- Leaderboard tab (Phase 2, with leagues)
- Dark mode

## UX notes
- **Layout:** full-height column: page content scrolls; bottom navigation is fixed. Warm
  off-white background, indigo text, amber accent for the active tab indicator (brand
  palette from PD-001 via tokens).
- **Loading:** centred spinner on the page area; navigation stays visible.
- **Error:** short friendly message, one primary "Try again" button. No technical jargon.
- **Success/normal:** tab switch is instant (no full-page reload).
- **Empty:** short line of text with a neutral illustration slot (Lumi from GAM-001 can be
  added later).
- Reduced motion: no animated tab transitions when `prefers-reduced-motion: reduce`.

## Parallel work
Can be built at the same time as PLT-003 and GAM-001 (no shared files).

## Implementation notes
_(dev-platform, 2026-11-07, branch `feature/plt-001-app-shell`, rebased on PLT-003 #17 and CR-002 #18)_

1. Routes: `src/app/(tabs)/page.tsx` (`/`), `src/app/(tabs)/profile/page.tsx`, `src/app/onboarding/page.tsx`, `src/app/not-found.tsx` (verified: 200/200/200/404 on `next start`).
2. `src/app/_shell/nav-items.ts`: exactly Learn (`/`) and Profile (`/profile`), each with an original inline SVG icon (`_shell/icons.tsx`) and a visible label.
3. `BottomNav` is rendered only by `src/app/(tabs)/layout.tsx`; onboarding and 404 are outside the group (unit and e2e tests).
4. Active tab: `aria-current="page"`, filled icon, bold label and amber `bg-primary` indicator bar (`BottomNav.test.tsx`).
5. `<nav aria-label="Main">` with native `next/link` anchors: Tab-reachable, Enter opens (RTL `user.tab()` and e2e keyboard test).
6. One `<main id="main" tabIndex={-1}>` per page via `_shell/Main.tsx` (tabs layout, onboarding, 404, root loading/error); one `<h1>` per page and none in layouts. `SkipLink` is the first element in `<body>` and focuses `<main>`.
7. `<html lang="en">`; `metadata.title = { default: APP_NAME, template: "%s · " + APP_NAME }` from `_shell/app-name.ts` ("Learn · Polyglow", "Profile · Polyglow", "Get started · Polyglow", "Page not found · Polyglow").
8. `loading.tsx` (root) and `(tabs)/loading.tsx` (nav stays visible): `<div role="status" aria-label="Loading">` with `Spinner` + `VisuallyHidden`.
9. `error.tsx` (root) and `(tabs)/error.tsx`: "Something went wrong" + `Button` "Try again" calling `reset()`; `error.message` is shown only when `NODE_ENV === "development"` (unit-tested with production env).
10. `not-found.tsx`: "We couldn't find that page" + link "Back to Learn" to `/`.
11. Learn and Profile show the empty-state copy in a `Card` with a decorative illustration slot.
12. Only `@/components/ui` primitives and token classes; grep for hex/`rgb(` in new files is empty.
13. `overflow-x-hidden` body, `max-w-md` column; main gets `pb-[calc(4rem+env(safe-area-inset-bottom)+1rem)]`; tabs `min-h-11 min-w-11` inside a 64 px bar. Checked in `tests/e2e/shell.spec.ts` at 375 × 667.
14. Nav container `pb-[env(safe-area-inset-bottom)]`, `viewportFit: "cover"`.
15. All links/buttons use `focus-visible:focus-ring` (CTO-004 token, contrast tested in `tokens.test.ts`).
16. `@axe-core/playwright` added; `tests/e2e/axe.ts` fails on serious/critical; used for `/`, `/profile` and an unknown path.
17. `tests/e2e/shell.spec.ts`: opens `/`, Profile, back to Learn via the nav, checks `aria-current` each time and that no full reload happened (runs on the mobile project).

Also: `src/app/providers.tsx` mounts the theme (dark default, `data-theme` on `<html>`, `useTheme()`) and `ToastProvider` (viewport raised above the nav). `GuestProfileBootstrap` (PLT-003) stays mounted once in the root layout, inside the providers; its `StorageUnavailableNotice` renders directly above `<main>` as PLT-003's notes specify. Theme stays dark-first per ADR-004 (ticket's "warm off-white" UX note maps to the light theme tokens).
