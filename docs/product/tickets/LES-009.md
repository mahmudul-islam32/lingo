# LES-009: Hearts in the lesson player and "out of hearts" screen
**Owner:** dev-lessons · **Priority:** P0 · **Depends on:** LES-002, LES-003, GAM-005 · **Milestone:** v0.3.0

## User story
As a learner, I want to see my hearts during a lesson, lose one when I answer wrongly, and
be told kindly when I've run out and when hearts come back, so that accuracy matters and
I'm never left stuck (US-GAM-10, US-GAM-11, US-GAM-12).

## Context
The LES-002 player already has an optional `hearts` prop (`LessonPlayerHearts`:
`initial`, `onLose(cost)`, `onOutOfHearts(session)`) and a `heartsSlot` for the header.
Without the prop, hearts are not deducted (v0.2.0 behaviour). The session reducer already
ends a session as `out_of_hearts` on the "Continue" after hearts reach 0, and that wins
over `completed` on the last exercise (PD-018). This ticket wires the prop to the
gamification hearts (GAM-005) and adds the screens around it.

## Acceptance criteria
1. A component `HeartsLessonPlayer` is exported from `@/features/lessons` with the same
   props as `LessonPlayer`. It reads `useHearts()` (GAM-005) once at lesson start and
   passes `hearts = { initial: view.current, onLose, onOutOfHearts }` to `LessonPlayer`.
   The route switches to it in PLT-009.
2. **Start gate:** if `view.canStartLesson` is false when the lesson opens (for example
   from a bookmarked URL), the player is not shown; the out-of-hearts screen (criterion
   8) is shown instead, with the heading "You're out of hearts".
3. **Header:** the reserved hearts slot shows `HeartsMeter` (GAM-005) with the session's
   `heartsRemaining`. At lesson start it equals the hearts shown in the Learn top bar.
4. Each "Check" whose result has `heartCost > 0` lowers the header number by that cost
   at once and calls `useLoseHearts` with the cost exactly once. Correct answers,
   skipped exercises and speak exercises never change hearts.
5. A match-pairs exercise with any number of mismatches costs exactly 1 heart, applied
   when the exercise completes (PD-012).
6. Losing a heart is announced through a polite live region: "You lost a heart. N left."
   or, at 0, "You lost your last heart."
7. Losing a heart plays a short animation on the meter (at most 400 ms). Under
   `prefers-reduced-motion: reduce` the number changes with no animation.
8. **Out-of-hearts screen:** after the "Continue" that follows the last heart being lost,
   the lesson ends and shows: Lumi (ember, lg), heading "You're out of hearts", the text
   from `formatHeartRefill` (e.g. "Next heart in 3 h 12 min"), the text from
   `formatHeartsFull`, the line "Hearts come back on their own. Your finished lessons and
   XP are safe.", and one primary button "Back to Learn" (goes to `/`).
9. Focus moves to the out-of-hearts heading when the screen opens. Escape and the quit
   button do not appear on this screen.
10. A lesson that ends out of hearts saves **no** lesson result and awards **no** XP
    (`saveLessonResult` is not called), and the streak and daily goal don't change.
11. The feedback panel (LES-003) for the answer that cost the last heart still shows the
    correct answer before the out-of-hearts screen.
12. Hearts lost before a confirmed quit stay lost: after quitting, Learn shows the
    reduced number, also after a reload.
13. If saving a heart loss fails, the lesson goes on with the in-memory count (no error
    shown mid-lesson); the failure is logged.
14. A heart that refills during a lesson is not added to the lesson's counter; it shows
    in the top bar after the lesson (PD-018).
15. **Loading state:** while hearts are being read, the LES-002 player skeleton is shown;
    the first exercise does not appear before hearts are known.
16. **Error state:** if hearts can't be read, the lesson starts with full hearts
    (GAM-005 UX notes) rather than blocking the learner.
17. At 375 × 667 the header (quit button, progress bar, hearts meter) fits on one row,
    the meter is not truncated, and the out-of-hearts screen fits without scrolling with
    the button pinned to the bottom (at least 48 px tall).
18. RTL tests (with stubbed GAM-005 hooks) cover: start with 5 → wrong answer → 4 and
    `onLose(1)` once; match pairs with 3 mismatches → 1 heart; correct/skipped → no loss;
    1 heart → wrong → feedback → Continue → out-of-hearts screen, no result saved; start
    gate at 0 hearts; live-region texts; reduced motion; hearts read error → full hearts.

## Out of scope
- Practice mode to earn hearts back (Phase 2)
- Buying or refilling hearts instantly (not planned for MVP)
- The path's 0-hearts gate on Learn (GAM-008)
- Mounting `HeartsLessonPlayer` in the lesson route and the e2e test (PLT-009)
- Sound effect on heart loss (LES-012, v1.0.0)

## UX notes
- **Header:** close (left), progress bar (middle, flexible), hearts meter (right).
- **Heart lost:** the meter's heart briefly shrinks and the number drops; no red
  full-screen flash.
- **Out of hearts:** calm, not punishing. Lumi ember, heading, the two time lines, the
  reassurance line, "Back to Learn". No XP, no stats.
- **Loading:** player skeleton.
- **Error:** hearts unreadable → play with full hearts (criterion 16).
- **Empty:** not applicable.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-lessons · **Branch:** `feature/les-009-lesson-hearts`

- **Contracts:** `HeartsView`, `AnswerCheckResult.heartCost` (match pairs = 1 for any mismatch, CR-001, already in `checkAnswer`), `LessonSession` (`status: "out_of_hearts"`), `LessonPlayerHearts` (LES-002 player: `initial`, `onLose(cost)`, `onOutOfHearts(session)`). No contract change needed.
- **Reuse:** `LessonPlayer` with its `hearts` and `heartsSlot` props, `LessonPlayerSkeleton` (LES-002); `FeedbackPanel` unchanged (the reducer already shows feedback before `out_of_hearts`, AC 11); from `@/features/gamification` (GAM-005): `useHearts`, `useLoseHearts`, `HeartsMeter`, `formatHeartRefill`, `formatHeartsFull`, `useMinuteClock`; `Lumi`, `Button`, `VisuallyHidden` from `@/components/ui`.
- **Files:** `src/features/lessons/hearts/HeartsLessonPlayer.tsx`, `hearts/OutOfHeartsScreen.tsx`, `hearts/LessonHeartsMeter.tsx` (animation + live region), `hearts/__tests__/`, export from `src/features/lessons/index.ts`. Do not change `LessonPlayer`'s props; if something is missing, file a request instead of reaching into the reducer.
- **Wiring:** while `useHearts().status === "loading"` render `LessonPlayerSkeleton`. Then capture `initial = view.current` once (`useState(() => …)` after load; a later refill must not change it, AC 14). If `!view.canStartLesson` at that moment → `OutOfHeartsScreen`. Otherwise keep a local `remaining` counter: `onLose(cost)` → `setRemaining(r => Math.max(0, r - cost))`, `loseHearts(cost).catch(log)` (no UI error, AC 13), and a live-region message. `heartsSlot={<LessonHeartsMeter current={remaining} max={view.max} />}`. `onOutOfHearts` → switch to `OutOfHeartsScreen`. `onFinish` passes straight through to the caller's results flow, so an out-of-hearts session never reaches `saveLessonResult` (AC 10).
- **Live region:** a persistent `<div aria-live="polite">` in `LessonHeartsMeter` whose text is set after each loss (clear, then set on the next frame so repeated identical messages are announced).
- **Animation:** CSS `scale` keyframe ≤ 300 ms on the heart, `motion-reduce:animate-none`. No Framer Motion (not installed).
- **Out-of-hearts screen:** `useMinuteClock(true)` for the two time lines; `<h1 tabIndex={-1}>` focused on mount; "Back to Learn" is a `next/link` to `/` styled as a primary `Button` (or `router.push("/")`), pinned with `sticky bottom-0`; no quit button rendered. The route keeps `key={lesson.id}`.
- **Tests:** mock `@/features/gamification` hooks with `vi.mock` returning controlled views and a `vi.fn()` loser; reuse `player/testing/fixtures.ts` + `stubs.tsx` for exercises. Cases as in AC 18. Assert `onFinish` (spy) is never called in the out-of-hearts path.
