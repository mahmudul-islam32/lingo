## Bug
LES-002 criterion 3 says "Pressing Enter triggers 'Check' when it is enabled". The
player's global Enter handler ignores every Enter whose target is a `button`, `input` or
`[role=radio]`, so tiles and options keep their own Enter (keyboard contract, LES-002
Technical notes). LES-002 was tested with stub exercise components, so the conflict only
showed with the real LES-004 component. Its options are `<button role="radio">`, and arrow
keys move both focus and selection. So:

- A keyboard user selects an option with the arrow keys. Focus is on that option and
  "Check" is enabled, but Enter does nothing. They have to Tab to "Check", which breaks
  criterion 3 for the most common exercise type.
- During feedback, Enter on the locked option didn't trigger "Continue" either, unless
  focus had already moved to the button.

Word-bank and match-pairs tiles weren't affected. Enter there must stay with the tile.

## User story
As a keyboard learner, I want Enter on the option I chose to check my answer so that I
can answer a multiple-choice question without hunting for the Check button.

## Acceptance criteria
1. Multiple choice, answering: with an option selected and focused (e.g. after
   ArrowDown), Enter shows the feedback panel (same as "Check"), and the option stays
   selected.
2. Multiple choice, answering: Enter on a focused option that isn't selected selects it
   and does **not** check. A second Enter then checks.
3. Feedback: Enter continues exactly once (no double-advance to a second exercise).
4. Word bank: Enter on a bank or answer tile moves that tile and never checks.
5. Match pairs: Enter on a tile selects it (`aria-pressed="true"`) and never checks.
6. Regression tests use the real exercise registry (not stubs) and cover criteria 1–5.

## Out of scope
- Changing the arrow-key or digit shortcuts of LES-004
- Space behaviour (unchanged: Space activates the focused control)

## UX notes
No visual change. States are unchanged: answering (Check disabled until an answer is
chosen), feedback (Continue focused), error and loading as in LES-002.
