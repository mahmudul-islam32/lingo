# GAM-006: Daily goal progress ring on Learn
**Owner:** dev-gamification · **Priority:** P0 · **Depends on:** GAM-003, CTO-004 · **Milestone:** v0.3.0

## User story
As a learner, I want to see today's progress toward my daily goal on the home screen so
that I know whether to do one more lesson (US-GAM-07).

## Acceptance criteria
1. A component `DailyGoalRing` (props: `courseId`) is exported from
   `@/features/gamification`. It reads `useUserProgress(courseId).progress.dailyGoal`
   (GAM-003) and shows a circular ring plus the text "E / G XP" (e.g. "15 / 20 XP").
2. The ring's filled share equals `dailyGoalFraction` (GAM-002), clamped to 0–100 %. At
   0 XP the ring is empty; above the goal it is full and the text shows the real number
   (e.g. "25 / 20 XP").
3. The ring has `role="progressbar"`, `aria-valuemin="0"`, `aria-valuemax` = goal XP,
   `aria-valuenow` = earned XP capped at the goal, and `aria-valuetext` "15 of 20 XP
   today" (or "Daily goal reached: 25 XP today").
4. Above or next to the ring, a visible label reads "Daily goal".
5. When the goal is reached, the ring shows a check icon and the line "Goal reached!"
   in addition to the colour change (state is not shown by colour alone).
6. When the goal is not reached, a hint line reads "N XP to go" (e.g. "5 XP to go").
7. After finishing a lesson and returning to Learn, the ring shows the new value without
   a reload (via GAM-003 invalidation).
8. At local midnight the ring resets to "0 / G XP" without a reload (GAM-003
   `useLocalToday`).
9. Changing the goal in settings later (PLT-017) changes "G" without code changes here
   (the goal is read from settings, never hard-coded).
10. **Loading state:** a circular skeleton of the same size (no layout shift).
11. **Error state:** the ring is replaced by the text "Daily goal unavailable right now."
    No alert, no retry button; Learn stays usable.
12. The ring animates from its previous value to the new one in at most 600 ms, and
    jumps straight to the value under `prefers-reduced-motion: reduce`.
13. At 375 px the ring is 64–96 px in diameter and fits beside the streak/Lumi area
    without horizontal scrolling. Ring stroke and track meet 3:1 contrast against the
    surface in both themes (tokens only).
14. RTL tests cover: 0 / 20, 15 / 20, 20 / 20, 25 / 20, loading, error, ARIA values and
    text for each, and the reduced-motion path.

## Out of scope
- Changing the goal (PLT-017, v0.4.0)
- Weekly goal history or calendar (Phase 2)
- The goal row on the results screen (LES-010)
- Mounting the ring on the Learn page (PLT-009)

## UX notes
- **Normal:** amber progress stroke on an indigo track, "E / G XP" next to or inside the
  ring, "Daily goal" caption.
- **Reached:** stroke in the success token, check icon, "Goal reached!".
- **Loading:** circular skeleton.
- **Error:** one muted line of text (criterion 11).
- **Empty:** 0 XP today, empty ring, "20 XP to go".

## Parallel work

mounts it on Learn.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-gamification · **Branch:** `feature/gam-006-daily-goal-ring`

- **Contracts:** `DailyGoalProgress` (`goalXp`, `earnedXp`, `reached`, `localDate`), `UserProgress.dailyGoal`. No contract change needed.
- **Reuse:** `useUserProgress(courseId)` (GAM-003), `dailyGoalFraction` (GAM-002, already clamps), `Skeleton` (`shape="circle"`), `CheckIcon` from `@/components/ui`.
- **Files:** `src/features/gamification/components/DailyGoalRing.tsx`, `components/__tests__/DailyGoalRing.test.tsx`, barrel line. Pure text helpers (`goalValueText`, `goalHint`) in `rules/daily-goal-format.ts` with unit tests.
- **Rendering:** inline SVG, two `<circle>`s (track + progress) with `pathLength="100"` and `stroke-dashoffset = 100 - fraction * 100`; the `role="progressbar"` and `aria-*` go on the wrapper, the SVG is `aria-hidden`. Animate with a CSS `transition: stroke-dashoffset 500ms` and `motion-reduce:transition-none` (no Framer Motion needed; it isn't installed). Size 80 px (`size-20`).
- **Tokens:** progress `stroke-xp`, reached `stroke-success`, track `stroke-border-strong`; text `text-fg` / `text-fg-muted`. If a pair isn't already in `src/components/ui/__tests__/tokens.test.ts`, add it there in the PR (shared file; mention it in the PR description).
- **Edge cases:** `earnedXp > goalXp` (cap `aria-valuenow`, show the real number); goal from settings only (never `GAME_CONFIG` here except via GAM-003's fallback); `progress === null` while loading.
- **Tests:** RTL table over 0/15/20/25 of 20 with ARIA assertions; loading skeleton; error text; reduced motion by mocking `matchMedia` and asserting the `motion-reduce` class (jsdom doesn't run transitions).
