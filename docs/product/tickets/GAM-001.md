# GAM-001: Lumi mascot component (4 static poses)
**Owner:** dev-gamification · **Priority:** P0 · **Depends on:** CTO-004 · **Milestone:** v0.1.0

## User story
As a learner, I want a friendly guide character on key screens so that the app feels warm
and encouraging (supports US-GAM-13; brand per PD-001).

## Acceptance criteria
1. A shared component `<Lumi />` in `/src/components/ui/` accepts `pose`
   (`"idle" | "happy" | "ember" | "celebrating"`) and `size` (`"sm" | "md" | "lg"` =
   48 / 96 / 160 px).
2. Lumi is drawn as original inline SVG: a small round paper lantern with a face and a warm
   amber/gold glow, indigo outlines. It has no animal, bird or owl features, and uses no
   third-party, stock or traced artwork.
3. The four poses differ visibly: **idle** (calm face, normal glow), **happy** (smile,
   brighter glow), **ember** (sleepy face, dim glow, for missed streak / offline / out of
   hearts), **celebrating** (big smile, strongest glow, small sparkle shapes).
4. By default Lumi is decorative (`aria-hidden="true"`). When a `label` prop is passed, it
   renders with `role="img"` and that `aria-label`.
5. Poses are static in MVP (PD-001). No animation, so nothing changes under
   `prefers-reduced-motion`.
6. The outline has at least 3:1 contrast against the warm off-white background token.
7. Colours come from design tokens, not literals inside the component logic.
8. Each pose's SVG markup is 5 KB or less.
9. Unit tests render every pose at every size, check the default `aria-hidden`, and check
   the `role="img"` + `aria-label` when `label` is set.
10. The pm checks originality and brand fit before acceptance (Review section).

## Out of scope
- Animations and reactions (Phase 2)
- Mapping streak state to a pose (GAM-009, v0.3.0)
- Avatar presets for profiles (PLT-016)

## UX notes
- Used on: onboarding welcome (happy), offline fallback (ember), results screen
  (celebrating), empty states (idle).
- Must read clearly at 48 px (top bar / cards) and at 160 px (hero).
- **Loading/empty/error/success:** not applicable to the component itself; it is the
  illustration used inside those states elsewhere.

## Technical notes
_(cto, 2026-11-07)_

**Owner agent:** dev-gamification · **Branch:** `feature/gam-001-lumi`

- **Files:** `src/components/ui/Lumi.tsx` (+ `Lumi.test.tsx`), poses as small inner SVG fragments in `src/components/ui/lumi-poses.tsx`; export `Lumi`, `LumiPose`, `LumiSize` from `src/components/ui/index.ts` (adding a new shared component is allowed; don't change existing CTO-004 components without a PR note).
- **Contracts:** none (presentational). Props: `{ pose: "idle" | "happy" | "ember" | "celebrating"; size?: "sm" | "md" | "lg"; label?: string; className?: string }`, `size` default `"md"`, sizes map to 48 / 96 / 160 px via `width`/`height` attributes so the SVG never causes layout shift.
- **Colours:** use `currentColor` and CSS variables from the CTO-004 tokens (`var(--color-night-900)` for outlines, `var(--color-glow-400)`/`--color-glow-300` for the glow, `var(--color-glow-100)` for highlights) in `fill`/`stroke`; no hex literals in the component. Check outline contrast ≥ 3:1 against **both** `--color-canvas` themes (dark-first default and light): on the dark canvas the outline must be the light ink (`--color-fg`) or the glow body must carry the contrast; document the measured ratios in the PR.
- **Size budget:** measure each pose with `renderToStaticMarkup(<Lumi pose=… />).length` in a test and assert ≤ 5 120 bytes.
- **Tests:** RTL `it.each` over poses × sizes (rendered `width`), default `aria-hidden="true"` and no role, `role="img"` + `aria-label` when `label` is passed, size budget test. No snapshot-only tests.

**Placement decision (cto, 2026-11-07, review):** the branch first put Lumi in
`src/features/gamification/mascot/`. The cto moved it to `src/components/ui/` (`Lumi.tsx`,
`lumi-poses.tsx`, `__tests__/Lumi.test.tsx`) as AC1 and these notes say. Lumi is a purely
presentational asset that platform (onboarding, offline fallback) and lessons (results screen)
use too, so it belongs with the shared primitives and not behind another feature's public API.
Import it with `import { Lumi } from "@/components/ui"`. Pose mapping logic (e.g. streak state
to pose, GAM-009) stays in `src/features/gamification`.

**Brand-fit and originality check (pm).** I read every shape in `lumi-poses.tsx`
(100 × 100 viewBox):
- Glow: two soft halo circles (r 46 / r 40) behind the body. Ember has no outer halo and a
  dim inner one.
- Lantern: one centred carry loop on top (`M44 16q6-11 12 0`), a dark top cap (24 × 9) and
  bottom cap (20 × 7), a round paper body (ellipse 31 × 30) with an inner light and three
  faint vertical rib seams, and a tassel (short line plus a small trapezoid) underneath.
- Arms: two short single strokes from the sides of the body, resting down, or raised in
  "celebrating". These are paper-fold stubs, not wing shapes.
- Face: small dot eyes (idle), smiling arcs (happy, celebrating), closed sleepy arcs and a
  flat mouth (ember), glow-coloured cheeks, and an open smile when celebrating.
- Sparkles: four-point stars, in "celebrating" only.

It has no beak, ear tufts or horns, large ringed eyes or facial disc, feathers, wings,
talons or tail. The single centred handle can't be read as two ear tufts. The palette is
amber/gold with indigo, with no green. The silhouette reads clearly as a hanging paper
lantern (handle, caps, ribs, tassel). The drawing is built from simple primitives, not
traced artwork. **Verdict: original, on-brand (PD-001, PD-016), nothing bird- or owl-like.**

**Overall: ACCEPTED.**
