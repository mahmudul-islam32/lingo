# ADR-016: Exam-prep exercise types and two exam courses

- **Status:** Accepted
- **Date:** 2026-11-21
- **Ticket:** TELC-001 (owner request: bring the telc B1 web app's content into Polyglow)
- **Decisions:** PD-073
- **Decider:** owner + cto
- **Relates to:** [ADR-011](ADR-011-reading-passages.md) and [ADR-012](ADR-012-grammar-note-card.md)
  (both still Proposed). `choice` with a `passage` and `explain` can serve those needs; the
  B1 plan may adopt them instead of new types.

## Context

The owner's telc B1 web app (`telcB1-web`) holds a full exam-prep course and the
Einbürgerungstest catalogue: reading texts of up to ~3,000 characters, headline/ad matching
with 10–12 options, listening scripts, 29 model letters, speaking tasks, grammar theory and
310 civics questions with long English explanations. The six exercise types (ADR-002,
ADR-009) cap text at 280 characters and options at 4, and have no ungraded "read" or
"write, then compare" step. Splitting or clipping would lose content the owner wants kept.

## Decision

1. **`explanation`** (optional, rich text ≤3,000) on every exercise, shown in the feedback
   panel after "Check" for correct and incorrect answers alike.
2. **Four new exercise types** in `src/contracts/course.ts`:
   - `choice`: optional `title` and rich-text `passage` (≤8,000), a question (≤600) and
     2–12 options (≤400), exactly one correct. Graded like multiple choice. The prompt is in
     the learning language (unlike `multiple_choice`, PD-019).
   - `listening`: a `transcript` (≤6,000) read with speech synthesis in the learning
     language (no audio file; `Name:` speaker labels are dropped for speech), plus question
     and options as `choice`. If the device has no voice, the text is shown instead, so the
     exercise is never skipped. The transcript is shown in feedback.
   - `task`: `skill` writing | speaking, `title`, rich-text `task`, optional `points` and
     `phrases`, rich-text `modelAnswer`. The learner writes (text area, word count) or
     prepares aloud, then "Show model answer".
   - `explain`: a teaching card (`title`, rich-text `body`, optional `examples`). "Continue"
     moves on with no feedback panel.
3. **Ungraded types** (`UNGRADED_EXERCISE_TYPES` = task, explain) are always `correct`,
   never a mistake, never cost or earn hearts. They count as exercises in progress and
   accuracy, the same as a correct answer.
4. **Rich text** (`src/contracts/rich-text.ts`): paragraphs, line breaks, `- ` lists,
   `## ` sub-headings, `**bold**`, `*italic*`. Rendered by `components/ui/RichText.tsx`
   as React nodes, never as HTML.
5. **`lessonMaxExercises` 20 → 40**, for full mock exams (Einbürgerungstest: 33 questions).
6. **Two courses**: `telc-b1-en-de` (level B1 only) and `einbuergerung-en-de` (no levels),
   both `available`. Content is generated by `scripts/import-telc/build.mjs` from the
   telc app's JSON, and so are their lesson loaders (`src/lib/content/generated-exam-loaders.ts`).
7. **Profile → Course** row: learners can switch courses after onboarding (`useSetCourse`).
   Progress is already per course.

## Alternatives considered

- Fit everything into the six types: loses reading texts, model letters and explanations.
  Rejected by the owner.
- Units inside `en-de` B1: mixes exam drill with the general course being written. Rejected.

## Consequences

- `AnswerInputSchema` gains four variants. Answers live only in the session (never
  synced), so there is no Supabase change.
- Hundreds more lesson routes are prerendered and precached (more build time and cache).
- Recorded audio for `listening` can come later as an optional `audio` field.
